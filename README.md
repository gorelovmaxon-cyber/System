# System2

System2 — переносимая рабочая система для проектов, общей памяти, retrieval и
локальных автоматизаций. Процесс, роли, статусы и правила приёмки определены в
[docs/system-workflow.md](docs/system-workflow.md).

## Поток работы

Планировщик → автор тикетов → исполнитель → приёмщик.

Планировщик уточняет цель, создаёт spec и план. Автор тикетов (в текущей конфигурации
Sonnet) разбивает spec по [TICKET_TEMPLATE.md](TICKET_TEMPLATE.md). Исполнитель (GPT
Luna через VS Code/Qwen Code) выполняет тикет и коммитит результат. Приёмщик проверяет
его по реальным командам и ставит `done` только после проверки.

Один тикет = один коммит = одна остановка. Подробные гейты и политика push описаны в
[docs/system-workflow.md](docs/system-workflow.md).

## Быстрый старт

1. Откройте репозиторий в VS Code.
2. Проверьте обязательные инструкции и HANDOFF проекта.
3. Для новой работы проведите планирование, затем создайте тикеты.
4. Передавайте исполнителю только согласованный тикет и принимайте результаты по одному.

См. [QUICKSTART.md](QUICKSTART.md) и [docs/usage-guide.md](docs/usage-guide.md).

## Структура

- `CLAUDE.md` — общие правила репозитория.
- `OPUS.md` — инструкция планировщика и приёмщика.
- `QWEN.md` — инструкция исполнителя; имя не ограничивает модель.
- `TICKET_TEMPLATE.md` — единый шаблон тикетов.
- `docs/` — рабочая документация.
- `.claude/skills/` — локальные навыки.
- `.claude/memory/` — переносимая память проекта.
- `issues/` и `.scratch/*/issues/` — серии тикетов; статус создания не означает выполнение.

Сервисы Khoj, Activepieces и Figma настраиваются только в соответствующих тикетах и
не считаются работающими по наличию документации.
