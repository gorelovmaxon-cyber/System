# System2

System2 — переносимая рабочая система для проектов, общей памяти, retrieval и
локальных автоматизаций. Процесс, роли, статусы и правила приёмки определены в
[docs/system-workflow.md](docs/system-workflow.md).

## Поток работы

Планировщик → исполнитель → приёмщик.

Планировщик (Astra или другая выбранная модель) уточняет результат, создаёт
достаточный план и тикеты по [TICKET_TEMPLATE.md](TICKET_TEMPLATE.md); отдельный
обязательный автор тикетов не нужен. Исполнитель — один выбранный Sonnet/Sol —
выполняет связанные тикеты последовательно и коммитит результат. Приёмщик проверяет
законченный блок по реальным командам и ставит `done` только после проверки.

Один тикет = один коммит; независимая проверка — на границе блока. Задание передаётся
файлом задачи и HANDOFF между чатами; автоматического запуска исполнителя нет.
Подробные гейты и политика push описаны в [docs/system-workflow.md](docs/system-workflow.md).

## Быстрый старт

1. Откройте репозиторий.
2. Проверьте обязательные инструкции и HANDOFF проекта.
3. Для новой работы проведите планирование, затем создайте тикеты.
4. Передайте исполнителю разрешённый блок связанных тикетов и проверьте результат на
   границе блока.

См. [QUICKSTART.md](QUICKSTART.md) и [docs/usage-guide.md](docs/usage-guide.md).

Для нового сайта: `start → maxmade-autopilot` (внутри — фазы autopilot и правила
[site-build](.claude/skills/site-build/SKILL.md)). Навык
[maxmade-autopilot](.claude/skills/maxmade-autopilot/SKILL.md) применяет
[стандарт сайтов](docs/standards/site-creation.md), включая дизайн-систему,
адаптивную сетку и проверку правил. Работа продолжается в выбранной роли/режиме.

## Структура

- `CLAUDE.md` — общие правила репозитория.
- `OPUS.md` — инструкция планировщика и приёмщика.
- `QWEN.md` — инструкция исполнителя; имя не ограничивает модель.
- `TICKET_TEMPLATE.md` — единый шаблон тикетов.
- `docs/` — рабочая документация.
- `.claude/skills/` — локальные навыки.
- `.claude/memory/` — переносимая память проекта.
- `issues/` и `.scratch/*/issues/` — серии тикетов; статус создания не означает выполнение.

Сервисы Khoj, Activepieces и Figma настраиваются только в соответствующих тикетах и
не считаются работающими по наличию документации.
