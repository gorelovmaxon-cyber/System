# SystemQwen — Экономичная система разработки

**Идея:** Opus (дорогой) думает и планирует (~20% токенов), Qwen (дешёвый) реализует код (~80% токенов). Экономия ~5-7× по сравнению с чистым Sonnet.

**Как работает:**
1. Всегда начинаем с **`/start [задача]`** — Opus предлагает команду (autopilot/grill/spec)
2. Opus создаёт детальные тикеты с алгоритмами
3. Qwen реализует через **VS Code расширение** (видит весь проект локально)
4. Opus проверяет результат

**Явные остановки между фазами** — никакой автоматизации, полный контроль.

## Как начать работу

### Шаг 0: Команда /start

**Всегда начинай с:**
```
/start [описание задачи]
```

Opus проанализирует задачу и предложит подходящую команду:
- `/autopilot` — полная сборка (grill → spec → tickets → implement → review)
- `/grill` — только расспрос для уточнения требований
- `/spec` — только спецификация без реализации

Пользователь говорит "да" → Opus запускает.

### Требования

1. **Для Opus (Claude Code):**
   - Система `D:\System` с autopilot, subagent-pipeline
   - Документация: `D:\System2\OPUS.md`

2. **Для Qwen (VS Code расширение):**
   - Расширение: `qwenlm.qwen-code-vscode-ide-companion`
   - Конфиг: `~/.qwen/settings.json` с nordrouter
   - Документация: `D:\System2\QWEN.md`

## Three-phase workflow с явными остановками

### Фаза 1: Планирование (Opus)

**Что делает Opus:**
1. Получает задачу через `/start`
2. Делает grill (если нужно уточнение)
3. Пишет spec (техническое описание)
4. Разбивает на тикеты T1, T2, T3... с детальными алгоритмами
5. Сохраняет в `.scratch/[project]/issues/T*.md`

**🛑 СТОП 1:** Opus сообщает:
```
✅ Тикеты готовы: T1, T2, T3
Передавай T1 в Qwen Code.
```

---

### Фаза 2: Реализация (Qwen через VS Code)

**Что делает пользователь:**
1. Открывает файл тикета (`D:\System2\issues\T1-название.md`)
2. Открывает Qwen Code чат в VS Code
3. Говорит: "Реализуй этот тикет" (или копирует содержимое)

**Что делает Qwen:**
1. Читает тикет
2. Видит весь проект через расширение (локально)
3. Следует алгоритму из тикета строго
4. Пишет код, запускает тесты
5. Делает коммит: `git commit -m "T1: описание"`

**🛑 СТОП 2:** Qwen сообщает:
```
✅ T1 готов
Коммит: a3f8b2c
Тесты: 199/199 зелёные
Изменены: src/data.js, src/workout.js
```

---

### Фаза 3: Проверка (Opus)

**Что делает пользователь:**
- Копирует ответ Qwen и передаёт Opus в Claude Code

**Что делает Opus:**
1. Читает ответ Qwen
2. Проверяет код: `git diff`, результат тестов
3. Оценивает:
   - ✅ Всё выполнено → "Передавай T2 в Qwen"
   - ⚠️ Есть проблемы → "Нужна доработка: [конкретные замечания]"

**🛑 СТОП 3:** Opus даёт следующий шаг или просит доработку.

---

**Цикл 2-3 повторяется для каждого тикета до конца.**

## Пример полного цикла

**Задача:** Добавить поддержку множественного выбора цветов резинок в workout tracker.

### 1. Старт
```
Пользователь: /start добавить множественный выбор цветов для упражнения 21
Opus: Задача понятна. Запускаю autopilot: grill → spec → tickets → review.
```

### 2. Планирование (Opus)
```
Opus создаёт:
- spec.md (техническое описание)
- T1: Добавить поле multiSelect в data.js
- T2: Реализовать UI для множественного выбора
- T3: Добавить тесты

✅ Тикеты готовы: T1, T2, T3. Передавай T1 в Qwen.
```

### 3. Реализация T1 (Qwen)
```
Пользователь открывает T1.md → Qwen Code
Qwen: [читает тикет, пишет код, тестирует]

✅ T1 готов
Коммит: b4f2a1e
Тесты: 205/205 зелёные
Изменены: src/data.js
```

### 4. Проверка T1 (Opus)
```
Пользователь копирует ответ Qwen → Opus
Opus: [проверяет git diff]

✅ T1 проверен: поле multiSelect добавлено корректно.
Передавай T2 в Qwen.
```

**Цикл продолжается для T2, T3...**

## Роли и границы ответственности

### OPUS (мозг, стратег)
**Делает:**
- Grill — выявляет требования
- Spec — пишет спецификацию
- Tickets — создаёт детальные тикеты под Qwen (файлы, строки, алгоритм, команды)
- Review — проверяет результат работы Qwen (коммиты, тесты, соответствие тикету)

**НЕ делает:**
- Не пишет код реализации (только примеры в тикетах)
- Не запускает команды в проекте

**Останавливается после:**
- Создания всех тикетов (передаёт пользователю)
- Проверки каждого тикета (говорит "ОК, следующий" или "нужны правки")

### QWEN (руки, исполнитель)
Работает через **Qwen Code расширение в VS Code** — видит весь проект локально.

**Делает:**
- Читает тикет от Opus (пользователь открывает файл тикета в чате)
- Пишет код по алгоритму из тикета строго
- Запускает `node --test` (БЕЗ аргумента test/)
- Делает `git add -A && git commit -m "..."`

**НЕ делает:**
- Не придумывает архитектуру (следует тикету)
- Не меняет файлы, не указанные в тикете
- Не делает несколько тикетов сразу

**Останавливается после:**
- Успешного коммита одного тикета (сообщает: "T2 готов, тесты зелёные, коммит [hash]")

### ПОЛЬЗОВАТЕЛЬ (оркестратор)
**Делает:**
- Начинает с `/start [задача]`
- Получает тикеты, передаёт их Qwen по одному через VS Code
- Запускает Opus для проверки: "Проверь результат T2: git log + тесты"
- Принимает решение: следующий тикет или правки

## Экономика

| Этап | Модель | Токены | Стоимость |
|---|---|---|---|
| Grill + Spec + Tickets | Opus | ~15-20k | ~$0.25 |
| Implement T2-T5 (4 тикета) | Qwen (VS Code расширение) | ~120-150k | ~$0.15 |
| Review T2-T5 | Opus | ~10-15k | ~$0.15 |
| **ИТОГО** | — | ~150-185k | **~$0.55** |

**Сравнение:**
- Чистый Sonnet: ~$2-3
- Экономия: **~5-6×**
