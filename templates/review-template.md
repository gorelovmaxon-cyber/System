# Review — SC-XX

Единый формат проверки — [templates/evidence-report.md](evidence-report.md).
Приёмщик сам сверяет коммит и отчёт с исходным тикетом/брифом; запросить у
исполнителя дополнительные данные можно, но отсутствие ответа не превращает
непроверенный результат в done.

## 1. Сверка с требованием

**Порядок важен: сначала собственная оценка результата, потом чужие документы.**
Открой манифест требований (`manifest.md` задачи) и исходный бриф. Спецификацию и
тикеты читать только после пункта 1.1 — иначе оценка подстроится под формулировки
исполнителя, а пересказ в тикетах уже потерял часть требований.

- [ ] Прочитаны исходная задача (бриф) и манифест требований.
- [ ] Каждое требование манифеста проверено против наблюдаемого поведения:
      закрыто / не закрыто / неприменимо, со ссылкой на evidence.
- [ ] Требования без тикета и тикеты без требования перечислены явно.
- [ ] Прочитаны Requirement IDs и критерии приёмки конкретного тикета.
- [ ] Проверены ограничения, зависимости и список изменённых файлов.

Если манифеста нет, это фиксируется в отчёте как отсутствующая граница проверки:
приёмщик сверяет с брифом напрямую и не выдаёт `done` только по тикетам.

## 2. Проверки и сценарии

- [ ] Положительный сценарий выполнен.
- [ ] Негативный/ошибочный сценарий выполнен.
- [ ] Регрессия по зависимым тикетам проверена.
- [ ] Live, fixture и синтаксические проверки различены.

`Файл создан`, `node --check`, lint и один зелёный unit-тест не являются
функциональным успехом без проверки требуемого поведения.

## 3. Статус

Выбрать ровно один: `done`, `awaiting-validation`, `blocked`, `доработка`.

При `awaiting-validation` указать отсутствующий доступ/сценарий; при `blocked` —
что именно не позволяет продолжить. При доработке указать владельцу точные
критерии и не скрывать дефект в отчёте.

## 4. Экономика

Проверить фактическое wall-clock время, retries и доступные context/token
метрики. Недоступную стоимость записать как `unknown` с причиной; цифры
экономии без источника не принимаются.

## Вердикт

```text
SC-XX: <status>
Commit: <hash>
Evidence: <path>
Missing/next action: <...>
```
