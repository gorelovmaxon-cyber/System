# Анализ: nick-vels/autopilot

> Статус документа: observation. Это источник идей для проверки, а не обязательная
> инструкция и не доказательство свойств System2.

**Дата:** 2026-08-16  
**Источник:** GitHub nick-vels/skills + видео Matt Pocock  
**Контекст:** Изучение для улучшения SystemQwen

## Ключевые находки

### 1. Память проекта (CLAUDE.md / AGENTS.md)

**Фазы записи:**

| Момент | Что записывается |
|---|---|
| **Phase 0 (скелет)** | Название, команды (что известно), структура |
| **Phase 5 (during build)** | Gotchas, реальная команда тестов, .env переменные |
| **Phase 8 (full description)** | Архитектура из КОДА (не из spec) через отдельного субагента |
| **Phase 8 (ADRs)** | Решения и почему (docs/adr/) — только tier T2+ |

**Принципы:**
- Субагент видит только КОД, не spec → описывает реальность
- Всё между маркерами `<!-- autopilot:start -->` / `<!-- autopilot:end -->`
- Пользовательский текст вне маркеров — неприкосновенен

### 2. Dashboard (живой HTML)

**Что показывает:**
- Прогресс проекта (общий + по этапам)
- Покрытие брифа (главная метрика)
- Таймеры в реальном времени
- Таски: готовые / в работе / ждут
- Долг (заглушки, незаполненные переменные)

**Как работает:**
- Открывается автоматически в Phase 0
- Обновляется каждые 10 секунд (офлайн, без сервера)
- `.autopilot/dashboard.html` + `.autopilot/state.js`

### 3. Слепая приёмка (Phase 8)

**Отдельный субагент получает:**
- ✅ Исходный бриф пользователя
- ✅ Готовый код
- ❌ НЕ получает spec.md

**Цель:** Проверить результат против оригинальных слов пользователя, а не против пересказа.

### 4. Manifest (пронумерованные требования)

Бриф пользователя → пронумерованные требования → трекинг статуса каждого.

**Гейты:**
- После spec: ни одно требование не осталось без раздела
- После plan: у каждого требования есть таск
- После build: слепая приёмка проверяет выполнение

**Правило:** Снять требование может только пользователь.

### 5. Ярусы (tiers) вместо "режимов"

| Ярус | Размер | Тикетов | Описание |
|---|---|---|---|
| T0 | Скрипт, лендинг | 0 | Один заход |
| T1 | Одна фича | 0 | Один заход |
| T2 | Несколько фич | 2-8 | Разбивка на таски |
| T3 | Несколько подсистем | 9-16 | Полная разбивка + ADRs |

**Больше 16 тасков — запрещено.** Работа разбивается на два запуска.

### 6. Режимы (full / semi / manual)

| Режим | Что спрашивают |
|---|---|
| full | Ничего (список решений в конце) |
| semi | Только неопределённое (2-8 вопросов) |
| manual | Вопросы + утверждение spec + утверждение плана |

### 7. Глубина (strict / normal / deep)

| Глубина | Что додумывают |
|---|---|
| strict | Только написанное + обработка ошибок |
| normal | Пробелы, которые испортят результат |
| deep | Полный список: пустой экран, обрыв, права, лимиты |

### 8. Доводка (polish) — опциональная фаза

**Включается:** `/autopilot polish ...`

**Как работает:**
1. Требует эталон от пользователя (сайты, скриншоты)
2. Запускает проект → сравнивает с эталоном → находит различия
3. Различия → обычные таски
4. Цикл повторяется 3 раза или до "хватит"

**Критерий остановки:** Круг не нашёл ничего нового (не "критик доволен").

## Отличия от SystemQwen

| Что | SystemQwen | nick-vels/autopilot |
|---|---|---|
| **Память проекта** | ❌ Нет автоматической | ✅ CLAUDE.md/AGENTS.md, 3 фазы записи |
| **Dashboard** | ❌ Нет | ✅ Живой HTML с метриками |
| **Слепая приёмка** | ❌ Нет | ✅ Отдельный агент против брифа |
| **Manifest** | ⚠️ Частично (тикеты) | ✅ Пронумерованные требования с трекингом |
| **ADRs** | ❌ Нет | ✅ docs/adr/ для T2+ |
| **Ярусы** | ❌ Нет (только mode) | ✅ T0-T3 автоматически |
| **Режимы работы** | ⚠️ `--mode=systemqwen` | ✅ full/semi/manual + strict/deep |
| **Доводка (polish)** | ❌ Нет | ✅ Сравнение с эталоном |

## Что взять для SystemQwen

### Критично важное:

1. **Память проекта (Phase 0, 5, 8):**
   - Скелет CLAUDE.md сразу
   - Субагент описывает код (не spec) в конце
   - Всё между маркерами

2. **Manifest (пронумерованные требования):**
   - Бриф → numbered requirements
   - Трекинг статуса
   - Гейты на каждой фазе

3. **Слепая приёмка:**
   - Субагент видит только бриф + код
   - Проверяет против оригинальных слов

### Желательное:

4. **Dashboard:**
   - Живой HTML с прогрессом
   - Открывается автоматически
   - Обновляется каждые 10 сек

5. **ADRs (для T2+):**
   - docs/adr/ для load-bearing decisions
   - Почему выбрали + что отвергли

6. **Ярусы:**
   - Автоопределение T0-T3
   - T0-T1: без разбивки
   - T2-T3: с тасками + ADRs

### Можно отложить:

7. **Доводка (polish):** Требует эталон, дорого по времени/токенам

## Применимость

**Использовать nick-vels/autopilot, если:**
- Нужен полный автомат "из коробки"
- Хотите dashboard и метрики
- Работаете в Claude Code / Cursor

**Доработать SystemQwen, если:**
- Нужна экономия через Qwen (80% кода)
- Хотите контроль на каждом шаге (явные остановки)
- Уже есть инфраструктура `.claude/skills/`
