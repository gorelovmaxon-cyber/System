# Sequential Subagent Pipeline

**Дата:** 2026-08-17  
**Контекст:** Анализ D:\System + D:\System2 + Documents (эволюция систем)  
**Источник:** Proven pattern across multiple projects

## Описание

Линейное выполнение тикетов через отдельных субагентов: **1 тикет = 1 свежий контекст = 1 субагент = 1 коммит**. Каждый субагент получает чистый контекст, реализует один тикет, завершается. Следующий тикет → новый субагент.

## Детали

**Процесс:**
1. Opus создаёт тикеты T1, T2, T3, T4 с детальными алгоритмами
2. Субагент 1 получает T1 → реализует → тестирует → коммитит → завершается
3. /clear (очистка контекста)
4. Субагент 2 получает T2 → реализует → тестирует → коммитит → завершается
5. Повторить для T3, T4...

**Ключевые моменты:**
- Каждый субагент видит только СВОЙ тикет
- Нет накопления контекста между тикетами
- /clear между тикетами обязателен
- Один коммит = одна атомарная функция

**Сравнение с параллелью:**

| Подход | Токены | Время | Конфликты |
|--------|--------|-------|-----------|
| Sequential | 100k | ~15 мин | 0 |
| Parallel (4 агента) | 400-700k | ~15 мин | Высокий риск |

## Применимость

✅ **Использовать когда:**
- Тикеты зависят друг от друга (T2 использует код из T1)
- Нужна экономия токенов (3-7× дешевле параллели)
- Важна атомарность коммитов
- Работа в одних и тех же файлах

✅ **Не использовать когда:**
- Тикеты полностью независимы И работают в разных файлах
- Нужна скорость > экономия (редко)
- Можно использовать isolation: 'worktree' для параллели

## Почему работает

**Экономия токенов:**
- Parallel Agent Teams ≈7× дороже
- Каждый параллельный агент несёт полный контекст
- Sequential: контекст только для текущего тикета

**Качество:**
- Свежий контекст = меньше hallucinations
- Фокус на одной задаче
- Чистая история коммитов

**Контроль:**
- Видишь результат каждого тикета ДО следующего
- Легко откатить один тикет
- Явные точки остановки

## Примеры

### D:\System2 (SystemQwen)
```

T2: Rewrote QWEN.md for VS Code extension
T3: Implemented 3-phase workflow with /start
T4: Made file links mandatory in tickets
```
Каждый коммит = один тикет = атомарное изменение.

### D:\dev (Trading Bot)
Последовательная реализация модулей:
1. market_data.py
2. signal_engine.py
3. position_manager.py
4. risk_manager.py

Каждый модуль зависит от предыдущего.

## Gotchas

- **Не забыть /clear между тикетами** — иначе контекст раздувается
- **Субагент не видит переписку** — всё в тикет (алгоритм + ссылки на файлы)
- **Git stash перед /clear** — если uncommitted changes
- **Один тикет = одна функция** — не пытаться впихнуть всё в T1
