# Explicit Stop Gates

**Дата:** 2026-08-17  
**Контекст:** SystemQwen (D:\System2) — core principle  
**Источник:** User preference from project analysis

## Описание

Явные точки остановки между фазами работы: **🛑 STOP после grill, spec, tickets, каждого тикета, review**. Никакой автоматизации без явного подтверждения. Полный контроль на каждом шаге.

## Детали

**Обязательные остановки:**

1. **После Grill** → показать вопросы → ждать ответов
2. **После Spec** → показать спеку → подтверждение
3. **После Tickets** → показать тикеты → передать в реализацию
4. **После каждого тикета** → коммит → проверка → следующий
5. **После Review** → принятие или доработка

**Формат STOP:**
```
🛑 СТОП: [что готово]

[Краткое резюме]

Готов продолжить? (да/нет/изменить)
```

**Что НЕ делать:**
- ❌ Продолжать без подтверждения
- ❌ "Начал реализацию T1..."
- ❌ "Запустил тесты..."
- ❌ Любое действие после STOP

**Что делать:**
- ✅ Показать результат фазы
- ✅ Явно объявить STOP
- ✅ Ждать команды пользователя
- ✅ Только после "продолжай" → следующая фаза

## Применимость

✅ **Всегда останавливаться на:**
- Grill завершён → показать вопросы
- Spec готова → показать архитектуру
- Tickets созданы → показать список T1-T4
- Тикет реализован → показать коммит
- Review завершён → вердикт

✅ **Можно НЕ останавливаться на:**
- Чтение файлов (внутренняя операция)
- Поиск в коде (внутренняя операция)
- Анализ без изменений
- Однозначно trivial правка (если пользователь явно попросил)

## Почему работает

**Контроль:**
- Видишь каждый шаг ДО выполнения
- Можешь скорректировать ДО траты токенов на реализацию
- Нет сюрпризов

**Экономия:**
- Spec неправильная → стоп → переделать → экономия 80% токенов
- Тикеты не те → стоп → переписать → экономия реализации
- Один тикет криво → стоп → переделать только его

**Доверие:**
- AI не "убегает" в автопилоте
- Явное разрешение на каждый этап
- Предсказуемость поведения

## Примеры

### Правильно (D:\System2 pattern)

```
Я создал 4 тикета для реализации:

T1: Setup project structure (5min, low risk)
T2: Implement market data WebSocket (15min, medium risk)
T3: Add signal detection logic (20min, medium risk)
T4: Integrate risk management (10min, low risk)

Все тикеты в .scratch/trading-bot/issues/

🛑 СТОП: Тикеты готовы. Передавай T1 в Qwen.
```

Пользователь: "Продолжай с T1"

```
[Qwen реализует T1]
[Создаёт коммит]

✅ T1 завершён: Setup project structure
Коммит: a3f9d2c
Файлы: src/index.ts, package.json, tsconfig.json
Тесты: зелёные

🛑 СТОП: Готов к T2. Передавать?
```

### Неправильно (автопилот без остановок)

```
Создал 4 тикета. Начинаю реализацию T1...

[Создал файлы]
[Написал код]
[Запустил тесты]
[Создал коммит]

T1 готов. Начинаю T2...

[Пишет код дальше без подтверждения]
```

❌ **Проблемы:**
- Нет контроля после тикетов
- Автоматическое продолжение T2
- Нет возможности скорректировать

## Gotchas

- **"Продолжай" ≠ "продолжай всё до конца"** — продолжить = следующий шаг, не весь проект
- **STOP должен быть явным** — не подразумеваемый, а написанный "🛑 СТОП"
- **Резюме перед STOP обязательно** — что сделано, что дальше
- **Не спрашивать "хочешь увидеть код?"** — показать сразу (краткое резюме)

## Когда можно смягчить

**Vibecoding mode** (если пользователь явно просит):
- "Сделай X полностью, сам разберись"
- Тогда STOP только на блокирующих неизвестных (оплата, API ключи)
- Но ВСЕГДА останавливаться на необратимом (деплой, удаление)

**Иначе:** Explicit stops обязательны.

### D:\System2 (SystemQwen)
CLAUDE.md:

## Как работаем

- Полный цикл → `/systemqwen [задача]`:

### USAGE.md (лучшая версия)
```markdown
Автономность с чекпоинтами:
- Действовать самостоятельно на рутине
- 🛑 СТОП на необратимом (деплой, оплата, удаление)
- 🛑 СТОП на внешних зависимостях (API ключи, хостинг)
```
