# auto-learn

Автоматическое самообучение системы: накапливает знания в `D:\System\memory/` после каждой завершённой задачи. Цель — **день 30 работы должен быть заметно лучше дня 1**.

## Когда запускается

- **Автоматически** в конце autopilot Phase 5 (после тестов, перед финальным отчётом)
- **Вручную** по запросу: "запомни это", "сохрани в память", "это важно для следующих задач"
- **Перед завершением сессии** — если было что-то нетривиальное

## Шаги

1. **Спросить пользователя:** "Что из этой задачи стоит запомнить навсегда?"
   - Повторяемые паттерны (что сработало хорошо)
   - Gotchas (на что наступили, как решили)
   - Решения (что выбрали и почему)
   - Факты (новые данные о проекте/технологиях/пользователе)
   
   **Готово, когда:** получен ответ или пользователь сказал "ничего" / "разовое".

2. **Определить тип знания** (если есть что записывать):
   - Факт → `D:\System\memory/facts/`
   - Решение → `D:\System\memory/decisions/` + предложить добавить в `DECISIONS.md` проекта
   - Gotcha → `D:\System\memory/gotchas/`
   - Паттерн → `D:\System\memory/patterns/`
   
   **Готово, когда:** тип определён по содержанию.

3. **Проверить существование `D:\System\memory/`**:
   - Если существует → записать туда
   - Если НЕ существует → создать `.system-memory/` в корне текущего проекта с той же структурой
   - Добавить в `.system-memory/README.md` инструкцию по переносу в `D:\System\memory/`
   
   **Готово, когда:** целевая папка определена и существует.

4. **Записать в файл** по формату из `D:\System\memory/README.md`:
   ```markdown
   # <Заголовок>
   
   **Дата:** <YYYY-MM-DD>
   **Контекст:** <В каком проекте/задаче>
   **Источник:** <Пользователь/Ошибка/Инсайт>
   
   ## Описание
   <Суть>
   
   ## Детали
   <Конкретика>
   
   ## Применимость
   <Когда использовать>
   ```
   
   Имя файла:
   - facts: `<проект-или-тема>.md`
   - decisions: `YYYY-MM-DD-<тема>.md`
   - gotchas: `<компонент>-<проблема>.md`
   - patterns: `<название-паттерна>.md`
   
   **Готово, когда:** файл создан или добавлена секция в существующий.

5. **Если это процесс (повторялся 2-3 раза)** → предложить создать скилл через `skill-forge`
   
   **Готово, когда:** либо запущен skill-forge, либо пользователь отказался.

6. **Краткое резюме:** "Записано в memory/<категория>/<файл>. Будет доступно в следующих сессиях."
   
   **Готово, когда:** пользователь уведомлён.

## Отличие от skill-forge

- **auto-learn** → декларативная память (ЧТО знаем: факты, решения, ошибки)
- **skill-forge** → процедурная память (КАК делать: пошаговые инструкции)

Если что-то повторялось 2-3 раза — это кандидат в скилл, auto-learn предлагает запустить skill-forge.

## Gotchas

- **Не записывать разовое.** Спросить явно: "это разовая правка или повторится?" Если разовое — пропустить.
- **Fallback на `.system-memory/` работает только когда `D:\System` физически недоступен** (другая машина, Docker, удалённый сервер). Не создавать локальную копию "на всякий случай".
- **Не дублировать содержимое DECISIONS.md проекта один-в-один** — в memory/ идёт только то, что применимо **кросс-проектно**. Решение "15г желатина" специфично для проекта тренировок — не в общую память.
- **Дата в формате YYYY-MM-DD**, не DD.MM.YYYY — для сортировки файлов по хронологии.
