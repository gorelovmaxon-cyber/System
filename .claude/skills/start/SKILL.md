# start — маршрутизатор

Прочитай задачу и проверь доступный контекст (git status, файлы проекта). Выбери
маршрут по типу работы:

| Тип задачи | Маршрут |
|---|---|
| Собрать или изменить систему под ключ | /autopilot |
| Собрать через явные остановки и VS Code-исполнителя | /systemqwen |
| Уже есть согласованные тикеты | /implement |
| Сломалось или падает | /diagnosing-bugs |
| Проверить код или diff | /code-review |
| Нужны первоисточники | /research |
| Нужны вопросы по идее | /grill-me → /to-spec → /to-tickets |

Для работы с SystemQwen объясни: планировщик формирует spec, автор тикетов (Sonnet)
готовит тикеты, исполнитель (GPT Luna через VS Code/Qwen Code) реализует их, а
приёмщик проверяет. Подробности — [docs/system-workflow.md](../../../docs/system-workflow.md).

Перед запуском коротко сообщи команду, причину и ожидаемый результат. Для маршрутов,
которые требуют ручного запуска, выдай точную команду пользователю. Для
autopilot/systemqwen продолжай по соответствующему скиллу. Мелкую однострочную
правку сделай сразу.

Не смешивай маршрутизацию с реализацией: после выбора маршрута следуй его контракту.
