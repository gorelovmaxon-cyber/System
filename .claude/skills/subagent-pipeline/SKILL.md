# subagent-pipeline

Один тикет — один сабагент — один свежий контекст. Оркестратор не пишет код, он
**нарезает, запускает и принимает**.

## Разделение моделей — не обсуждается

| Роль | Модель | Почему |
|---|---|---|
| Оркестратор: расспрос, спека, нарезка тикетов, приёмка, ревизия требований | **Opus** | Здесь ловятся противоречия в ТЗ и нестыковки с реальностью. Это единственное место, где нужна способность заметить то, о чём не спросили |
| Исполнитель тикета | **Sonnet** | Тикет с явными критериями приёмки и тестами — исполнение, а не изобретение. Opus платит за способность, которая не используется |
| Ресёрч по источникам | **Sonnet** | Сбор и цитирование — исполнение. Оркестратор структурирует результат и оценивает силу доказательств |
| Повторная попытка после падения | **Opus** | Первая попытка провалилась — значит задача оказалась не исполнением |

**Проверяй себя на этом.** Самый частый срыв — оркестратор незаметно начинает делать
работу сам: «тут же на пять минут». Ресёрч особенно легко утекает на Opus, потому что
он ощущается как размышление, а не как задача. Утёк — признай вслух, не заметай.

## Когда брать

- Тикетов больше двух, и они реализуются по очереди.
- Пользователь сказал «в отдельных чатах», «сабагентами», «чтобы контекст не тёк».
- **Autopilot на фазе implement** — стандартный режим для экономии токенов (последовательные Sonnet-субагенты вместо параллельных агентов).

## Шаги

1. **Положи источник правды в файл проекта.** Если ТЗ, спека или требования живут только
   в переписке — сабагент их НЕ увидит: у него чистый контекст. Перенеси в `ТЗ.md` /
   `SPEC.md` до первого запуска — **готово, когда:** сабагент может прочитать всё нужное
   с диска, не спрашивая тебя.
   
   **Если вызван из Autopilot:** источник правды уже на диске (`SPEC.md` создан на фазе 2, тикеты нарезаны и лежат в `issues/`). Этот шаг пропускается.

2. **Первый тикет — трассирующий.** Он задаёт структуру всего проекта и создаёт пустые
   файлы-заглушки под будущие тикеты, уже подключённые в сборку. Тогда следующие тикеты
   дописывают свои файлы, а не переделывают общие — **готово, когда:** у каждого
   последующего тикета есть свой файл, который никто больше не трогает.

3. **Собери промпт сабагента по шаблону** `tools/subagent-prompt.template.md`. Обязательны
   четыре блока: что прочитать первым делом, твой объём, **что НЕ входит** (перечислить
   чужие тикеты поимённо), как закончить — **готово, когда:** промпт самодостаточен и не
   требует ничего из твоей переписки.

4. **Запускай серийно, если тикеты трогают общие файлы.** Параллель — только на реально
   непересекающихся файлах. В одностраничном приложении почти всё сходится в один
   ui-файл, значит серийно — **готово, когда:** ни один запуск не делит файл с другим.

5. **Принимай работу сам, не верь отчёту.** Прогони `tools/accept-ticket.ps1` — тесты,
   сборка, отсутствие внешних ссылок, состояние дерева — **готово, когда:** цифры увидены
   своими глазами, а не процитированы сабагентом.

6. **Читай раздел «решил сам» в отчёте.** Там лежат будущие дефекты. Каждое решение
   сабагента — либо принято, либо превращено в новый тикет — **готово, когда:** ни одно
   самостоятельное решение не осталось без вердикта.

7. **Ревизия требований → пересмотр закрытых тикетов.** Требования изменились в середине
   стройки — пройди по уже закрытым тикетам и найди те, что делались по старой версии.
   Заведи тикет на доведение — **готово, когда:** ни один закрытый тикет не противоречит
   текущему ТЗ.

## Инструменты (tools/)

- `tools/subagent-prompt.template.md` — каркас промпта исполнителя. Заполнить и отдать.
- `tools/accept-ticket.ps1` — приёмка: тесты, сборка, внешние ссылки, git. Запускать, а не пересказывать.
- `examples/golden-case.md` — эталон: как выглядит хорошая приёмка и как ловится дефект.

## Gotchas

- **`node --test test/` падает с `MODULE_NOT_FOUND` на Node 24 под Windows.** Это баг
  Node, а не код. Рабочая форма — `node --test` без аргумента. Пиши это прямо в промпт
  сабагента, иначе каждый наступит заново и потратит попытку.

- **Сабагент не видит переписку.** Поймано в поле: ТЗ существовало только как документ в
  чате, первый сабагент ушёл бы вслепую. Всегда клади на диск заранее.

- **Тикет, сделанный до ревизии требований, молча остаётся старым.** Поймано в поле:
  раздел витаминов собрали с дозой 10 г, потом ТЗ изменили на 15 г — приложение
  показывало обе цифры в разных местах. Ревизия требований обязана порождать проход по
  закрытым тикетам.

- **Не давай сабагенту `disable-model-invocation`-скиллы.** Половина скиллов Pocock
  модель вызвать не может — попытка даёт ошибку. Для них выдавай пользователю строку
  для вставки.

- **Обрыв соединения оставляет незакоммиченную половину работы.** Не доделывай её руками
  и не удаляй: `git stash push -m "<тикет>, до <причина>"` — дерево чистое, работа
  возвращаема. Только потом перезапускай тикет.

- **Одинаковое число в трёх местах разъезжается.** Если доза, вес или порог живут в
  нескольких модулях — заводи одно определение сразу, а не после того, как разъехались.

- **Отчёт сабагента может заканчиваться вопросом из глобального CLAUDE.md** («Записать в
  скилл?»). Это утечка правил в его контекст, а не вопрос тебе. Игнорируй.

- **Скрипт приёмки пересобирает артефакт и может испачкать дерево.** Под Windows
  сгенерированный файл получает другие окончания строк, чем закоммиченный, и приёмка
  рапортует «незакоммиченные правки», хотя работы там нет. Проверь `git diff --stat`: если
  изменён только собранный артефакт — `git checkout -- <файл>`, это не потеря работы.

- **Сессионный лимит обрывает сабагента так же, как обрыв связи.** Половина работы в
  дереве, тесты красные, потому что старый API уже удалён, а новый не дописан. Лечение
  то же: `git stash push`, перезапуск тикета с чистого состояния. Не пытайся достроить
  чужую половину руками — быстрее и чище начать заново.

- **Отчёт без хеша коммита ещё не значит, что коммита не было.** Проверяй деревом и
  `git log`, а не наличием хеша в тексте.
