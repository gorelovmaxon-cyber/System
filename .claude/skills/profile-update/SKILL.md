# profile-update

Используй единый корень и формат из [memory README](../../memory/README.md).
Не создавай .system-memory/ и не дублируй записи в другом каталоге.

## Процесс

На границе задачи просмотри `pending` проектного
[журнала решений](../../../docs/decision-journal.md). Проектные факты и тарифы
не переносить в общий профиль; прямое предпочтение сохранять с его scope.

1. Проанализируй завершённую задачу и выдели только повторяемые предпочтения пользователя,
   а не факты проекта и не собственные решения агента.
2. Прямо выраженное и уже подтверждённое пользователем предпочтение можно
   сохранить через save.js с точной ссылкой на сессию без второго вопроса
   «сохранить?». Гипотезу агента о предпочтении сначала покажи пользователю
   с точным текстом; до подтверждения не записывай её как `confirmed`.
3. После прямого высказывания или подтверждения запиши через единый writer:
   - прямое подтверждение пользователя → status confirmed, source session with date;
   - гипотеза о предпочтении → status observation до прямого подтверждения;
   - category user-profile, подходящий scope, evidence и при необходимости confidence.
4. При конфликте сохрани прежний текст, новую запись свяжи полем supersedes, а
   прежнюю пометь superseded с обратной ссылкой.
5. Обнови MEMORY.md при добавлении нового файла. Секреты и машинные пути не сохраняй.
6. Сообщи путь, статус и источник; коммит сразу, push в согласованных границах без нового
   вопроса, вне них — по указанию пользователя.

Не записывай разовые решения, факты проекта или неподтверждённые выводы как
пользовательские предпочтения.
