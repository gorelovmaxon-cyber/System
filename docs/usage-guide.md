# Руководство по использованию System2

Полный контракт процесса находится в [system-workflow.md](system-workflow.md).

## Роли

Планировщик уточняет цель и пишет spec. Автор тикетов (в текущем процессе Sonnet)
разбивает spec по [TICKET_TEMPLATE.md](../TICKET_TEMPLATE.md). Исполнитель (GPT Luna
через VS Code/Qwen Code) реализует тикет. Приёмщик проверяет его и ставит `done`.

## Обычный цикл

1. Откройте репозиторий в VS Code и прочитайте обязательные инструкции проекта.
2. Согласуйте spec и остановитесь на гейте планирования.
3. Создайте тикеты по [единому шаблону](../TICKET_TEMPLATE.md), проверьте ссылки и
   зависимости, затем остановитесь.
4. Передайте исполнителю ровно один тикет. Он меняет только заявленный объём, запускает
   проверки и создаёт один scoped-коммит.
5. Передайте результат приёмщику. Приёмщик сверяет diff, тесты и evidence.
6. После принятия переходите к следующему тикету.

## Статусы

`planned` → `ready-for-agent` → `in-progress` → `awaiting-review` → `done`.
Если проверка невозможна — `awaiting-validation`; если продолжение невозможно без
внешнего изменения — `blocked` с причиной.

## Минимальный отчёт исполнителя

```text
ID: SC-xx
Изменено: <файлы/поведение>
Проверки: <команды и фактический результат>
Коммит: <hash>
Ограничения: <если есть>
Статус: awaiting-review
```

Не записывайте секреты в отчёты или Git. `push` выполняется после проверки и явно;
результат считается готовым только после фактической проверки и запуска.
