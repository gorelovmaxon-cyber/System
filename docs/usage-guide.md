# Руководство по использованию System2

Полный контракт процесса находится в [system-workflow.md](system-workflow.md).

## Роли

Выбранный пользователем планировщик уточняет результат и формирует
достаточный план; тикеты готовятся по [TICKET_TEMPLATE.md](../TICKET_TEMPLATE.md) —
планировщиком или исполнителем в тех же границах, отдельный обязательный автор тикетов
не нужен. Один выбранный пользователем исполнитель реализует связанные тикеты
последовательно в разрешённом блоке. Пользователь вручную передаёт задание и HANDOFF
между чатами; автоматического runner'а нет. Выбранный независимый приёмщик проверяет
законченный блок и ставит `done`; собственную реализацию не принимает.

## Обычный цикл

1. Откройте репозиторий и прочитайте обязательные инструкции проекта и HANDOFF.
2. Согласуйте результат, границы и достаточный план. Остановка нужна только при
   недостающем решении или доступе пользователя.
3. Создайте тикеты по [единому шаблону](../TICKET_TEMPLATE.md), проверьте ссылки и
   зависимости.
4. Передайте исполнителю разрешённый блок связанных тикетов. Он меняет только заявленный
   объём, запускает проверки и делает по одному scoped-коммиту на тикет, не останавливаясь
   на каждом вручную.
5. Передайте приёмщику законченный блок: он сверяет diff, тесты и evidence, дополнительные
   проверки выбирает по риску.
6. После проверки блока переходите к следующему.

## Статусы

`planned` → `ready-for-agent` → `in-progress` → `awaiting-review` → `done`.
Если проверка невозможна — `awaiting-validation`; если продолжение невозможно без
внешнего изменения — `blocked` с причиной.

## Минимальный отчёт исполнителя

```text
ID: SC-xx
Изменено: <файлы/поведение>
Проверки: <команды и фактический результат>
Коммит: <hash>
Ограничения: <если есть>
Статус: awaiting-review
```

Не записывайте секреты в отчёты или Git. После достаточных проверок `push` выполняется
в уже согласованных границах без нового вопроса; для этого можно использовать
`node scripts/memory/sync.js --status`, затем
`node scripts/memory/sync.js --push --branch <branch>`. Hook capture работает
fail-open и не делает push.
результат считается готовым только после фактической проверки и запуска. Полный
runbook: [docs/system-operations.md](system-operations.md).
