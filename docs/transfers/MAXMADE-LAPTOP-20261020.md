## 1. Получить точные версии из GitHub

Репозитории приватные: на ноутбуке потребуется вход своим GitHub-аккаунтом через
IDE/Git Credential Manager. Не вставляйте токен в URL команды или в переписку.
В PowerShell создайте новую папку; существующие рабочие копии не перезаписывайте.

```powershell
New-Item -ItemType Directory -Force C:\MAXMADE
Set-Location C:\MAXMADE
git clone https://github.com/gorelovmaxon-cyber/System.git System
git clone --branch integration/brief-vps-20261020 https://github.com/gorelovmaxon-cyber/Sait.git Site
git clone --branch integration/vps-20261020 https://github.com/gorelovmaxon-cyber/gotovaya-sistema-brifa.git Brief
```

| Копия | Где продолжать |
|---|---|
| Общая System2 | `C:\MAXMADE\System`, ветка `master` |
| Нынешний сайт | `C:\MAXMADE\Site`, ветка `integration/brief-vps-20261020` |
| Подключённая система | **`C:\MAXMADE\Brief\готовая система`**, ветка `integration/vps-20261020` |

GitHub main сайта содержит прежний v5. Старый корень репозитория Brief хранит
предыдущую систему. Для нынешнего VPS нужны именно указанные ветки и папка.

## 2. До ухода с основного ПК отдельно перенести два приватных файла

В Git опубликованы адреса, инструкции и **публичный ключ сервера**. Пароли,
приватные SSH-ключи и токены в репозитории отсутствуют. Для первого входа перенесите
два уже существующих файла через личную флешку или своё защищённое хранилище:

| На основном ПК | На ноутбуке |
|---|---|
| `C:\Users\gorel\.ssh\maxmade_codex_setup_20261014` | `%USERPROFILE%\.ssh\maxmade-bootstrap-from-main` |
| `C:\Users\gorel\.ssh\maxmade_brief_operator_20261020.json` | `%USERPROFILE%\.ssh\maxmade_brief_operator_20261020.json` |

Первый файл без `.pub` — действующий приватный SSH-ключ, который нужен только для
начальной выдачи доступа ноутбуку. Второй — логин/пароль CRM. Копирование через
Git, чат, issue или публичную ссылку не использовать. Оригиналы на основном ПК сохранить.
В `%USERPROFILE%` подставляется пользователь ноутбука, а не обязательно `gorel`.

Без приватного файла или отдельно зарегистрированного публичного ключа ноутбука
одного клонирования репозитория для SSH недостаточно. Вход SSH по паролю выключен;
старый root-пароль из прежней переписки не является способом текущего SSH-входа.

## 3. Выдать ноутбуку собственный SSH-ключ

Нужны Windows OpenSSH Client (`ssh`, `ssh-keygen`) и PowerShell. Python на ноутбуке
для этого шага не требуется: небольшой установщик выполняется имеющимся Python на VPS.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\MAXMADE\System\docs\transfers\maxmade-20261020\Register-MaxmadeLaptop.ps1
```

Скрипт проверит сохранённый ключ сервера, ограничит Windows-права приватных файлов,
создаст на ноутбуке `maxmade_laptop` и `.pub`, затем через временно перенесённый ключ
добавит **только публичный ключ** ноутбука существующему `maxmade-admin`.
Приватный ключ ноутбука на VPS не отправляется. Существующие ключи сохраняются;
повторное выполнение не добавляет дубликат. Перезагрузка, изменение firewall/sshd
и установка пакетов для этого не нужны.

При `Enter passphrase` задайте и сохраните парольную фразу локально. Ввод не отображается.
Не сообщайте её агенту/в чат. Если такие файлы уже существуют, скрипт использует их,
а не создаёт новую пару поверх прежней. При несовпадении trusted host/config остановится.

Успех: после установки ключа команда проверки выведет `maxmade-admin`, затем
`MAXMADE laptop key login confirmed`. После этой проверки повседневный вход использует
собственный ключ ноутбука, файл bootstrap больше для него не нужен. Сам скрипт
приватные файлы не удаляет; не передавайте временную копию другим людям.

Разрешён ExecutionPolicy Bypass только для этого запуска PowerShell, глобальная политика не меняется.
Справка по публичным/приватным ключам и Windows OpenSSH:
[Microsoft Learn](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_keymanagement).

## 4. Подключиться к VPS

После подтверждения собственного ключа ноутбука:

```powershell
ssh -F "$env:USERPROFILE\.ssh\maxmade-laptop.config" maxmade-vps
```

| Параметр | Значение |
|---|---|
| Провайдер / ОС | AdminVPS / Ubuntu24.04 |
| IP / порт | **185.250.47.204 /22** |
| Рабочий пользователь | **maxmade-admin**, `sudo -n` подтверждён чтением20.10 |
| Сайт | https://maxmadepro.ru/ |
| CRM / расчёт | https://maxmadepro.ru/crm / https://maxmadepro.ru/operator |
| Логин CRM | `maxmade`; пароль в отдельно перенесённом JSON-файле |
| Host key | ED25519, **SHA256:+HcXONWZ56cIrkyA/9omdommjuosBuYIy2YL3QpSvzI** |

Публичный `maxmade_known_hosts` лежит рядом со скриптом и переносится в `.ssh`.
`StrictHostKeyChecking=yes` проверяет его автоматически. Не вводите вслепую `yes`
и не удаляйте known_hosts при предупреждении. Это ключ **сервера**, не ключ ноутбука.
Anchor перенесён с действующего основного ПК и повторно сверён текущим строгим SSH.
Первоначальная независимая сверка через консоль провайдера не была подтверждена.
Для такой сверки в доверенной HTML-консоли AdminVPS выполняется:

```bash
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256
```

Если в новом сетевом окружении timeout, сначала проверяют доступность22/маршрут;
это не повод менять порт/firewall/ключ сервера. Proxifier ноутбука не нужен серверному
Telegram: его прокси уже работает на VPS.

## 5. Первый осмотр после входа — без изменения сервера

Команды выполняются в SSH-окне Ubuntu:

```bash
whoami
sudo -n systemctl is-active nginx php8.3-fpm mysql maxmade-brief maxmade-brief-telegram
readlink -f /srv/maxmade/current
readlink -f /srv/maxmade-brief/current
```

Ожидаются пользователь `maxmade-admin`, active и текущие выпуски:

- сайт `/srv/maxmade/releases/maxmade-20261020-brief-5ec8fda91785`;
- система `/srv/maxmade-brief/releases/20261020-71ae55dbf12d`.

`maxmade-admin` может выполнять необходимые административные команды через sudo.
Прямой root не требуется. Для SFTP используйте тот же ключ/пользователя; системные
каталоги root не становятся доступными на запись обычному SFTP. Новый выпуск
готовится отдельно и устанавливается через sudo, права `777` не нужны.

## Серверные ориентиры и откат

Данные системы: `/var/lib/maxmade-brief`, приватные settings:
`/etc/maxmade-brief`, service units `maxmade-brief` / `maxmade-brief-telegram`.
Старый MySQL/PHP-конфиг: `/etc/maxmade/config.php`, вложения:
`/srv/maxmade/private-lead-attachments`. Содержимое этих конфигов не печатать.
Исходники и резервные копии с секретами не добавлять в Git.

Резервные копии: `/var/backups/maxmade`, новая часть в `brief/`, ежедневно,
локально на VPS,14 дней. Возврат предыдущего сайта подготовлен, выполняется
только при необходимости по отдельному решению:

```bash
sudo -n python3 /root/maxmade-brief-deploy-20261020/rollback.py
```

Он возвращает прежний сайт/Nginx, сохраняя новые БД/файлы. Публичный `/api/` целиком
на Python не перенаправлять: есть действующие PHP lead/track. Не запускать локальные
fixture/live_preview.py как production-службу — они имеют другие настройки доставки.
Не редактировать current/dist на месте: новая копия → проверки → новый выпуск → переключение.

Передача содержит проверенные параметры и автоматизацию. Доступ конкретного ноутбука
считается выданным только после выполнения шага3 и успешного входа его новым ключом.
