# Проверки System2

Команды выполняются из корня System2. Node 24, Python 3.12 и Git должны быть
доступны. Быстрая проверка и полный набор разделены: наличие зелёного check не
доказывает работу интеграций или правильный ответ модели.

## Однократная подготовка зависимостей

Создать локальное окружение Python (не меняет глобальный Python):

```powershell
python -m venv .local/check-venv
.local/check-venv/Scripts/python.exe -m pip install -r requirements-check.txt
npm ci --prefix .claude/mcp-servers/figma --ignore-scripts --no-audit --no-fund
```

На Linux/macOS путь Python внутри venv — `.local/check-venv/bin/python`.
PyYAML закреплён в `requirements-check.txt`, зависимости Figma — в существующем
package-lock.json. Установленные пакеты остаются в игнорируемых каталогах.
Установка — явный этап подготовки, команды проверки сами пакеты не устанавливают.
В CI Python готовится в отдельном окружении job. Можно явно задать
`SYSTEM2_CHECK_PYTHON`, если Python с PyYAML уже подготовлен.

## Команды

| Команда | Что доказывает |
|---|---|
| `npm run check` | Синтаксис JS/CJS, настоящий YAML всех канонических навыков, локальные Markdown-ссылки/якоря в действующих документах, diff --check, негативные проверки самого checker |
| `npm run test:memory` | Полный набор памяти/очереди/синхронизации в изолированной копии и временных фикстурах |
| `npm run test:figma` | Извлечение токенов и MCP initialize/list/call с fixture, без рабочего .env и запросов Figma API |
| `npm run test:python` | Регрессии launcher’а Khoj с подменой PostgreSQL; сервис не запускается |
| `npm run test:all` | Check, Python, Figma и полный memory-набор; останавливается при первой ошибке |

`check` рассчитан на быстрый локальный ответ, полный набор занимает минуты и в
него не включается. Если среда или новая проверка замедлила check — измерить и
разделить этапы по смыслу, не ослабляя проверку ради произвольного числа замечаний.
Полный suite нужен по изменению общих механизмов/обязательному гейту; без нового
основания уже успешные проверки не повторяются.

## Изоляция и доказательства

Memory runner копирует код и публичные конфиги во временную папку, удаляет
связанные с System2/интеграциями секретные переменные из окружения дочернего
процесса и задаёт временные Git-конфиги/каталоги. Не копируются рабочая память,
local config, SSH, hooks проекта и реальные endpoint. Git push в тестах идёт
только к созданным ими локальным bare-репозиториям. Логи TAP и result.json
остаются во временной папке, путь выводится при запуске.

Git-тесты сами задают merge-политику, создают нужный каталог hooks и добавляют
Git Bash usr/bin только в среду своего дочернего процесса. Глобальные настройки
пользователя не меняются. Транспортный отказ доставки сохраняет ограниченный
код причины в last_error, без тела запроса или скрытого повтора. HTTP 408 по-прежнему
проверяется именно как HTTP 408; диагностические данные тестового сервера
помогают отделить отсутствие запроса от неправильного ответа.

YAML-проверка поддерживает существующие `disable-model-invocation`/`argument-hint`
и не меняет политику вызова навыков ради валидатора. Отсутствие PyYAML — ошибка
подготовки, а не успешная проверка. Ссылки внутри fenced/inline примеров не
проверяются как реальные файлы текущего репозитория. Checker тестирует, что
некорректный синтаксис, YAML и ссылка действительно дают отказ.

## CI и живая приёмка

Checker явно проверяет также OPUS.md, QWEN.md, TICKET_TEMPLATE.md,
`.claude/memory/MEMORY.md` и `.claude/memory/README.md`, если они существуют.
Историческая память рекурсивно не проверяется. Примеры ссылок отмечаются inline/fenced
кодом; реальные ссылки сохраняют проверку. URL-fragment декодируется одинаково для
Markdown и HTML id; ошибочный percent-escape даёт диагностическую ошибку проверки.

[GitHub workflow](../.github/workflows/check.yml) запускает `test:all` для push и
pull_request в Windows с закреплёнными Node/Python. Файл workflow сам по себе не
доказывает успешный удалённый run; до push/прогона он остаётся непроверенным в GitHub.
Branch protection — отдельное изменение настроек репозитория и здесь не включается.

Структурная проверка 50 навыков не является живым прогоном 50 команд. Роль,
границы, остановки start и новая сессия требуют отдельных фактических ответов
выбранного агента. Матрица и непроверенные пункты — в
[отчёте исправлений](../.scratch/system-checks-2026-10-21/RESULT.md).
Ни check, ни полный suite не обещают доступность Khoj/AP/production-сервисов,
обязательное автосохранение или межмашинное восстановление.
