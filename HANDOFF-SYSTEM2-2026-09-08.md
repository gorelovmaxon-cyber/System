## 2. Что хочет пользователь

- Постоянный помощник, который между сессиями помнит решения, причины,
  исправления и предпочтения пользователя, а не требует пересказывать контекст.
- Одна общая система для разработки, сайтов и маркетинга; у проектов свой
  контекст и HANDOFF, общие предпочтения доступны всем без смешивания данных.
- Продолжение работы на другом ПК без потери памяти и незавершённой работы.
- Меньше затрат на загрузку контекста и ручное обновление профиля без потери качества.
- Сначала закончить Khoj и Activepieces, затем довести интеграции и весь цикл.
- Понятные объяснения и конкретная работа, без постоянного перепланирования,
  раздутого чата и ненужных новых компонентов.

**Главная — локальная система, а не репозиторий.** В неё входят инструкции,
память, незакоммиченные файлы, локальные настройки, очереди, сервисы и их данные.
Git хранит переносимую часть и помогает синхронизации, но не заменяет резервную копию.
На ноутбуке корень может отличаться от `E:\System2`; пути нужно определять по месту.

## 3. Согласованная архитектура и процесс

- `.claude/memory/`: общая память, профиль, facts, decisions, patterns, gotchas.
  Наблюдение модели не становится подтверждённым предпочтением без источника.
- Инструкции и короткий HANDOFF читаются обязательно. Khoj дополнительно
  выбирает релевантную память с источниками и ограничением объёма; при отказе есть fallback.
- Commit и явное резюме сессии создают события. Одна Git-история не сохраняет причины решений.
  Автоматический сбор всех браузерных переписок не входит в согласованный объём.
- Надёжная локальная очередь → Activepieces анализирует событие → Node bridge/writer
  проверяет результат и записывает память → обновляется индекс Khoj.
- Повторы не создают дублей; сбои не теряют события. Состояния записи, синхронизации
  и индексации различаются. Конфликты сохраняют обе версии, а не затираются.
- Git/hooks, bootstrap и doctor обеспечивают переносимость и диагностику.
- Figma MCP нужен для получения данных макета; реальные значения и доступ проверяются отдельно.
- Gemini в обсуждённом процессе — внешний исследовательский источник, не основная память.
- Сервер 24/7 — возможный следующий этап, не обязательная часть локальной v1.

Процесс: планировщик (мы/Opus) → Sonnet нарезает → GPT Luna реализует →
отдельная проверка результата. Имена моделей здесь — роли из переписки,
а не подтверждение доступности конкретных версий или автоматического делегирования.
Тикет содержит контекст, контракты, шаги, ограничения, зависимости и проверяемую
приёмку; полный готовый код внутри тикета не обязателен.

«За один проход» означает закончить согласованный объём с исправлениями по тестам,
а не обещание работы без ошибок. Заявления «90% экономии токенов», «100% автоматизации»
и «0% ошибок дизайна» не подтверждены измерениями и не являются фактическим результатом.

## 6. Что точно нельзя считать завершённым

- По отчётам Луны на исходном ПК отсутствовали Docker Desktop/WSL и работающий Khoj.
  Установка Khoj столкнулась с Python 3.14; предложен Python 3.12.
  На новом ПК версии и совместимость нужно проверить заново, не повторять вывод вслепую.
- Activepieces в реализации закреплён на 0.86.3, но живой запуск не принят.
- `services/activepieces/flows/memory-event-to-writer.json` — **blueprint**, а не
  подтверждённый импортируемый экспорт. README прямо требует сборки шагов в UI
  или адаптации к формату установленного релиза. Это оставшаяся реализация, не только тест.
- Нет принятого цикла с реальным AI-подключением и webhook, вызовом writer и reindex.
- Реальный второй ПК, Figma-макет и восстановление сервисов не проверены.
- Отчёт, названный independent acceptance, появился в серии работ исполнителя;
  его название не заменяет отдельное ревью нами.
- В SUMMARY осталась историческая вводная «тикеты не выполнялись», ниже уже указаны
  результаты исполнения. При доработке устранить противоречие и согласовать статусы
  в самих тикетах, SUMMARY и release matrix. Это подтверждённый дефект отчётности.

## 7. Порядок продолжения — без нового большого перепланирования

1. **Сохранить и сверить состояние обоих ПК.** Найти фактический корень, прочитать
   локальные инструкции, проверить HEAD, dirty/untracked-файлы и наличие планов.
   Не делать reset/clean, не затирать ноутбук клоном поверх существующей работы.
2. **Независимо проверить реализацию Луны.** Сверить SC-01…18 с кодом и доказательствами;
   воспроизвести доступные тесты. Отдельно проверить writer, очередь, retries,
   атомарность/блокировки, авторизацию, допустимые пути и изоляцию проектов.
   Не записывать тестовые данные в настоящую память. Получить короткий список дефектов
   с воспроизведением и приоритетом; отличать баг от недостающего доступа/сервиса.
3. **Поднять необходимые сервисы.** Выбрать поддерживаемую среду Khoj и реальную
   конфигурацию Activepieces по закреплённым версиям; проверить Docker → host bridge.
   Ключи и доступы вводить локально, не в чат, Git, отчёты или индекс.
4. **Довести главное ядро.** Завершить настоящий flow: событие → AI → проверенный writer
   → индекс → поиск. Проверить повторы, отключение сервисов, ошибочный AI JSON,
   изменение/удаление памяти и возобновление после сбоя.
5. **Довести перенос и дополнительные проверки.** Hooks/sync/HANDOFF, реальный ноутбук,
   конфликты и restore. Figma можно проверять параллельно при наличии доступа,
   если работа не пересекается с файлами ядра.
6. **Принять v1.** Пройти реальную задачу до продолжения на другом ПК, сверить R01–R13,
   обновить единую матрицу статусов. Выпуск только после доказательств, не по количеству коммитов.

Не начинать заново T5–T9: их объём уже включён в SC. Не добавлять Hermes,
новый оркестратор или серверное развёртывание как условие завершения текущего ядра.

PLAN, SPEC, SONNET_PROMPT, все 18 тикетов, SUMMARY, отчёты, код, память и этот

**Git по-прежнему не переносит локальные настройки, секреты, очереди, данные сервисов,
снимки backup и настройки провайдера в `.vscode/`.** Их нужно восстановить/настроить
отдельно. Полная рабочая система ещё не готова и не восстановлена на реальном ноутбуке.
Архив `system2-export.tar.gz` и старые API-скрипты исключены из Git; не публиковать их
без отдельной проверки секретов. Копии памяти SC-02/SC-03 остаются только на исходном ПК.

retrieval вернул local fallback. Тестовый commit не публиковался.
Это проверка переносимости файлов, не замена независимого аудита и live-приёмки.
