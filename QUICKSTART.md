# System2 — краткий запуск

Единый процесс: [docs/system-workflow.md](docs/system-workflow.md). Для запуска,
диагностики и восстановления см. [docs/system-operations.md](docs/system-operations.md).

| Роль | Ответственность | Остановка |
|---|---|---|
| Планировщик (Astra или выбранная модель) | результат, план, тикеты, проверка блока | при недостающем решении пользователя |
| Исполнитель (один Sonnet/Sol) | связанные тикеты по [TICKET_TEMPLATE.md](TICKET_TEMPLATE.md), проверки, один коммит на тикет | на границе блока |
| Пользователь | оркестрация и решения на гейтах | между фазами |

Отдельный обязательный автор тикетов не нужен; автоматического запуска исполнителя нет —
задание передаётся файлом задачи и HANDOFF.

## Цикл

1. Планировщик согласует результат, границы и тикеты.
2. Исполнитель получает разрешённый блок связанных тикетов, реализует их последовательно
   и коммитит каждый.
3. Приёмщик проверяет законченный блок: diff, реальные проверки, evidence.
4. При успехе следующий блок; иначе — конкретная доработка.

Правило: один тикет = один коммит; независимая проверка — на границе блока. После
достаточных проверок `push` выполняется в уже согласованных границах без нового вопроса;
вне этих границ — по указанию пользователя. Force-push и безусловная фоновая
синхронизация не используются.

## Проверка результата

```text
git status
git log --oneline -1
git diff HEAD~1 --stat
```

Команды тестов берутся из конкретного тикета. Не используйте destructive reset для
чужих изменений.
