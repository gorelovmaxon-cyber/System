## Алгоритм (шаг за шагом)

1. **В `D:\System2\OPUS.md`, секция "### 3. Создай тикеты" (примерно строки 45-70):**
   
   После описания структуры тикета добавить:
   
   ```markdown
   **ВАЖНО: Обязательные ссылки на файлы**
   
   Qwen — исполнитель, не заставляй его искать файлы. В каждом тикете обязательно:
   
   1. **В секции "## Контекст"** — первым блоком:
      ```markdown
      **Файлы для изменения:**
      - [относительный/путь/к/файлу.js](относительный/путь/к/файлу.js)
      - [другой/файл.md](другой/файл.md)
      ```
   
   2. **Смежные файлы для контекста** (после основного описания):
      ```markdown
      **Смежные файлы для понимания контекста:**
      - [путь/к/документации.md](путь/к/документации.md) — зачем читать
      - [путь/к/связанному/коду.js](путь/к/связанному/коду.js) — зачем читать
      ```
   
   3. **Используй кликабельные markdown ссылки** формата `[текст](путь)`, не просто обратные кавычки
   
   4. **Полные пути от корня проекта** или абсолютные (`D:\System\...`), не "файл где-то в src"
   
   **Пример плохо:**
   ```markdown
   ## Контекст
   Нужно изменить `data.js` и посмотреть на `workout.js`
   ```
   
   **Пример хорошо:**
   ```markdown
   ## Контекст
   
   **Файлы для изменения:**
   - [src/data.js](src/data.js)
   - [src/workout.js](src/workout.js)
   
   **Смежные файлы для понимания контекста:**
   - [ТЗ.md](ТЗ.md) — раздел "Оборудование"
   - [src/settings.js](src/settings.js) — текущая логика настроек
   ```
   
   **Зачем:** Qwen в VS Code просто кликает по ссылке и открывает файл. Никакого поиска, никаких догадок.
   ```
