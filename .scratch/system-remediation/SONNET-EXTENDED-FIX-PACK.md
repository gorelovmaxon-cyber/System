## Поручение

Пользователь попросил расширить проверку и передать проблемы одним пакетом, чтобы исправлять причины и смежные сценарии, а не получать по одной ошибке за раунд. Этот документ **дополняет актуальный SONNET-PROMPT.md**. Согласованная архитектура, самостоятельная нарезка Sonnet, scoped-коммиты и независимый рубеж до настоящей памяти сохраняются. Старые приёмки не объявляются пройденными.

Прочитай этот пакет целиком, сопоставь находки с существующими FIX-01…11, дополни тикеты либо сам создай необходимые небольшие тикеты. **Затем выполни исправления доступного объёма**, не заканчивая только новой нарезкой. Число тикетов не равно числу строк ниже: группируй по общей причине, контракту и проверяемому результату. Не переписывай систему с нуля, не канонизируй текущий lock в скилле.

## Первый приоритет: корректность записи и границы памяти

### T1 · P1 · Карантинная блокировка по-прежнему допускает двух владельцев

Подробности и доказательства — в третьем ревью. Процесс P уже получил lock; устаревший C переносит его в карантин; до восстановления канонический путь свободен и третий T получает lock. P и T оба вошли, P не вызывал release.

**FIX-02:** сначала обосновать протокол владения/восстановления для трёх процессов и остановки на любой его границе. Не исправлять только конкретную задержку теста. Rename освобождает путь и потому не устраняет проблему устаревшего решения. Если существующие ограничения мешают корректному решению, обозначить минимальное необходимое изменение; не заменять гарантию словами. Не подключать этот lock к очередям как готовый общий примитив до проверки.

### B01 · P1 · Отсутствующий evidence записывается как строка "undefined"

`writer.js:168`: singleLine делает String(value) до проверки типа. Удалить evidence из предложения → writer возвращает persisted, в памяти `evidence: undefined`. Аналогично null/объект становятся непустой строкой. Исходная валидация требовала строку, поэтому это регрессия изменения S2.

**FIX-01:** сначала проверить тип/наличие обязательных полей, потом нормализовать строку. Reject undefined/null/объект/массив для обязательного evidence, проверить source/supersedes и лимиты. Нельзя «подтверждать источник» за счёт строкового преобразования отсутствующего значения.

### B02 · P1 · Проверка пути writer обходится через Windows junction

`writer.js:248`: path.resolve/startWith проверяют только лексическое имя. Создать внутри синтетического memory_root категорию facts как junction на другой TEMP-каталог. writer сохраняет файл **вне разрешённого memory_root**, возвращая обычный путь `.claude/memory/facts/writer-entries.md`.

**FIX-01 и проверки путей:** проверять фактические пути/ссылки в существующих предках и целевых файлах, включая Windows junction/reparse point. Безопасная политика для ссылок должна быть явной; если они не поддержаны — отклонять с понятной ошибкой. Не утверждать полный sandbox против другого процесса с правом менять ФС без соответствующего механизма. Проверить аналогичные границы search/indexer и сохранность старых файлов.

### B03 · P1 · Local config перенаправляет явно заданный root и смешивает конфигурации двух копий

`resolve-paths.js:97`: при options.root=A и SYSTEM2_ROOT=A, но local config A содержит system_root=B, resolver возвращает root/memory/data от B, registry и localConfig — от A. В тесте обе копии валидны. Это нарушает задокументированный приоритет и особенно существенно для существующих D:\System2 и D:\SystemTheBest\System.

**SC-02 / отдельный FIX по конфигурации, при необходимости выделить из FIX-11:** один приоритет explicit root → env → discovery/config по принятому контракту; не смешивать разные корни. Доказать, что явно выбранная копия не пишет в другую из-за старого local config. Проверить cwd, env, local paths, bootstrap и запуск из другого проекта.

### B09 · P1 · Оборванный writer/indexer JSONL-хвост блокирует восстановление

`writer-log.js:18`, `indexer-log.js:18`: после одной корректной операции дописать незавершённый JSON. Новая запись writer и просмотр index status падают SyntaxError, корректные старые записи через API недоступны. F10 ранее воспроизведён для очереди; теперь независимо подтверждено для обоих журналов.

**FIX-06 + интеграция FIX-01/07:** общая проверенная стратегия восстановления/диагностики журналов, сохранение исходного повреждённого хвоста, отличение прерванного хвоста от повреждения середины, отсутствие молчаливой потери подтверждённых записей. Проверить поведение при параллельном append/read, не просто подавить JSON.parse.

### B15 · P2, обязательно до миграции · Новая нормализация ломает повтор старого intent

`writer.js:295`: старый валидатор сохранял source с краевыми пробелами как есть; новый обрезает до hash. Синтетический intent с корректным старым hash и source `  evidence-source  ` при повторе **того же исходного запроса** теперь даёт CONFLICT. Память может ещё отсутствовать; восстановление не завершается.

**FIX-01/04:** версионированная совместимость/безопасная миграция журналов и старых предложений. Не ослаблять проверку настоящего конфликта и не перезаписывать старый hash автоматически без проверки. Добавить fixtures старых валидных LF/CRLF, пробелов, evidence/source/defaults и состояний intent/persisted. Заявление «формат/алгоритм совместимы» нуждается в уточнении. Для неподдерживаемого старого ввода — явное безопасное восстановление, не вечная необъяснённая блокировка.

## Поиск: конфигурация, источники и полнота разрешённых результатов

### B04 · P2 · Наличие минимального local config отключает наследование поисковых настроек

`search.js:13`: configFor выбирает либо local, либо example. Example с khoj.enabled=false; local содержит только local_paths. search пытается выполнить HTTP. В тесте fetch подменён, реального запроса не было. Аналогично могут исчезать настроенные endpoints/budget/timeout.

**FIX-03 + конфигурация:** один согласованный merge с сохранением вложенных значений и явных false/0 там, где они допустимы. Проверки минимального override и частичного integrations.khoj. Не заводить несколько разных политик конфигурации по модулям.

### B05 · P2 · Произвольный разрешённый memory_root ломает положительный поиск

`search.js:19,207`: writer пишет в configured `custom-memory`, Khoj возвращает существующий абсолютный путь этого файла. relativeSource делает ссылку с `.claude/memory`, а чтение ищет именно там → `ok:true, results:[]`.

**FIX-03:** фактический путь разрешать от memory_root, display source хранить отдельно при необходимости. Проверить абсолютные/относительные варианты, пользовательский корень, кавычки/пробелы/Windows-пути и отсечение выхода наружу. Нельзя подставлять непроверенный snippet при ненайденном файле.

### B14 · P2 · Запрещённая лучшая запись скрывает разрешённую из того же файла

`search.js:209`: сначала matchEntry выбирает одну лучшую запись без scope, затем фильтр отклоняет её целиком. Файл содержит B: `SHARED_QUERY private details`, затем A: `SHARED_QUERY allowed details`; запрос A и общий snippet дают пустой результат, хотя локальный fallback находит A.

**FIX-03:** фильтровать кандидатов по разрешённой области до выбора/ранжирования или возвращать все подходящие разрешённые записи с общим limit. Проверить одинаковые слова разных проектов, user, обратный порядок, несколько hits одного файла. Не исправлять полноту ценой снятия изоляции.

### B07 · P2 · Повтор ручной индексации изменённого файла ничего не делает

`indexer.js:36,104`: CLI по умолчанию использует event_id=manual. После первой successful индексации изменить файл, снова queueIndex('manual',file): возвращается старая indexed-задача, run не обрабатывает ничего. Такой же риск при повторном использовании pair(event_id,file) для нового поколения содержимого.

**FIX-07:** различить повтор одной задачи и новую ревизию файла/явную новую операцию. Ручная команда должна уметь повторно проиндексировать изменённый или удалённый файл, сохраняя идемпотентность retries.

### B08 · P2 · В indexer нет backoff

Два последовательных run после 503 выполняют две попытки за десятки миллисекунд; настройка backoff_ms=60000 не учитывается. В задаче нет next_attempt_at. Требование backoff уже есть в SC-10.

**FIX-07/08:** честный график повторов, лимит, причина, принудительный ручной повтор отдельно; управляемые часы в тестах. Не считать многократный немедленный run реализацией backoff.

### B16 · P3 · Несколько предложений одного файла создают одинаковые pending-строки индекса

`indexer.js:32`: Map current не обновляется внутри queueIndex. Пакет из двух предложений facts создаёт **две строки** одинакового task_id. status Map показывает одну и маскирует проблему. На текущем одиночном run это ещё не доказывает две HTTP-доставки, но противоречит требованию одной постановки и раздувает журнал.

**FIX-07:** дедупликация files и актуализация состояния на каждой постановке; тестировать не только размер Map, но и журнал и фактическое число обработок.

### B19 · P1 · Indexer принимает абсолютный путь с .. вне памяти

`indexer.js:17`: абсолютный candidate проверяется prefix без path.resolve. `memory_root\..\..\outside.md` принимается, хотя фактическое разрешение — файл вне памяти. В тесте выполнена нормализация, внешнего HTTP/чтения файла не было.

**FIX-07 + единая проверка путей:** нормализовать до проверки и проверить фактический разрешённый путь, включая ссылки; покрыть абсолютный/относительный путь, Windows case/разделители, соседнюю папку с похожим именем. Не отдавать стороннему API непроверенный путь.

### B10 · P2 · Ограничение diff портит UTF-8 и превышает размер

`events.js:30`: truncateUtf8('яяяя',6) даёт строку с U+FFFD размером **8 байт** при лимите 6. Обрезка выполнена внутри кодовой точки, декодирование добавляет replacement-character.

**FIX-06:** резать по корректной границе UTF-8 с учётом многобайтных символов и самого суффикса. Проверки кириллицы, emoji, лимита меньше суффикса, 0/недопустимых значений. Нулевой U+FFFD в исходниках не проверяет этот runtime-дефект.

### B11 · P2 · Валидатор события пропускает отсутствие event_id и неправильные типы массивов

`events.js:37`: создать корректное событие, удалить event_id, заменить decisions на объект → validateEvent принимает; enqueue тоже сохраняет. Доказан дефект экспортированных контрактов validateEvent/queue API. Стандартный createEvent генерирует id, поэтому не утверждается, что любой обычный CLI-вызов уже создаёт такой журнал.

**FIX-06:** полная schema-валидация на границе приёма, deterministic identity, типы всех полей, revision/timestamp/размеры. Недопустимое входное событие не должно попасть в журнал под undefined-ключом. Проверить и прямой API, и capture/--file.

## Два пункта с подтверждённым поведением, но требующие явного контракта

### B17 · Контракт writer: пустой пакет

writeProposal(event_id,[]) возвращает persisted с пустым written_files и закрепляет hash события; последующая попытка сохранить данные под ним — CONFLICT. Сам запрет изменять content события логичен, но значение persisted без записи и допустимость пустого пакета не сформулированы.

**FIX-01/09:** выбрать и документировать: отклонять пустой write или явный идемпотентный результат без знания. Согласовать с веткой has_pattern=false в flow. Не выдавать эту неопределённость за автоматически доказанную потерю данных и не ослаблять конфликт всего события.

### B18 · Локальный Figma extractor игнорирует options.nodeId

extractDesignTokens(file,{nodeId:'1'}) возвращает токены узла 2 из того же входного дерева. Доказано на синтетическом дереве без API; сервер передаёт этот аргумент, но extractor его не использует. Не утверждается, что живой Figma API обязательно возвращает лишний узел: его фактическую фильтрацию ещё нужно проверить.

**SC-14 / FIX-11 либо отдельный FIX:** обеспечить контракт nodeId на стороне извлечения или доказать и документировать достаточную гарантию предыдущего слоя. Проверить fixture-путь и node-id в URL отдельно от отдельного аргумента, дерево с соседними узлами, неподдержанные значения. Версии и реальные ответы сверять по первичным источникам при live-проверке.

Проверь фактический запуск/планировщик и доказательство «получатель восстановился — backlog дренируется без новых commit». Worker Activepieces сам по себе не доказывает обработку локальной Node-очереди. Команда status не должна менять владение.
- **Долговечный capture до завершения hook:** post-commit запускает Node в фоне и выходит. Сбой сессии до enqueue может оставить только diff-файл. Доказать восстановление/сверку пропущенных commit-событий или безопасно зафиксировать событие до фоновой доставки. Не блокировать commit ожиданием AI.
- **Граница webhook 2xx/persisted:** deliverEvent принимает любой 2xx за успех, не проверяя конечный результат flow. Исполнить FIX-09 на действительной версии Activepieces и доказать долговечную передачу ответственности.
- **Doctor:** health URLs и часть путей захардкожены; настройки альтернативных портов/корня не учитываются. Проверить диагностику настоящих endpoints и разницу «процесс жив»/«готов записывать» (bridge health отвечает 200 даже без token).
- **Hook в обычном подключённом проекте:** hook ищет scripts/memory относительно Git-корня проекта; init-project туда эти скрипты не ставит. Проверить реальный проект A вне System2, его SYSTEM2_ROOT/project_id и доставку в каноническую очередь.
- **Git sync:** status проверяет только memory/config и не все файлы/HANDOFF; upstream может быть устаревшим, push всегда использует origin. Проверить выбранную ветку/remote, detached HEAD, upstream и честное значение clean/synced. `push` коммитов не сохраняет незакоммиченный HANDOFF.
- **Writer/индекс совместно:** индексатор тоже append-ит writer-log и может сохранять устаревшую копию состояния. Нужны параллельный writer/indexer/recovery и проверка актуальности поколений; отдельная успешная функция этого не доказывает.
- **Figma:** проверить скрытые fills, значение alpha, gap без padding, разные радиусы, фильтр узла и ошибки MCP. Здесь API-совместимость/реальные значения независимо не принимались.
- **Среда и восстановление:** compose/flow blueprint не равны живому запуску. Docker/WSL, AI/Figma доступы, backup сервисов, реальный второй ПК и режим offline/restore остаются самостоятельной приёмкой. Не менять системную безопасность или выполнять неавторизованные платные вызовы ради зелёного статуса.

## Как выполнить пакет без нового бесконечного планирования

1. Проверь актуальный HEAD/dirty и сопоставь этот пакет с уже внесёнными правками. Создай `EXTENDED-FIX-MATRIX.md`: T1/B01…19/F05…10 → existing/new FIX → требование → тест → статус. Для B17/B18 и статических зон укажи уровень доказательств/выбранный контракт отдельно.
2. Первыми исправляй взаимное исключение, валидацию, границы путей и единственный выбранный корень. Расширение корректного общего механизма не должно переносить дефект T1 в очереди.
3. Затем согласованно исправь capture/журналы/queue/indexer, включая старые F05…10 и новые B-пункты. Не выдавай отсутствие реального Khoj за причину не выполнять локальные проверки.
4. Доведи retrieval/config и сохранение HANDOFF/hooks/project identity. Повторный bootstrap и перемещение/вторая копия должны проверяться на данных, а не только по файлам.
5. После локальных исправлений — доступные живые интеграции и оставшиеся SC, с внешней приёмкой до настоящей памяти согласно SONNET-PROMPT. Пока рубеж не пройден, независимые тесты/правки выполняются на синтетических данных.
6. Перед подачей на приёмку сам пройди **все сценарии пакета**, а не только последнее замечание, и создай положительные регрессии. Для общих механизмов включи смежные варианты, перечисленные выше. Сохраняй исходные evidence, не меняй ожидания ради успеха.
7. Отдельные коммиты по проверяемым FIX, обновлённые SC/матрица/WRITER-REVIEW/HANDOFF и один итоговый пакет на ревью: что закрыто, что осталось, почему, команды, коммиты и реальные результаты. Статус исполнителя awaiting-review; READY требует полной приёмки.

Новый скилл сейчас не требуется. Главное — выполнить этот объединённый объём и представить проверяемый результат. Проверяющий не обещает, что после расширенного ревью больше не появится ни одного дефекта, но следующие правки должны охватывать классы ошибок и взаимодействие компонентов, а не только знакомые тестовые строки.
