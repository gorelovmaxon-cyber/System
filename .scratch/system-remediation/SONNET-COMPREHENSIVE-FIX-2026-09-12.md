# Sonnet — единое задание после общего аудита 12 сентября

Прочитай полностью [COMPREHENSIVE-REVIEW-2026-09-12.md](COMPREHENSIVE-REVIEW-2026-09-12.md), [V1](INDEPENDENT-REVIEW-2026-09-12.md) и актуальный [SONNET-PROMPT.md](SONNET-PROMPT.md). Общий аудит дополняет прежний EXTENDED-FIX-PACK; выполненные полезные изменения сохранить.

## Поручение на следующий проход

1. Сверь HEAD/status и source manifest аудита. Сохрани текущие незакоммиченные изменения отдельно, не reset/clean. Проверенный HEAD fb10b89 не включает весь пакет; не исправляй только чистую копию HEAD, потеряв untracked-модули.
2. Сам сопоставь V1/G01…G19 с FIX/SC, уточни существующие тикеты и добавь недостающие по общей причине. Не ограничивайся планом: затем исполняй. Для G12/G14/G18 обозначь отсутствующую операцию/интеграцию; для G16 явно выбери и зафиксируй контракт вместо заявления о доказанной live-ошибке.
3. Первый блок — взаимное исключение V1 + G15. До реализации опиши право входа, идентичность ресурса, смерть/паузу каждого процесса до и после публикации, безопасный release и общую память с разными data_dir. Не исправляй только расписание новой пробы ещё одним pid-check.
4. Второй блок — очередь/индекс как единый механизм: актуальные часы claim/backoff, межжурнальный recovery, reconcile, честный indexed, долгие внешние запросы и устаревший finish.
5. Затем общие границы чтения/индекса, project_id, канонизация hash и входная валидация capture; потом init/register/hooks/worker/sync. Используй порядок из общего отчёта.
6. На каждый инвариант: позитивная регрессия, RED на реальном исходном дереве либо явно обозначенной реконструкции, исправление, GREEN и соседние сценарии. Сохрани исторические результаты harness до повторов; exit 0 у audit-probe означает наличие проблемы.
7. Актуализируй FIX/SC, матрицы, WRITER-REVIEW, контракт и HANDOFF. Сохрани все изменения scoped-коммитами. Не выдавай неполный dirty tree за воспроизводимый принятый commit. Публикацию выполнять по действующему заданию пользователя; этот файл не заменяет сохранение runtime/секретов отдельной копией.
8. Подай полный локальный пакет на независимую приёмку вместе с точным SHA, статусом дерева и перечнем внешних проверок. До положительного вердикта не мигрировать настоящую память и не подключать writer к рабочему потоку.

Штатные 100/100 подтверждены аудитом, конкретный U2 улучшен; это сохраняем. Самостоятельно accepted/READY не выставлять. Живой AP/Khoj/AI/Figma, настоящий второй ПК и restore остаются последующим этапом. Новую систему, глобального оркестратора или skill с текущим lock не создаём.
