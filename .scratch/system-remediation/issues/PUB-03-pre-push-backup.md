**Blocked by:** PUB-01, PUB-02
**Status:** planned

Существующий bundle `transfer-backups\2026-09-09-1701\system-master-2026-09-09.bundle` снят
с `c0b3459` и **не содержит** ни одного из сегодняшних коммитов. Полной копии текущего

Bundle снимается **до** push: он и есть страховка на случай, если push не пройдёт.

## ⚠️ Файлы НЕЛЬЗЯ трогать

- `.gitignore` и отслеживаемые файлы репозитория — тикет ничего не коммитит.
- `.local/**`, `config/system.local.json`, `services/activepieces/.env` — копируются в резерв, но не в Git.
- Значения секретов не выводить в чат и не записывать в отчёт.

## Входные/выходные данные

Вход: рабочая копия на `HEAD`. Выход: папка резерва с bundle, манифестом SHA-256 и инвентаризацией; для untracked-файлов — копии по относительным путям.

## Алгоритм (шаг за шагом)

1. Создать уникальную папку `D:\SystemTheBest\transfer-backups\pre-push-<YYYYMMDD-HHMMSS>`. Существующую не перезаписывать.
2. `git bundle create <путь>\system-master-<дата>.bundle --all`, затем `git bundle verify <путь>`.
3. Сохранить в папку: `git rev-parse HEAD`, `git status --short --untracked-files=all`, `git log --oneline origin/master..HEAD`, `git remote -v`, вывод `git ls-remote origin refs/heads/master`.
4. Скопировать untracked-содержимое по относительным путям и посчитать SHA-256 копий. Файл `evidence/status-check-current-tests.txt` копируется как есть (UTF-16), в Git не пойдёт.
5. Инвентаризировать локальный runtime: `config/system.local.json`, `.local/**`, `services/activepieces/.env`. Копии — в резерв; значения секретов в отчёт не выводить. Для `.local/*.jsonl` учесть, что это живые журналы: копия — снимок, а не согласованный дамп.
6. Записать в отчёт: что сохранено, что отсутствует, что не удалось сохранить.

## Критерии приёмки

- [ ] `git bundle verify` возвращает успех; в bundle присутствует текущий `HEAD`.
- [ ] Манифест SHA-256 совпадает с копиями untracked-файлов.
- [ ] Секреты не попали в отчёт и в Git; значения ключей не выводились.
- [ ] В Git создан ровно один коммит — отчёт и инвентаризация; резервные бинарные файлы в коммит не входят.

## Проверки

**Среда и предпосылки:** локально, Git.
**Команды:** `git bundle create ... --all`; `git bundle verify ...`; `Get-FileHash` по манифесту; `git status --short` после коммита.
**Ожидаемый результат:** bundle валиден и содержит `HEAD`; отчёт закоммичен, резерв вне репозитория.
**Если проверка недоступна:** при сбое `bundle create` зафиксировать ошибку и не переходить к PUB-04 — публикация без резерва не выполняется.

## Ограничения

Резерв не заменяет push: копия на том же диске не является переносом. Это страховка от потери при сбое публикации.
