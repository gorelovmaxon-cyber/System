# FIX-07 — Индекс: надёжная постановка задач и возобновление in-flight после аварии

**What to build:** Сбой очереди индекса не скрывается и восстанавливается: повтор persisted-события и команда reconcile создают недостающие задачи; причина сбоя видна; оставшиеся после аварии in-flight задачи безопасно возобновляются и не блокируют run; состояние между журналами восстанавливается на каждой границе, включая полную потерю производного журнала.
**Requirement IDs:** SC-10 (R08), дефекты F05, F06, G04, G18.
**Blocked by:** FIX-01 (idempotent-путь writer), FIX-06 (jsonl/appendDurable)
**Status:** awaiting-validation

## Контекст

Аудит 2026-09-09:
- **F05:** ошибка `queueIndex` проглатывается; повтор выходит по раннему idempotent-пути до постановки задачи → событие навсегда без задачи индекса. Сам факт сохранения при отказе индекса допустим; дефект — отсутствие надёжного восстановления и видимой причины.
- **F06:** `run()` обрабатывает только pending/failed; in-flight после аварии остаётся навсегда (`requeueFailed` их не трогает).

Общий аудит 2026-09-12:
- **G04:** `run()` брал `const now = Date.now()` один раз на проход и передавал его в захват; вторая задача в проходе получала аренду в прошлом (`expiredOnStart: true`, воспроизведено).
- **G18:** восстановление было только частичным — оно не покрывало «между журналами»: задача могла быть создана, но агрегат не записан; производственный журнал мог быть потерян целиком; предусмотренной операции `reconcile` не существовало. Требование — «одна проверяемая модель event/file revision/tasks/aggregate; восстанавливать missing tasks и несогласованные агрегаты, повтор после сбоя на каждой межжурнальной границе».

## Файлы для изменения

- `scripts/memory/writer.js` — на idempotent-пути: перед возвратом `queueIndex(eventId, previous.written_files)`; при ошибке — не бросать, записать `index_error` в журнал writer (видимая причина). При первичной записи ошибку `queueIndex` фиксировать в журнале, не глотать молча.
- `scripts/memory/indexer.js` — `reconcile()`: для каждого persisted-события из writerLog с непустым `written_files` восстановить задачи по ТЕКУЩИМ ревизиям файлов и привести агрегат к факту; CLI `--reconcile`; `run()`: аренда считается в момент захвата, осиротевшие in-flight (`lease_expires_at` истёк или отсутствует) обрабатываются, а после прохода выполняется пересборка агрегатов.
- `scripts/memory/doctor.js` — (опционально) проверка «есть persisted-события без задач индекса» с инструкцией `indexer.js --reconcile`.
- `scripts/memory/tests/fix-07.test.js` — новый регрессионный тест.

## Входные/выходные данные

`reconcile()` → `{events, created, aggregates, errors}`: сколько событий рассмотрено, сколько задач создано, у скольких событий агрегат изменился, какие записи агрегата не удались. `run()` → массив per-task результатов (форма не меняется). Журнал writer: `index_error` — последняя причина сбоя постановки.

## Алгоритм (шаг за шагом)

1. Writer idempotent-путь: `try queueIndex(eventId, files)`; при ошибке — `writerLog.append({...previous, hash, indexed:false, index_error: message})`; результат функции не меняет — запись уже persisted.
2. Writer первичный путь: `catch` у `queueIndex` → `writerLog.append({...result-поля, indexed:false, index_error: message})` вместо пустого `catch`.
3. Indexer `run()`: `candidates` — все задачи, кроме `indexed` (отбор без времени). Пригодность решает `eligible()` внутри транзакции захвата по времени захвата (G04); аренда покрывает `timeout_ms` по построению (`leaseFor`), поэтому незавершённый запрос не может пережить аренду. После прохода — `refreshAggregates()`, ошибки видны в stderr.
4. Indexer `reconcile()`: по `writerLog.records()` со `status === 'persisted'` и непустым `written_files` → `queueIndex(event_id, written_files)` (дедуп по `task_id`, создаёт только отсутствующие ревизии) → агрегат к факту. CLI `--reconcile`.
5. Doctor: добавить проверку (по желанию) и инструкцию.

## Ограничения

Reindex по-прежнему требует реального механизма Khoj (SC-04, внешняя блокировка); здесь чинятся постановка/восстановление/статусы, не сам reindex. `reconcile` восстанавливает состояние по `written_files` и текущему содержимому файлов; если файл удалён и его ревизия стала `missing`, задача на эту ревизию будет создана и останется неподтверждённой — это честное состояние, а не ошибка.

## Блок 3: перепроверка пути index-задачи по факту (G06/G13) — 2026-09-12

**Проблемы.** G06 (P1): задача берётся из журнала и путь не перепроверяется — запись журнала могла быть восстановлена или изменена вручную (`file: '../../outside.md'`), и такой путь передавался адаптеру, то есть за пределы корня памяти. G13 (P2): законный файл мог оказаться за каталогом, переименованным и заменённым junction между постановкой задачи и прогоном; чтение уходило наружу, а задача завершалась `indexed`.

**Что изменено в `scripts/memory/indexer.js`:** в `reindex` путь задачи перепроверяется по факту перед обращением к адаптеру — `assertSafePath(memory_root, absolute, 'indexer file')`; непрошедший путь даёт задаче `failed` с причиной `indexer file crosses a symbolic link or junction` и до адаптера не доходит. `currentRevision(root, file)` теперь оборачивает `fileRevision` в `assertSafePath` и возвращает `null` при отказе, поэтому нечитаемый/уведённый за корень путь честно **не подтверждает** актуальность и не может удержать агрегат `indexed`.
