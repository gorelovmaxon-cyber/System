## Входные/выходные данные

Вход: локальный `master` и проверенный bundle. Выход: `origin/master == HEAD`, отчёт с фактическими SHA и результатами проверок.

## Алгоритм (шаг за шагом)

1. Повторная проверка перед публикацией:
   `git status --short --untracked-files=all`, `git log --oneline origin/master..HEAD`,
   `git ls-remote origin refs/heads/master`, поиск секретов в `git diff origin/master..HEAD`.
   Если remote ушёл вперёд — остановиться и сообщить, не делать force.
2. `git push origin master`. Не использовать `--force` и `--force-with-lease`.
3. Сверить: `git ls-remote origin refs/heads/master` должно совпасть с `git rev-parse HEAD`.
4. Свежий клон в отдельный каталог вне репозитория: `git clone <remote> <TEMP-путь>`,
   затем `git log -1 --oneline` (должен совпасть) и `git status --short` (должно быть пусто).
5. Прогон на клоне: `node --test scripts/memory/tests/*.test.js` → ожидается 152/152, exit 0.
   Если набор падает на клоне, а на рабочей копии проходит — это различие сред; зафиксировать
   факт и причину, не переписывая результат как успех.
6. Записать отчёт и закоммитить его, затем **опубликовать и этот коммит** (`git push origin master`)
   — иначе отчёт останется локальным.

## Критерии приёмки

- [ ] `git ls-remote origin refs/heads/master` совпадает с `git rev-parse HEAD` на момент завершения.
- [ ] Свежий клон содержит тот же `HEAD`; рабочее дерево клона чистое.
- [ ] Тесты на клоне прогнаны; результат записан как есть (число, exit code, дата).
- [ ] Отчёт опубликован, а не оставлен локально.
- [ ] В отчёте явно сказано: публикация не означает READY; live-интеграции не проверялись.
