## 5. Безопасный push и проверка содержимого на GitHub

После локальной копии и коммита выполни `git fetch origin`, сравни `HEAD` и актуальный `origin/master`.

- Если `origin/master` — предок HEAD: обычный `git push origin master` из подтверждённой ветки master.
- Если remote уже содержит HEAD: проверь, не появились ли там новые нужные коммиты, и согласуй локальное дерево обычным fast-forward при чистом рабочем дереве.
- Если ветки разошлись: сохрани обе истории обычным merge, разреши конфликты по содержимому с сохранением правок обоих ПК, проверь результат; не force push и не сбрасывай одну сторону. Не выдумывай разрешение смыслового конфликта, если оно требует неизвестного решения пользователя. Пока оно не разрешено, локальная резервная копия и отдельная опубликованная ветка снимка сохранят работу, но master-перенос ещё не завершён.
- Если текущая ветка оказалась другой: сначала выясни её связь с master; не публикуй случайную ветку под именем master.

После push:

```powershell
git rev-parse HEAD
git ls-remote origin refs/heads/master
git status --short
```

SHA локального HEAD и remote master должны совпадать для объявленного снимка. Создай **новый уникальный клон** GitHub вне рабочей копии и проверь:

- HEAD совпадает с опубликованным SHA, `ffe215a` и все сегодняшние коммиты входят в его историю.
- Есть новый HANDOFF, все 10 перечисленных ранее untracked-файлов, тикеты, код и тесты.
- Git tree совпадает с публиковавшимся деревом; ключевые документы и evidence имеют те же SHA-256.
- В клоне нет незакоммиченных изменений. Для этой проверки не нужны bootstrap, сервисы или миграция памяти.
