# SYSTEM-SYNC-01 — актуализировать локальную System2 и GitHub

**What to build:** Опубликовать накопленные локальные записи памяти и документы
в согласованном репозитории System, отличив историю от действующих инструкций.
**Requirement IDs:** S01–S04.
**Blocked by:** none.
**Status:** verified — документальный пакет проверен исполнителем;
независимая приёмка не заявляется, SHA публикации определяется по Git.

## Основание и план

Пользователь после сравнения локальной System2 с GitHub поручил «актуализируй».
На 2026-11-01 исходные HEAD и origin/master — `a18fa6e`:
четыре изменённых файла и пять новых; неопубликованных коммитов нет.
Основной путь — проверить весь пакет, сохранить исходную память, обозначить
устаревшие передачи и предложения, проверить и опубликовать обычным push.
Если remote изменился, сначала сверить входящие изменения без сброса местных файлов.

## Требования и проверка

- S01: сохранить все 18 ранее локальных событий памяти без изменения payload;
  резерв девяти исходных файлов находится в игнорируемой `.local/system-sync-20261101`.
- S02: включить проверенные документы/receipts, обозначить исторические статусы
  и завершить обработку исторического pending-наблюдения без повышения достоверности.
- S03: проверить состав, отсутствие credential-кандидатов, diff и `npm.cmd run check`;
  код и рабочее поведение не меняются, полный suite без нового основания не нужен.
- S04: scoped-коммит и обычный push; подтвердить равенство HEAD и live master.

## Границы

Не изменять код, сайты, VPS, конфиги ПК, секреты, стандарт ОК и локальные адаптеры.
Не внедрять предложения Astra/Autopilot, не запускать внешние интеграции.
Независимые статусы CORE-FIX/PROFILE не повышать; самостоятельная проверка
этого документального пакета не считается независимой приёмкой.

Итоговые факты и проверки — в [RESULT.md](RESULT.md).
