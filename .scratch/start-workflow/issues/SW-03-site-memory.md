# SW-03 — рекомендации по прошлым сайтам, Khoj и локальный fallback

**What to build:** До spec агент извлекает подходящий прошлый опыт с источниками;
новый сайт получает общие уроки, но не чужие секреты/требования.
**Requirement IDs:** SW-R3
**Blocked by:** SW-02
**Status:** planned
**Перед началом работы:** E:\\SystemTheBest\\System, профиль core.

## Контекст и план
Читать scripts/memory/search.js, resolve-paths.js, indexer.js,
.claude/memory/README.md, docs/khoj-setup.md, docs/routes/sites-workflow.md.
Проектный поиск сейчас ограничен scope user/текущего проекта. Не ослаблять
эту изоляцию ради «всей памяти» и не использовать неограниченный поиск как скрытый обход.
Основной путь: общие переиспользуемые уроки + явно разрешённые источники прошлых сайтов.
Сначала инвентаризация уже сохранённых источников/metadata, без массового чтения переписок.
Если общих уроков нет — прямо сообщить, предложить конкретные источники для извлечения.
Не переклассифицировать всё старое содержимое как user.

## Изменения и границы
Согласовать start/sites с retrieval-контрактом; при необходимости минимальные
расширения существующего поиска и тестов. Определить явный безопасный способ
доступа к разрешённому межпроектному опыту, не новый поисковик.
Khoj на этом ПК: сначала фактическое состояние существующей установки,
конфигурации и индекса. Использовать существующий runtime; не переустанавливать
и не тянуть модели повторно без доказанной необходимости.
Живой Khoj обязателен как отдельное доказательство пользовательского запроса;
его отсутствие не останавливает реализацию локального пути, но оставляет
Khoj-сценарий awaiting-validation. Docker/WSL не требуются и не трогать.
Постоянный автозапуск/планировщик не добавлять без решения; описать запуск и readiness.

## Критерии
- [ ] Для нового сайта найдены релевантные общие/разрешённые уроки с source,
      scope, status и датой, если она есть; отсутствующие metadata не выдуманы.
- [ ] Рекомендация ссылается на найденное доказательство либо помечена новым предложением.
- [ ] Чужой project scope и источник с секретом не попадают в автоматический контекст.
- [ ] U+FFFD/неподтверждённые старые записи не становятся подтверждёнными рекомендациями.
- [ ] Положительный запрос проходит реально через Khoj и актуальный индекс;
      результат fallback не засчитывается как успех Khoj.
- [ ] При выключенном Khoj штатный search.js находит известную запись локально;
      пустая выдача/неизвестный ID обрабатываются честно.
- [ ] Нет обещания «все прошлые сайты учтены», если они не сохранены/не разрешены.

## Проверки и окончание
Fixtures: общая рекомендация, разрешённый источник, закрытый чужой проект,
устаревшая/повреждённая запись. Не загрязнять каноническую память.
Проверки retrieval/scoping по риску; менять изоляцию только с её регрессиями.
Живой положительный Khoj + контролируемый fallback без остановки чужих процессов.
Команды, режим и результаты в RESULT.md; scoped-коммит, awaiting-review
или awaiting-validation для конкретного недоступного live-сценария.
