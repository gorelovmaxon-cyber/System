# SW-01 — минимальное подключение проекта и реальная команда start

**What to build:** Подключить существующую/новую папку к одной общей System2;
после однократного setup команда start доступна в выбранном пользовательском клиенте.
**Requirement IDs:** SW-R1, SW-R5
**Blocked by:** none
**Status:** ready-for-agent
**Перед началом работы:** открой E:\\SystemTheBest\\System, проверь root, дерево и remote.

## Контекст и план
Прочитать ../README.md, scripts/memory/init-project.js, resolve-paths.js,
project-id.js, config/system.example.json и навыки start/project-memory-init.
Сначала установить, в каком клиенте пользователь реально запускает start.
Подтвердить его механизм project skills/команд по фактической конфигурации и
официальной документации при необходимости. Не обещать одну slash-схему для всех клиентов.
Основной путь: небольшой клиентский адаптер → канонические инструкции общей System.
Нет безопасной ссылки/подгрузки — предложить минимальный управляемый loader,
а не копию всей системы. Нет доступа к клиенту — подготовить адаптер, live оставить открытым.

## Файлы и вход/выход
Менять по необходимости init-project.js, project-id.js, resolve-paths.js,
.claude/skills/project-memory-init/SKILL.md, docs/system-operations.md;
новый клиентский шаблон и целевые тесты — выбрать рядом с существующими.
Вход: абсолютные корни проекта/System, стабильный ID, клиент.
Выход: минимальная точка входа, локальная привязка, сохранённые CLAUDE/HANDOFF.
Новый ID должен оставаться тем же при переходе на другой ПК; документировать
разделение переносимого registry и ignored local_paths, не публиковать секреты/абсолютные пути.
Локально зарегистрированный ID не обещать синхронизированным через Git.

## Критерии
- [ ] В изолированной папке вне System start обнаруживается/вызывается в реальном клиенте.
- [ ] Новый проект и уже известный ID без local_paths подключаются однозначно.
- [ ] Чужие CLAUDE/HANDOFF/AGENTS и hooks сохранены; повторный setup не дублирует секции.
- [ ] Ошибочная папка, конфликт ID/пути, отсутствие System дают конкретное действие,
      не создают вторую память и не перезаписывают проект.
- [ ] Машинный путь настраивается локально; перенос проекта не требует копии SystemTheBest.
- [ ] При запуске без подключения пользователь получает честную инструкцию setup:
      средствами клиента, если неизвестную slash-команду агент не получает.
- [ ] Созданы регрессии на пути с пробелами/кириллицей и запуск вне root.

## Проверки и окончание
Целевые тесты подключения по существующему node:test; точные новые команды
зафиксировать в RESULT.md. Изолированные Git config и fixtures вне рабочей памяти.
Отдельно live-вызов в клиенте, не подмена чтением SKILL.md в терминале.
Один scoped-коммит, evidence в общем RESULT.md, awaiting-review.
Никаких копий runtime/backups, массовой установки глобальных skills и запуска Docker.
