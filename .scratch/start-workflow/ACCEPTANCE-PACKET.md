## Оставшаяся проверка планирующего прохода

Целевой интерфейс выпуска — чат GPT с доступом к файлам и инструментам System2;
Claude Code с API 402 выше — исторический результат, не обязательный клиент.
При отдельной живой проверке предоставить агенту доступ к изолированному demo-проекту
и System2, явно попросить прочитать правила и HANDOFF и обратиться:

```text
Старт: Сделай небольшой демонстрационный сайт мороженого. Это изолированный fixture SW-05: не реализуй сайт, не запускай исполнителя и не сохраняй демо-данные в каноническую память System. Найди разрешённый опыт с источниками; покажи рекомендации отдельно от фактов; задай существенные вопросы по одному; после моих явных ответов предложи spec на согласование. Только после моего явного согласия создай локальные brief/spec/тикеты и HANDOFF, затем остановись перед передачей исполнителю.
```

«Старт:» — обращение к агенту, не зарегистрированная slash-команда и не
автоматическая загрузка правил в любом клиенте. Уже проверенные передачу, ICE-01,
изолированное сохранение, отсутствие дублей и продолжение в новой сессии не
повторять ради этой документальной правки; ниже сохранён условный шаблон
исторического плана, не поручение запускать ещё один цикл.

Если агент спросит о формате, **пользователь может выбрать** фиктивный ответ
«витрина с меню, адресом и формой заявки; без оплаты и публикации». Это лишь
предложение для демо, не уже полученный ответ. Другие вопросы и согласование
spec должны пройти реально. Зафиксировать вывод клиента с источниками (`scope`,
`status`, источник и дата, если она есть), путь к созданной spec, тикетам,
HANDOFF и факт остановки. `ok:false`/`fallback:local` не считать живым Khoj;
старый G11 не считать пройденным. Нельзя переносить demo fixture в общую память.

## Точный текст передачи *после* согласования spec и создания тикета

Пользователь открывает отдельный чат Sonnet/Sol в указанном demo-каталоге и
передаёт следующее сообщение **только если** в spec согласованы витрина, меню
и отсутствие публикации, а локальный тикет на меню создан планирующим агентом.
Вставить фактические абсолютные пути к spec/тикету вместо этого условного
текста нельзя до их появления; в новом чате исполнитель сам находит файлы:

```text
Открой проект C:\Users\gorel\AppData\Local\Temp\sw05-icecream-demo-20260923. Прочитай AGENTS.md, CLAUDE.md, HANDOFF.md и локальные SPEC.md и тикеты из этапа SW-05 (их фактические пути возьми из HANDOFF). Проверь git status и согласованность spec с тикетом. Выполни только один согласованный малый тикет «Статическое меню мороженого»: локальный статический HTML с заголовком и тремя позициями меню, их названиями и ценами из согласованной spec; если названия или цены не согласованы, остановись и спроси, не выдумывай их. Не делай форму заказа, оплату, публикацию и остальной сайт. Проверь отображение меню локально и отсутствие ссылок на отсутствующие ассеты; выполни указанные в тикете проверки. Сохрани результат и HANDOFF на контрольной точке, а полезное подтверждённое знание — только если оно появилось, с evidence/source/scope и стабильным event_id через штатный writer (fixture не записывать в каноническую память); проверь чтение/поиск и отсутствие дубля при повторе. Зафиксируй проверки и scoped-коммит только своих файлов, остановись для независимой приёмки. Не ставь себе done/READY; не запускай следующего агента.
```

Этот текст — **условный шаблон передачи**, а не поручение начать исполнение
сейчас. Если реальная spec не содержит меню/цен или тикет отличается, сначала
согласовать тикет с пользователем; не подменять результат обращения к агенту шаблоном.
Для demo-памяти использовать только изолированную тестовую память и её
конфигурацию; если такой изоляции нет, не вызывать `save.js` для fixture,
отметить checkpoint `awaiting-validation`.
