## SW-05 — пакет проверки и точное ограничение

Существующий [runbook](../../docs/system-operations.md#работа-с-одной-задачей-через-start) дополнен однократным setup, вызовом `/start`, порядком spec/тикетов, передачей Sonnet/Sol, checkpoint, новым ПК и восстановлением после аварии. Для независимого сквозного прогона используйте изолированный demo проект, стартовый запрос `/start Сделай сайт мороженого`, а на первый существенный вопрос фиктивный ответ: «витрина с меню, адресом и формой заявки; без оплаты и публикации». Ответ является fixture, не решением пользователя по реальному сайту. После доступного API клиент должен сам сохранить spec, тикеты и HANDOFF и остановиться. Затем **пользователь** передаёт один малый тикет Sonnet/Sol и открывает новую сессию; отдельный приёмщик сверяет реализацию, сохранённое знание, отсутствие дубля и продолжение без старого чата. Ни один из этих пунктов не засчитан из наличия инструкций.

Недостающие действия: пользователь восстанавливает доступ/лимит **существующего** Claude Code API; затем живой маршрут до согласованных с пользователем файлов spec/тикетов; пользователь передаёт пакет исполнителю и открывает новый сеанс; независимый приёмщик оценивает SW-R1…SW-R5. Предлагаемый fixture-ответ и малый тикет в [пакете](ACCEPTANCE-PACKET.md) не считаются ответом/согласием пользователя. До этого SW-02/SW-05 `awaiting-validation`, весь пользовательский цикл не принят. Стоимость полного блока unknown: отдельные CLI ответы содержали суммы, но полный успешный маршрут не состоялся; экономия времени/денег не оценивалась. Docker/AP, Figma, новые установки, restore L06/L07, Git round-trip и копия SystemTheBest в demo не выполнялись.
