# START-ROUTING-01 — явный выбор команды и разделение ролей

Статус: ready-for-agent. Подготовлено планировщиком 2026-10-18.
Исполнитель и независимый приёмщик выбираются пользователем; автоматического запуска нет.

## Основание и результат

Прямое решение пользователя в беседе 2026-10-18: start должен определить, что делать,
остановиться и рекомендовать команду; site-build следует autopilot, добавляя правила
создания сайтов; планировщик и рабочий остаются разными ролями.
Это заменяет прежнее правило «один start проходит разрешённые фазы».

Наблюдение: при запросе анализа ТЗ, гайдлайна и макета агент прочитал System2,
но перешёл от маршрутизации к обещанию генерации визуального макета.
Генерация не была запущена. Проблема не в недоступности общей папки:
CLAUDE.md проекта явно указывает канонический корень. Текущий проект system-of-site
и его старый HANDOFF при этом не являются проектом клиентского сайта.

## Разрешённый блок

Согласованно изменить инструкции маршрутизации и роли, примеры и затронутые проверки.
Не создавать сайт, макет, изображение; не регистрировать новый клиентский проект;
не менять глобальные настройки клиента и не устанавливать навыки.

## Контракт

1. `/start <задача>` выполняет только вход и маршрутизацию: читает обязательные
   инструкции, актуальную передачу и относящийся контекст, определяет проект,
   роль, этап и объём. Материалы изучает в объёме, достаточном для выбора маршрута.
2. В конце start кратко сообщает: понимание задачи, корень проекта и System2,
   роль, сохранённый этап, рекомендованную команду с причиной и ожидаемым результатом.
   Затем завершает ответ. Не запускает автоматически grill/spec/tickets/генерацию/код,
   не выполняет даже мелкую продуктовую правку под видом start.
   Фиксация решения и указателя продолжения допустима, полноценное планирование —
   после выбора маршрута. Не выдаёт текстовый вызов за зарегистрированную slash-команду.
3. После явного выбора пользователем `/site-build` (или текстового эквивалента)
   работает autopilot в назначенной роли. site-build — дополнение требованиями
   стандарта сайтов, а не второй самостоятельный процесс и не повторное интервью.
   Пользователь не обязан отдельно запускать каждую внутреннюю фазу autopilot.
4. Планировщик анализирует, уточняет, согласовывает spec, готовит тикеты и передачу.
   Реализацию выполняет отдельный выбранный пользователем исполнитель.
   Реализация включает код, визуальные макеты, ImageGen, Figma и конечные ассеты;
   название «эскиз» или «прототип» не позволяет планировщику обойти разделение.
   Текстовое описание композиции и требований допустимо как планирование.
5. Роль наследуется из явного поручения/передачи; команда и выбор формата результата
   не меняют её. Если роль неизвестна — указать это, не назначать себя исполнителем.
   Явное последующее изменение роли пользователем имеет приоритет.
6. Повторный start сохраняет этап и роль, рекомендует команду продолжения и тоже
   останавливается. Прямой запуск исполнителя по согласованному тикету не требует
   дополнительного start или повторного интервью.
7. Проверять соответствие задачи текущему проекту. При несовпадении сообщать это,
   не использовать чужой HANDOFF как состояние новой задачи и не сохранять клиентские
   решения в чужую проектную память. Доступная общая System2 продолжает действовать;
   новая папка сама по себе не обеспечивает соблюдения инструкций.

## Проверка и приёмка

Проверить согласованность действующих инструкций и локальных ссылок. Одного поиска
ключевых слов недостаточно для заявления о поведении агента. Сценарии:

| Вход | Ожидаемый результат |
|---|---|
| start + ТЗ/гайдлайн/макет, «только главный экран» | Понимание задачи, роль, рекомендация site-build, остановка без генерации и spec |
| Ответ «визуальный макет» на вопрос о формате | Фиксация формата; не назначение исполнителя и не согласование композиции |
| Явный site-build, роль планировщика | Фазы планирования autopilot с правилами сайта, пакет передачи; без макета/кода |
| Повторный start при готовых тикетах исполнителя | Сохранённая роль, рекомендация продолжения, остановка; без нового grill |
| Прямое поручение исполнителю выполнить согласованный тикет | Исполнение разрешённого блока без принудительного возврата в start |
| Новый клиентский сайт открыт в папке другого продукта | Несовпадение указано, общие правила прочитаны, чужие этапы и память не присвоены |
| start + мелкая правка | Рекомендация короткого маршрута и остановка |

Для поведенческих проверок требуется отдельная доступная сессия выбранного агента;
не запускать субагентов без разрешения. Если её нет, отметить «не проверено» и
передать независимому приёмщику; статическое чтение не выдавать за живой прогон.
Существующие тесты адаптеров запускать при их изменении; не расширять работу
до полного аудита System2. Новые автоматические тесты — только для реального
изменения поведения генератора, не для проверки наличия фраз в Markdown.
