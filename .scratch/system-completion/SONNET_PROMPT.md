# Задание Sonnet: подготовить полный пакет тикетов SystemQwen v1

Открой проект E:/System2. Ты автор тикетов, реализацию затем делает GPT Luna,
приёмку — планировщик/Opus. Подготовь весь пакет за одну сессию нарезки.

Прочитай:

1. [SPEC.md](SPEC.md) — согласованная архитектура, контракты и R01–R13.
2. [PLAN.md](PLAN.md) — SC-01–SC-18, порядок, границы, готовность.
3. [TICKET_TEMPLATE.md](../../TICKET_TEMPLATE.md) — актуальный обязательный формат.
4. Указанные в конкретном тикете существующие файлы, чтобы задания соответствовали репозиторию.

Шаблон уже изменён (SC-00). Старые инструкции требовать полный код и фиксированные
200–300 строк отменены пользователем. Сохрани разделы, ссылки, ограничения, алгоритм,
контракты и подробные сценарии проверки. Полный код пишет исполнитель; короткие примеры
нужны только для снятия неоднозначности. Не создавай серверы/скрипты/compose в этом шаге.

Создай issues/SC-01-*.md … SC-18-*.md и issues/SUMMARY.md рядом с этим файлом.
В каждом тикете: требование → нужное поведение → точные файлы → проверка → доказательство.
В интеграционных тикетах обязательно укажи установку, настройку, запуск и живую проверку;
старое ограничение T5–T9 «только документы» не переносится на новые сервисные работы.
Проверку среды и актуальных релизов запланируй в SC-01. Не копируй неподтверждённые
API/переменные из старых тикетов или прошлого ревью как установленный факт.

Нарезка должна включать весь план, даже если исполнение отдельных интеграционных
проверок позднее потребует Docker, ключей или второго ПК. Перечисли это в SUMMARY;
не считай отсутствующий доступ полученным и не заменяй живую проверку моками.

Проверь ссылки, существующие пути, граф зависимостей, соответствие SPEC и покрытие
R01–R13. Старые T1–T9 относятся к разным этапам: используй новый namespace SC.
SC-01 ready-for-agent, остальные planned. Не помечай их готовыми по факту создания текста.

После создания сообщи путь к SUMMARY, количество тикетов, порядок исполнения и реальные
внешние prerequisites. Остановись после нарезки. Не выполняй тикеты и не публикуй изменения.

## Уточнения, принятые после нарезки (2026-09-08, перед исполнением)

Эти уточнения внесены в SPEC/PLAN и в уже созданные тикеты; пакет перепроверен.

1. Приоритет локальной системы: рабочая система — это локальные инструкции, память
   (включая незакоммиченные правки), настройки, сервисы и данные ПК. Git хранит
   переносимую (отслеживаемую) часть и не заменяет всю систему.
2. До миграции памяти/настроек — резервная копия текущего локального состояния, включая
   нужные untracked/gitignored-файлы; секреты — отдельно и защищённо. Git-история их не восстановит.
3. Проверки фиксируют фактическое состояние (например, `core.hooksPath`, запущенные
   сервисы) и сохраняют существующие настройки; ожидаемые результаты в отчёты не подставляются.
4. Секреты — не в Git и не в отчётах/выводе; защищённая локальная настройка допустима.
   Формат/механизм конфигурации сервисов (например, Khoj) выбирается по поддерживаемому
   способу выбранной версии, а не предписывается заранее.
