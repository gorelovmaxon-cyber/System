# SystemQwen v1 — SUMMARY пакета тикетов SC-01…SC-18

Пакет подготовлен автором тикетов (Sonnet) по [SPEC.md](../SPEC.md) и [PLAN.md](../PLAN.md) для исполнителя (GPT Luna через VS Code). После нарезки работа остановлена: тикеты не выполнялись, сервисы не запускались, изменения не публиковались.

- Каталог тикетов: `.scratch/system-completion/issues/` (этот файл рядом).
- Формат: [TICKET_TEMPLATE.md](../../../TICKET_TEMPLATE.md) (SC-00; полный код не обязателен).
- Статусы после исполнения: **SC-01/02/03/07/08/11/12/13/14/15 — awaiting-review**, **SC-04/06/09/10 — blocked по внешним предпосылкам**, **SC-05 — awaiting-validation**; SC-16 выполняет механизм evidence. «Тикет создан» ≠ «выполнено».

## Ревизия после нарезки (2026-09-08, перед исполнением)

По ревью внесены четыре поправки в SPEC.md, PLAN.md, SONNET_PROMPT.md и тикеты пакета; объём системы не расширялся. Пакет перепроверен после правок:

1. **Приоритет локальной системы** — работающая система это локальные инструкции, память (включая незакоммиченные правки), настройки, сервисы и данные ПК; Git хранит переносимую часть и не заменяет всю систему (SPEC, решения 1/5; контексты SC-02, SC-13).
2. **Резервная копия до изменений** — перед миграцией памяти/настроек копируется текущее локальное состояние, включая нужные untracked/gitignored-файлы; секреты — отдельно и защищённо (шаг 0 в алгоритмах SC-02, SC-03; критерии приёмки).
3. **Проверки фиксируют факт, а не ожидание** — SC-01 фиксирует фактическое `core.hooksPath`/remote/ветку/состояние сервисов без сброса настроек и подгонки; SC-11 перепроверяет состояние на момент исполнения и подтверждает отсутствие дублирующего hook тестовым коммитом.
4. **Технические противоречия сняты** — формат/механизм конфигурации сервисов (Khoj и др.) выбирается по документированному способу выбранного релиза (SC-01/ENVIRONMENT.md), а не предписывается заранее; секреты — не в Git/отчётах/индексе, но защищённая локальная настройка (gitignored, ограниченный доступ) допустима и для сервисов необходима. Ссылки из `issues/` на SPEC/PLAN приведены к `../`.

Исполнены scoped-коммиты по доступным тикетам; live Khoj/Activepieces/Figma/второй ПК
не выдаются за проверенные. Push не выполнялся.

## Внешние предпосылки и ручные шаги (живые проверки)

Живые проверки ряда работ требуют доступа и/или ручной настройки; отсутствие доступа фиксируется как pending/awaiting-validation в соответствующем тикете и в RELEASE-REPORT (SC-18). Моки живую приёмку не заменяют.

- **Версии/установки по официальным источникам** — проверяет и фиксирует SC-01 в `.scratch/system-completion/ENVIRONMENT.md` (Node, Git Bash, Docker/Compose, Khoj, Activepieces, postgres/redis). Не переносить непроверенные версии/API из старых тикетов T5–T9 и прошлых ревью.
- **Docker Desktop** — нужен для SC-06/SC-09 (Activepieces), возможно для Khoj. Не проверен до исполнения.
- **Сетевая связность Windows/Docker → host** — вариант фиксируется и проверяется в SC-06 до сборки flow (SC-09).
- **API-ключ AI-провайдера** (AI-подключение в Activepieces) — нужен для живого AI-теста SC-09. Без ключа flow собирается, а позитивный AI-сценарий остаётся awaiting-validation.
- **Figma API-ключ и доступ к макету** — нужны для живой проверки SC-14; без них — awaiting-validation (fixture- и MCP-проверки выполняются локально).
- **Второй ПК** — живая проверка SC-13; без него изолированный клон проверяется всегда, реальный ПК — awaiting-validation.
- **Установка зависимостей/запуск сервисов** — часть реализации (старое ограничение «только документы, не устанавливать» из T5–T9 отменено).
