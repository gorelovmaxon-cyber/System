# SC-14 — Исправленная Figma-интеграция (MCP-сервер извлечения значений)

**What to build:** Figma-сервер, корректно извлекающий поддерживаемые значения (цвета, типографика, отступы, радиусы с происхождением и без потери одноимённых узлов) и предоставляющий проверяемый MCP-интерфейс для реального MCP-клиента; поддерживаемое подмножество и ограничения задокументированы.
**Requirement IDs:** R10
**Blocked by:** SC-01
**Status:** planned

## Контекст

SPEC R10: «Figma корректно извлекает поддерживаемые значения и предоставляет проверяемый MCP/REST интерфейс». Текущий черновик: Express + ручной JSON-RPC эндпоинт `/mcp` без официального MCP SDK, без SSE/stdio-транспорта, README называет его «MCP Streamable HTTP-compatible», но это не проверено реальным MCP-клиентом; сервер нигде не зарегистрирован. Ограничения извлечения: один `GET /v1/files/:key` на весь файл, одноимённые узлы не различаются, opacity/fills-варианты и радиусы с разными значениями по углам обрабатываются частично, происхождение (путь/узел) не сохраняется. «REST endpoint сам по себе не MCP» — нужен либо официальный MCP SDK/проверенный транспорт, либо доказательство соответствия выбранному протоколу (SPEС требует проверяемый MCP).

## Входные/выходные данные

**Tool:** `figma_get_design_tokens` — вход: `{ fileUrl | fileKey, nodeId? (опционально), scope?: "colors"|"typography"|"spacing"|"radii"|"all" }`.
**Выход:** массив значений с происхождением, например:
```json
{ "colors": [ { "name": "primary/500", "value": "#FF0000",
                "node": "…/frame/button", "type": "style|fill" } ],
  "typography": [ { "name": "H1", "fontFamily": "Inter", "fontSize": 32,
                    "fontWeight": 600, "lineHeight": 40, "node": "…" } ],
  "spacing": [ { "name": "card", "padding": { "top":16,"right":16,"bottom":16,"left":16 },
                 "gap": 8, "node": "…" } ],
  "radii": [ { "name": "button", "radius": { "tl":8,"tr":8,"br":0,"bl":0 }, "node": "…" } ] }
```
Одноимённые узлы не теряются: name дополняется путём/индексом или возвращаются отдельными записями с одинаковым name и разными node. `nodeId` в URL/входе обрабатывается явно (404/не найдено — ошибка с текстом, а не пустой результат). Figma API-ошибки (401/403/429/неверный key) — понятные сообщения.

## Алгоритм (шаг за шагом)

1. **Выбрать транспорт/SDK** по официальной документации MCP и проверить совместимость с тем, как сервер будет вызываться (для Claude Code/агента — stdio через `node server.js`, либо streamable HTTP). Зафиксировать выбор и дату в README. Предпочтение — официальному SDK, а не ручному JSON-RPC, если окружение позволяет установить зависимости.
2. **Реализовать lib/extract.js** (чистая функция): обход узлов; (а) colors — из styles (FILL) и из fills узлов (solid), с учётом opacity (если opacity<1 — значение с альфой или пометка), HEX; (б) typography — по text-стилям/узлам с text (fontFamily/size/weight/lineHeight); (в) spacing — padding по сторонам (не только равные), gap при наличии auto-layout; (г) radii — по углам (cornerRadius scalar или радиусы по углам); (д) происхождение — путь узла; (е) одноимённые узлы — не схлопывать. Неподдерживаемые случаи (градиенты, изображения-заливки) — пропускать с пометкой/в поле ignored.
3. **Реализовать server.js** поверх SDK: tools/list, tools/call figma_get_design_tokens; получение файла через Figma REST (`GET /v1/files/:key` с `X-Figma-Token`); при nodeId — соответствующий запрос/фильтрация; обработка ошибок API и node-id; таймауты. REST-only эндпоинт, если остаётся, — только как вспомогательный, MCP-интерфейс основной и проверяемый.
4. **Создать fixture и тесты**: fixture с ожидаемыми значениями (одноимённые узлы, разные радиусы, opacity, padding, вложенность) → тесты extract; тест реального MCP-клиента: поднять сервер, client.initialize → tools/list содержит tool → tools/call возвращает структуру выше.
5. **Зарегистрировать/задокументировать подключение**: README: как добавить сервер в MCP-клиент (для Claude Code — `claude mcp add figma -- node …` или конфиг в .mcp.json; пример в .mcp.example.json) — без привязки к секретам.
6. **Живая проверка** (если есть доступ к макету и ключу): вызвать tool на реальном файле, сверить несколько значений с макетом; нет доступа — awaiting-validation.
7. **Обновить .gitignore** (`.env`, `node_modules/`), README.
8. **Проверить** сценариями ниже.

## Проверки

**Среда и предпосылки:** локально, Node; установка зависимостей сервера (`npm install`) — часть работы. Внешняя предпосылка — Figma API-ключ и доступ к макету.
**Команды:** `npm test` (fixture+extract), `node test/mcp-client.test.js` (клиент против сервера), запуск сервера; команды создаются в этом тикете.
**Ожидаемый результат:** тесты зелёные; MCP-клиент получает корректный ответ.
**Если проверка недоступна:** нет ключа/макета → живая Figma-проверка awaiting-validation; fixture- и MCP-проверки обязательны и выполняются локально (это не «мок вместо живой приёмки», а проверка контракта извлечения и транспорта).
