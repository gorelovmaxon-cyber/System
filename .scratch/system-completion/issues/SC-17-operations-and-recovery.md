## Входные/выходные данные

**Backup-набор:** (а) память — git-репозиторий System2 (remote + локальные копии); (б) конфиги/реестр — в Git (example) + локальные (перечень); (в) flow-конфиг Activepieces — в `services/activepieces/flows/` (Git) + БД flow (экспорт/volume); (г) неотправленная очередь `.local/` — копия каталога; (д) локальные секреты — отдельное защищённое хранилище (менеджер паролей/файл вне репозитория) с описанием, как восстанавливать в .env/окружение.
**Восстановление:** порядок шагов + проверочные команды (doctor OK, health сервисов, поиск находит запись, flow обрабатывает событие).

## Проверки

**Среда и предпосылки:** локально; сервисы останавливаются/запускаются в рамках проверки; отдельная копия — временная папка.
**Команды:** по runbook (создать в этом тикете как текст; каждая команда существует в README сервисов/скриптах из предыдущих тикетов); backup/restore-команды.
**Ожидаемый результат:** runbook проходим; восстановление работает на копии; health/поиск/flow подтверждают.
**Если проверка недоступна:** живой откат версии сервиса или восстановление БД Activepieces, если экспорт недоступен на выбранной версии, — описать процедуру и пометить проверку; в отчёте — что проверено, что нет.

## Ограничения

- Не разворачивать удалённый сервер; remote-профиль — только текст плана.
- Backup реальных личных данных вне System2 (проекты клиентов) — не в скоупе; здесь система памяти/сервисов.
- Восстановление ключей — процедура для пользователя, документируется, но значения не хранятся.
