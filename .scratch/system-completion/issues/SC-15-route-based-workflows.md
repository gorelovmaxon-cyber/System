## Контекст

SPEC R11: «Разработка, сайты и маркетинг имеют разные маршруты с общей памятью; Gemini остаётся внешним источником». SC-15 в PLAN: один start/router; разработка — поведение и тесты; сайты — бриф, дизайн, визуальная проверка, формы и требуемая аналитика; маркетинг — цель, аудитория, источники, материалы и измерение. ## Входные/выходные данные

**Сигнатура выбора маршрута** (в start): примерные триггеры — «добавить/исправить/протестировать функцию» → dev; «лендинг/сайт клиента/дизайн макета» → sites; «привлечь/аудитория/рассылка/контент-план» → marketing; неоднозначно → уточняющий вопрос пользователю (grill), без угадывания.
**Общее ядро (все маршруты):** обязательные файлы проекта → retrieval → шаги маршрута; результат фиксируется в памяти (writer, SC-08) и/или HANDOFF.
**Выход маршрута:** конкретный проверяемый результат + что НЕ делается автоматически: публикация сайта, запуск рекламы, расход бюджета, создание SEO-статей и т.п. — только по явному решению пользователя (правило SC-15: публикация/расход не возникают из одного анализа).

## Алгоритм (шаг за шагом)

1. **Определить минимальные проверяемые маршруты** и записать их в route-доки: dev (поведение и тесты), sites (бриф → дизайн/структура → реализация → визуальная проверка → формы/аналитика по брифу), marketing (цель → аудитория → источники → материалы → измерение). Каждый маршрут: триггеры, шаги, критерии готовности, «что вне маршрута» (не навязывается).
2. **Написать три route-дока** с примерами применения и ссылками на релевантные скиллы/инструменты (для sites — опционально Figma-сервер SC-14; для marketing — внешние исследования как входные документы).
3. **Развить start-роутер**: этап «определить домен» → выбор маршрута (dev/sites/marketing) или уточнение у пользователя; во всех ветках вызвать общее ядро (обязательные файлы SC-12 → retrieval SC-05). Сложность: мелкая задача не гоняется через полный pipeline (например, быстрый фикс → короткий путь dev).
4. **Обновить docs/system-workflow.md**: раздел «Маршруты задач» (таблица выбора, правило «публикация/бюджет — только по явному решению»).
5. **Проверить** тремя примерными запросами: (а) «добавь валидацию формы в проект X» → dev + релевантная память; (б) «сделай лендинг для клиента N» → sites + бриф; (в) «привлеки подписчиков на тему Y» → marketing + источники; каждый: маршрут выбран, общее ядро выполнено, шаги соответствуют, ничего лишнего не запущено.

## Критерии приёмки

- [ ] Три примерных запроса выбирают правильные маршруты и находят релевантную память (поиск SC-05); неоднозначный запрос → уточняющий вопрос, а не произвольный выбор.
- [ ] Каждый маршрут начинается с обязательных файлов проекта (CLAUDE.md/HANDOFF) и retrieval; маршрут dev не тянет бриф сайта/маркетинга.
- [ ] Сложность соразмерна задаче: мелкий фикс не проходит полный маркетинговый pipeline; публикация/расход бюджета не запускаются из одного анализа (нет шага «опубликовать» без явного решения).
- [ ] Клиентские данные (сайты/маркетинг) не смешиваются с общей памятью другого проекта; scope проекта соблюдается.
- [ ] Gemini-исследование принимается как внешний документ с источником/датой; API-интеграция Gemini не появилась.
- [ ] route-доки существуют и связаны из start и system-workflow.md; R11 покрыт (маршруты с общей памятью).

## Проверки

**Среда и предпосылки:** локально; поиск (SC-05) и обязательные файлы (SC-12) доступны. Три проверочных запроса выполняются как сухой прогон маршрутов (без реального изменения проектов клиентов).
**Команды:** вызов start/скилла с примерным запросом; проверка выбранного маршрута и шагов по route-доку; `node scripts/memory/search.js` для проверки релевантной памяти (команда из SC-05).
**Ожидаемый результат:** корректный выбор маршрута; шаги соответствуют route-доку; не запущены непрошеные действия.
**Если проверка недоступна:** реальный проект клиента недоступен → маршруты проверяются на синтетических запросах, в отчёте это помечается; проверка выбора маршрута от этого не зависит.

## Ограничения

- Три маршрута — текстовые процессы поверх существующего ядра и скиллов; не создавать новые тяжёлые фреймворки и не переписывать доменные скиллы.
- Не добавлять в v1 публикацию сайтов, рекламные запуски, аналитику-интеграции: только определение «требуется ли по брифу» и ссылки на инструменты.
- Маршруты не заменяют ручную проверку дизайна/контента пользователем.
