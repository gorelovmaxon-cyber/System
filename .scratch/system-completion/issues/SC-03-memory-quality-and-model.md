## Входные/выходные данные

Формат записи памяти (для `.claude/memory/README.md`; для файлов — минимальный набор полей в начале записи):
```markdown
---
status: confirmed | observation | superseded
category: user-profile | facts | patterns | decisions | gotchas
scope: user | <project_id>
source: <URL/файл/сессия/дата>   # обязателен для confirmed
evidence: <что наблюдалось/кем подтверждено>
supersedes: <путь или id прежней записи>   # только для superseded/обновлений
confidence: <0..1 оценка, не доказательство>   # опционально
---
```
Правила:
- **observation** — выбор/вывод агента или анализ без прямого подтверждения пользователем.
- **confirmed** — прямое пожелание пользователя ИЛИ наблюдаемый факт с источником (файл/коммит/дата/сессия).
- **superseded** — прежняя запись, заменённая новой; связь `supersedes` двусторонняя, текст прежней записи сохраняется.
- Конфликтующие записи связываются, не перезаписываются молча.
- Цифры экономики/бенчмарков — это оценки; без источника помечать «unverified, дата».

## Алгоритм (шаг за шагом)

0. **Резервная копия до изменений**: сделать копию затронутых файлов `.claude/memory/` и легаси `memory/user-profile/coding-style.md` (в `.scratch/system-completion/backup/`, с датой) — часть записей может быть незакоммичена, git их не восстановит.
1. **Создать `.claude/memory/README.md`** с форматом и правилами выше; сделать его единственным источником формата (на него ссылается auto-learn).
2. **Аудит**: пройти все файлы `.claude/memory/` (и легаси `memory/user-profile/coding-style.md`) и классифицировать каждую запись: (а) личное предпочтение/правило пользователя; (б) проектное решение; (в) анализ/наблюдение модели; (г) факт с источником; (д) непроверенное утверждение. Составить список расхождений: где нет status/evidence, где выбор агента подан как preference, где цифры без источника.
3. **Правки по аудиту**: для каждой проблемной записи — добавить поля status/source/evidence/scope, не меняя формулировок-фактов без необходимости; конфликтующие пары связать через supersedes. Прямые пожелания пользователя (стиль кода, архитектурные предпочтения) пометить confirmed; технологические выборы агентов (например, «выбран Node.js bridge») — observation.
4. **Аналитические файлы**: превратить в observation-документы (шапка статуса + источники + дата). Непроверенные утверждения о ценах/доходах/экономии пометить unverified (дата, откуда взято или «без источника»). В `.scratch/next-chat-prompt.md` убрать «source of truth».
5. **Легаси-копия**: `memory/user-profile/coding-style.md` пометить superseded → каноническая `.claude/memory/user-profile/coding-style.md`; при наличии существенных расхождений — свести их в канон (confirmed) с пометкой в каноне.
6. **MEMORY.md**: переписать индекс под актуальные категории; анализы перечислить в секции наблюдений отдельно от решений.
7. **Факты по dev/kwork**: только из реально доступных источников. Если `D:\dev`/`D:\Sait` недоступны с этого ПК или их содержимое не читается — не создавать «аудит»; в projects-overview/реестре пометить статус unknown/not-audited (без выдуманных деталей).
8. **Скиллы auto-learn/profile-update**: обновить шаги записи: (а) определять status по правилам (прямое пожелание пользователя в диалоге → confirmed с source=сессия; вывод агента → observation); (б) при конфликте с существующей записью — создавать новую + supersedes-связь, показывать пользователю; (в) ссылаться на `.claude/memory/README.md`; (г) убрать создание `.system-memory/` (единый корень из SC-02).

## Проверки

**Среда и предпосылки:** локально; git-история доступна для отката.
**Команды:** выборочный просмотр diff `git diff .claude/memory`; проверка отсутствия потерянных строк (diff только добавочный). Для теста статусов — разбор одного синтетического кейса по шагам auto-learn (можно без запуска модели, по тексту шагов).
**Ожидаемый результат:** диффы аддитивны; ключевые формулировки пользователя сохранены; нет записей, где выбор агента подан как preference без источника.
**Если проверка недоступна:** недоступные проекты (D:\dev и т.п.) — статус not-audited в реестре, живая проверка их памяти не выполняется и не имитируется.
