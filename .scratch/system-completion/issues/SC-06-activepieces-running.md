# SC-06 — Запущенный Activepieces и конфигурация подключений

**What to build:** Рабочий Activepieces (UI, worker, БД) на закреплённой версии с персистентностью, подготовленной связностью контейнера к host-мосту и AI-подключением; конфиг перенесён в `services/activepieces/`.
**Requirement IDs:** R06
**Blocked by:** SC-01
**Status:** awaiting-validation

> Статус уточнён 2026-09-11: Docker/Activepieces на этой машине недоступны; конфигурация не считается живым сервисом.
**Перед началом работы:** Открой VS Code в `E:/System2`. SC-01 принят: ENVIRONMENT.md содержит выбранный релиз Activepieces (тег образа), postgres/redis-образы, порты, решение по сетевой связности Windows/Docker → host (например, `host.docker.internal` или выделенный адрес) и подтверждение, что Docker работает. Проверь `docker info`.

## Контекст

SPEC R06: «Activepieces реально получает событие, анализирует его и вызывает работающий writer» — полный flow строит SC-09, здесь должен быть живой сервис и проверенные подключения. Решение 4: контейнер обращается к bridge по явно настроенному адресу, не по localhost контейнера; вариант подключения Windows/Docker фиксируется и проверяется **до** сборки flow.

Черновик `.scratch/activepieces/docker-compose.yml` существует, но: образ `activepieces:latest` (не закреплён), секреты-плейсхолдеры, вариант сетевой связности с host не описан и не проверен, канонического расположения нет. Старые тикеты T7/T8 не выполнялись (готовность текста ≠ запуск). Число контейнеров само по себе не цель — важна работоспособность на выбранной версии.

## Входные/выходные данные

Вход: релиз и версии из ENVIRONMENT.md; адрес host-моста (переменная, напр. `AP_HOST_BRIDGE_URL`/`HOST_BRIDGE_URL=http://host.docker.internal:8643`, значение уточнить в ENVIRONMENT по выбранному варианту). Выход: запущенный стек с UI, рабочий execution worker, персистентные volumes; в отчёт — реальные команды и ответы (health, логи, проверка связности из контейнера).

## Алгоритм (шаг за шагом)

1. **Сверить версии** из ENVIRONMENT.md с фактически доступными (docker pull/манифест); расхождение — вернуться к SC-01-правилу: зафиксировать фактический тег с датой в ENVIRONMENT.md.
2. **Создать `services/activepieces/.env.example`** (все переменные, плейсхолдеры; включая owner/учётку первого пользователя и адрес host-моста). Сгенерировать gitignored `.env` со случайными значениями секретов (команды генерации — в README).
3. **Написать канонический compose** в `services/activepieces/`: локальная привязка портов (127.0.0.1, если релиз позволяет), healthchecks, `restart`-политика, volumes для БД/redis/кэша, переменные окружения для host-моста. Число контейнеров — по фактической конфигурации выбранного релиза, а не по старой гипотезе.
4. **Запустить стек** (`docker compose up -d`), дождаться health всех сервисов. Проверить логи app/worker на отсутствие ошибок конфигурации.
5. **Проверить UI**: открыть порт, пройти первичную настройку (создание владельца) по документации релиза. Записать URL и шаг.
6. **Проверить связность контейнер→host bridge ДО flow**: из контейнера activepieces выполнить запрос к host-мосту по выбранному адресу (например, `wget -qO- http://host.docker.internal:8643/health` — но мост появится в SC-08; поэтому проверить достижимость host: выбранный адрес резолвится и порт открыт, либо временно поднять простой listener для проверки — не оставлять его). Зафиксировать в ENVIRONMENT.md рабочий вариант (host.docker.internal против альтернативы).
7. **Подготовить AI-подключение**: в UI создать connection к выбранному AI-провайдеру (имя провайдера/модели — из ENVIRONMENT.md и фактического flow SC-09; если ключа ещё нет — зафиксировать как недостающий доступ в ENVIRONMENT.md/SUMMARY, но connection для webhook/безопасности настроить по возможностям). Ключи — только через UI/секреты, не в файлах репозитория.
8. **Проверить персистентность**: выполнить простой тестовый flow (webhook → без внешних AI-зависимостей → ответ), затем `docker compose restart`/`down && up` и убедиться, что flow и данные БД сохранились.
9. **Обновить docs/activepieces-setup.md** и **ENVIRONMENT.md** (фактическая версия, результат связности, имя connection).
10. **Проверить** сценариями ниже.

## Критерии приёмки

- [ ] `docker compose ps` — все сервисы healthy; health-endpoint Activepieces отвечает (`/api/v1/health`), UI доступен локально.
- [ ] В логах app/worker нет ошибок конфигурации/миграций; worker режим работает (выполнение flow возможно).
- [ ] Тестовый flow (без внешних ключей) выполняется; после перезапуска стека flow и данные сохраняются (персистентность).
- [ ] Вариант связности контейнер→host зафиксирован и проверен фактически; в ENVIRONMENT.md записано, какой адрес использовать в SC-09.
- [ ] Секреты — только в gitignored `.env`/UI; `git check-ignore services/activepieces/.env` подтверждает; в коммите нет значений ключей.
- [ ] docs/activepieces-setup.md отражает реальные версии и команды; `.scratch/activepieces/docker-compose.yml` остался нетронутым.
- [ ] R06 (частично): сервис запущен и готов принимать события; полный «получает событие → анализирует → вызывает writer» проверяется в SC-09.

## Проверки

**Среда и предпосылки:** локально, Docker (проверен в SC-01). Создание учётной записи владельца Activepieces может требовать ручного шага в UI — это допустимо и документируется.
**Команды:** из README сервиса (создать в этом тикете): `docker compose -f services/activepieces/docker-compose.yml up -d`, `docker compose ps`, health-curl, проверка связности из контейнера, логи worker.
**Ожидаемый результат:** healthy-стек, персистентность, зафиксированная связность.
**Если проверка недоступна:** отсутствие API-ключа AI-провайдера не блокирует этот тикет (нужно для SC-09) — фиксируется как недостающий доступ; запуск Docker недоступен → blocked с конкретикой.

## Ограничения

- Flow «событие → анализ → writer» и его конфиг — SC-09; здесь не строить.
- Не менять канонический корень памяти и writer (SC-08).
- Версии закрепляются фактически; если выбранный релиз требует иной конфигурации (число контейнеров, переменные), следовать релизу и обновить ENVIRONMENT.md, а не подгонять под старое число «3».
