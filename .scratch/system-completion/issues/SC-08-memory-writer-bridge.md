# SC-08 — Единый writer памяти: bridge API и ручная запись

**What to build:** Небольшой Node-мост с защищённым HTTP API записи: принимает структурированные предложения памяти (не произвольные пути/команды), валидирует категории и корень, пишет атомарно с идемпотентностью по event_id и долговечным учётом; тот же механизм обслуживает ручное сохранение.
**Requirement IDs:** R03, R07
**Blocked by:** SC-03, SC-07
**Status:** awaiting-review

> Статус уточнён 2026-09-11: T1 переработан через OS IPC authority и покрыт регрессией; реальная память не подключена до независимого решения.
**Перед началом работы:** Открой VS Code в `E:/System2`. SC-03 (формат/статусы памяти) и SC-07 (события/очередь, контракты в docs/memory-contract.md) приняты. Проверь resolve-paths (SC-02).

## Входные/выходные данные

**Запрос POST /write:**
```json
{ "event_id": "evt_<hex>",
  "proposals": [ { "category": "facts",
                   "statement": "…", "evidence": "…",
                   "scope": "systemqwen", "status": "observation",
                   "confidence": 0.7 } ] }
```
Категории (allow-list, финальный список сверить с каталогами SC-03): `user-profile`, `facts`, `patterns`, `decisions`, `gotchas`. scope: `user` или валидный project_id из реестра. status: observation/confirmed/superseded. Корень записи: `memory_root` из resolve-paths. Запись в файл категории по правилам SC-03 (новая запись или supersedes-связь, если задан `supersedes`).
**Ответ 200:**
```json
{ "status": "persisted",
  "written_files": [ ".claude/memory/facts/x.md" ],
  "revision": "<хеш/rev записи>" }
```
Ошибки: 400 (невалидная категория/scope/поля), 401 (неверный/отсутствующий токен), 409 (повторный event_id с другим содержимым), 500. Повтор того же event_id с тем же содержимым → 200 без дубля (идемпотентно).

## Алгоритм (шаг за шагом)

1. **Реализовать writer.js**: (а) validate: категория в allow-list, scope валиден, status валиден, statement/evidence непусты, размеры ограничены; (б) путь файла всегда производная от category внутри memory_root (никаких путей извне); (в) блокировка записи (внутрипроцессный mutex + файловая блокировка для bridge) для сериализации; (г) атомарность: писать во временный файл в том же каталоге → rename; (д) формат записи — по `.claude/memory/README.md` (SC-03): append новой записи либо supersedes-правка; (е) логика добавления записи в существующий файл категории: дописывание секции с сохранением прежнего текста.
2. **Реализовать writer-log.js**: перед записью регистрировать event_id+намерение (write-ahead) в processed.jsonl; после успешной записи — отметить persisted с revision. Повтор с тем же event_id: если уже persisted и содержимое идентично �� вернуть 200 без записи; если содержимое отличается — 409 (явный конфликт).
3. **Реализовать bridge-server.js**: HTTP на `127.0.0.1:<port>`; аутентификация: заголовок `Authorization: Bearer <token>`; token — из локального конфига/окружения (не в example-значениях); health без аутентификации (только «жив»); обработка ошибок writer в HTTP-коды; логирование без секретов и без полного содержимого (только event_id, категория, файл, код).
4. **Реализовать save.js**: ручной ввод → предложение; `--event-id` из события сессии (SC-07) связывает ручную запись с событием; без него — генерируется собственный id; затем запись через writer.js (та же функция, что и в bridge).
5. **Обновить контракт и конфиг**: секция «Writer» в docs/memory-contract.md; `bridge.port`, `writer.categories` в config; README с примерами curl и save.
6. **Проверить** сценариями ниже.

## Критерии приёмки

- [ ] Запись по золотому пути: POST /write с валидным предложением → 200, файл категории создан/дополнен, текст прежних записей сохранён; в ответе written_files и revision, без секретов.
- [ ] Повтор того же event_id (то же содержимое) → 200, дубля текста в файле нет (идемпотентность).
- [ ] Параллельные события (2 одновременных /write на разные категории и на одну) → обе записи сохранены, файл не повреждён, потери нет.
- [ ] Неверная категория / scope вне реестра / попытка «выхода за корень» (поле statement или любой путь не влияет на выбор файла) → 400, ничего не записано.
- [ ] Без токена/с неверным токеном → 401. Повторный event_id с другим содержимым → 409.
- [ ] Перезапуск bridge после записи, но до ACK клиенту (эмуляция): при повторе запроса дубля нет (write-ahead + проверка event_id).
- [ ] save.js сохраняет запись с `--status confirmed` и source через тот же механизм; `git status` показывает ожидаемые изменения `.claude/memory/`.
- [ ] R03/R07: writer принимает структурированные поля; наблюдение/подтверждение различаются; повтор не дублирует.

## Проверки

**Среда и предпосылки:** локально, Node. Bridge запускается как локальный процесс (`node scripts/memory/bridge-server.js`); для проверок — временная переменная окружения токена.
**Команды:** запуск bridge; `curl -X POST http://127.0.0.1:8643/write -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d @payload.json`; `node scripts/memory/save.js --category gotchas --statement "…" --evidence "…" --scope user --status confirmed --source "SC-08 test"`; `git diff --stat .claude/memory`.
**Ожидаемый результат:** все сценарии критериев воспроизводятся с зафиксированными ответами в отчёте.
**Если проверка недоступна:** тест на «параллельные записи» выполняется двумя процессами curl (доступно локально); если какая-то проверка требует несуществующего окружения — причина фиксируется, статус awaiting-validation.

## Ограничения

- Мост — небольшой локальный сервис для v1, без фреймворка и без публикации наружу (bind 127.0.0.1). Удалённый/облачный профиль — отдельная работа (SC-17 описывает, не реализует).
- Синхронизация (synced) и индексация (indexed) — не здесь (SC-11/SC-10); writer отмечает только persisted.
- Никакого выполнения команд, чтения произвольных путей и «магии» по содержимому statement.
