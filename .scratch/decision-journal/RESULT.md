## Правила и выполненный перенос

Запись содержит устойчивый ID, дату, project_id, тип, краткое содержание, источник, статус подтверждения, статус обработки, supersedes и ссылку на event_id/файлы памяти после переноса. Exact repeat возвращает `created:false`; другое содержимое с тем же ID даёт конфликт. Исправление создаёт новый файл со связью supersedes, старый остаётся. На границе задачи агент проверяет источник, дубли/конфликты и scope: устойчивое прямое предпочтение → профиль с подходящим scope; проектный факт/тариф → память проекта; общий приём → общая память лишь при доказанной переносимости. Наблюдение остаётся observation, вопрос — pending. Прямое решение не переспрашивают; гипотезу о предпочтении подтверждают.

Из актуальных `REQUIREMENTS.md`, `HANDOFF.md`, `B01-RESULT.md` и `B01-DEMO-BRIEF.md` сайта подготовлены четыре записи. Три подтверждённые через writer попали в память только с `scope: system-of-site`:

- `journal_system-of-site_2606a50d2d9da23b047d78da` — преимущественно вопросы с выбором, со свободным вводом где нужен;
- `journal_system-of-site_f842cc87e06ba66683bf6de2` — Максим проверяет полный синтетический разговор;
- `journal_system-of-site_20c1f120a14faf2103e957c2` — ставки B01 как проектный факт, итоговый расчёт ожидает утверждения.

`60765b3864858c2f2c3a2fcd` — наблюдение о порядке вопросов из синтетического демо, оставлено pending без повышения до confirmed. Тарифы/статус B01 не внесены в общий профиль. Старую память сайта массово не импортировали. Продуктовые файлы B01 не менялись.
