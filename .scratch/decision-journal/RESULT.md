## Правила и выполненный перенос

Запись содержит устойчивый ID, дату, project_id, тип, краткое содержание, источник, статус подтверждения, статус обработки, supersedes и ссылку на event_id/файлы памяти после переноса. Exact repeat возвращает `created:false`; другое содержимое с тем же ID даёт конфликт. Исправление создаёт новый файл со связью supersedes, старый остаётся. На границе задачи агент проверяет источник, дубли/конфликты и scope: устойчивое прямое предпочтение → профиль с подходящим scope; проектный факт/тариф → память проекта; общий приём → общая память лишь при доказанной переносимости. Наблюдение остаётся observation, вопрос — pending. Прямое решение не переспрашивают; гипотезу о предпочтении подтверждают.

Из актуальных `REQUIREMENTS.md`, `HANDOFF.md`, `B01-RESULT.md` и `B01-DEMO-BRIEF.md` сайта подготовлены четыре записи. Три подтверждённые через writer попали в память только с `scope: system-of-site`:

- `journal_system-of-site_2606a50d2d9da23b047d78da` — преимущественно вопросы с выбором, со свободным вводом где нужен;
- `journal_system-of-site_f842cc87e06ba66683bf6de2` — Максим проверяет полный синтетический разговор;
- `journal_system-of-site_20c1f120a14faf2103e957c2` — ставки B01 как проектный факт, итоговый расчёт ожидает утверждения.

`60765b3864858c2f2c3a2fcd` — наблюдение о порядке вопросов из синтетического демо, оставлено pending без повышения до confirmed. Тарифы/статус B01 не внесены в общий профиль. Старую память сайта массово не импортировали. Продуктовые файлы B01 не менялись.

## Проверки и пределы

| Сценарий | Результат |
|---|---|
| 1. Новое решение | Изолированный тест `capture` создаёт запись; сайт содержит подтверждённые записи. |
| 2. Повтор | Изолированный тест возвращает `created:false`; повтор `save.js` с тем же event_id оставил ровно одно вхождение в памяти. |
| 3. Исправление | Изолированный тест сохраняет старый файл и `supersedes`; выбор текущего значения требует проверки цепочки агентом. |
| 4. Новая сессия | HANDOFF, журнал и память дают путь к решению без старого чата; отдельная живая сессия ещё не проверена. |
| 5. Тариф не в общем профиле | Writer-запись имеет `scope: system-of-site`, category `facts`; профиль не менялся. |
| 6. Наблюдение | Сайт оставил запись `observation` pending; тест не позволяет отметить открытый вопрос. |
| 7. Другой scope | Изолированный тест скрывает чужую запись в `list`; штатный `search.js --project` применяет существующий фильтр. |
| 8. Writer сохранил, mark прервался | Изолированный тест повторного `mark` получает одну запись и тот же event_id. |
| 9. Khoj недоступен | Реальный `search.js` вернул `khoj-unavailable` с локальным fallback; локальная память и writer-log сохранены, `indexed` не подтверждён. |
| 10. Push не удался | Существующий тест SW-04 подтверждает локальный коммит и явную ошибку публикации; эта работа отдельно сверяет remote после push. |
| 11. Нет нового знания | Пустой журнал возвращает пустой список; правило агента требует no-op. |
| 12. Секретный тестовый маркер | Изолированный тест отклоняет маркер и не создаёт файл; статическая проверка исходящего diff дополнительно обязательна. |

Команда `node --test scripts/memory/tests/decision-journal.test.js scripts/memory/tests/memory-fixation.test.js scripts/memory/tests/sw-04-checkpoint.test.js`: **21/21 pass**. `git diff --check` для обоих репозиториев: без ошибок. Проверка U+FFFD как confirmed добавлена в CLI. Live-механизм вызова перед каждым ответом и факт чтения в совершенно новой сессии остаются за пределами этих тестов; сценарий 4 ожидает проверки пользователем/приёмщиком. Ошибка push не может превращаться в `synced`; до проверки remote не объявлять публикацию. Khoj fallback не доказывает индексацию.

После первого коммита обнаружена дополнительная граница: если вызвать общий `save.js` из каталога сайта, содержащего унаследованный `config/system.example.json`, он разрешает **локальный** корень сайта. Случайная локальная запись от повторной пробы удалена после точной проверки diff и не публиковалась; повтор из корня System дал `idempotent:true`. CLI журнала теперь перед определением project_id и проверкой writer-log переключается на свой корень System2. Инструкция по-прежнему требует вызывать штатный `save.js` из корня System2.
