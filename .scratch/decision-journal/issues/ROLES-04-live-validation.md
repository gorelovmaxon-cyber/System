# ROLES-04 — подготовка живой проверки сохранения поправки

**What to build:** В существующем отчёте есть короткий сценарий реальной поправки пользователя и восстановления в новой сессии.
**Requirement IDs:** ROLES-04 поручения пользователя 2026-10-08.
**Blocked by:** Следующее реальное уточнение пользователя в обычной работе и фактическое продолжение в новой сессии; обычную работу System2 это не блокирует.
**Status:** awaiting-validation.

## План и критерии

- [ ] Пользователь даёт реальную поправку; агент без напоминания сохраняет её до финального ответа.
- [ ] На границе задачи capture → save.js → search → mark используют правильный проект и scope; supersedes содержит реальный journal_id, если есть прежняя запись.
- [ ] Новая сессия читает файлы и находит актуальную поправку, продолжает правильный этап без старого чата.
- [ ] Локальное продолжение и перенос на другой ПК различаются: второму нужны отдельное разрешение на публикацию и получение scoped-коммитов.

Сценарий и поля для фактических evidence:
[существующий отчёт](../RESULT.md#roles-live-validation).

пользователя 2026-10-08 разрешает изолированную новую сессию без старой переписки
исключительно для реальной проверки. Если появится реальная поправка, точный промпт:
«Открой E:\SystemTheBest\System. Прочитай действующие правила и актуальный HANDOFF.
Определи текущий этап и следующий разрешённый шаг. Ничего не изменяй».
Содержание поправки, её ID и ожидаемый ответ в промпт не добавлять.

запрос специальной поправки ради проверки: ждать следующего реального уточнения,
новые тестовые задачи не создавать. Изолированная сессия не запускалась.
Незавершённая проверка не блокирует обычную работу System2 и не означает
