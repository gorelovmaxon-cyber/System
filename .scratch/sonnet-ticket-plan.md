# План для Sonnet: Нарезка тикетов из spec.md

**Когда использовать:** После того как Opus создал spec.md (спецификацию задачи)

**Задача Sonnet:** Нарезать spec.md на детальные тикеты для GPT Luna по шаблону TICKET_TEMPLATE.md

---

## Входные данные для Sonnet:

1. **spec.md** — спецификация от Opus (что нужно, зачем, архитектура)
2. **TICKET_TEMPLATE.md** — шаблон тикета SystemQwen
3. **Количество тикетов** — Opus указывает сколько тикетов нужно (например: 5 тикетов)

---

## Инструкция для Sonnet:

```markdown
# Задача: Нарезать spec.md на N тикетов

## Входные данные:

- [spec.md](путь) — спецификация задачи
- [TICKET_TEMPLATE.md](путь) — шаблон тикета
- Количество тикетов: N

## Что делать:

### Шаг 1: Прочитать spec.md

Понять:
- Что нужно реализовать (цель)
- Какие компоненты (файлы, конфигурации)
- Зависимости между частями
- Критерии готовности

### Шаг 2: Определить границы тикетов

Разбить spec.md на N логических частей:
- Каждый тикет = 1 завершённая подзадача
- Каждый тикет = 1 коммит
- Тикеты последовательные (T1 → T2 → T3) или параллельные

### Шаг 3: Создать тикеты по TICKET_TEMPLATE.md

Для каждого тикета T[N]:

1. **Заголовок:**
   ```markdown
   # T[N] — [Краткое название из spec]
   
   **What to build:** [1-2 предложения что именно]
   **Blocked by:** [T[X] или none]
   **Status:** ready-for-agent
   **Перед началом работы:** Открой VS Code в папке `[путь]`
   ```

2. **Контекст:**
   - Взять из spec.md раздел относящийся к этому тикету
   - Объяснить "зачем" и "как это связано с общей целью"

3. **Файлы для изменения:**
   ```markdown
   - [путь/к/файлу.js](путь) — что именно менять (строки, функция)
   ```

4. **Файлы для чтения (контекст):**
   ```markdown
   - [путь/к/примеру.md](путь) — откуда брать паттерн
   ```

5. **⚠️ Файлы НЕЛЬЗЯ трогать:**
   ```markdown
   - `CLAUDE.md` — только читать
   - `.claude/memory/` — не изменять
   ```

6. **Алгоритм (шаг за шагом):**
   
   **ВАЖНО:** Здесь добавляешь ПОЛНЫЙ КОД и примеры:
   
   ```markdown
   ### Шаг 1: Создать файл X
   
   1. **Создать файл** `путь/к/файлу.js`
   
   2. **Добавить код:**
   
   ```javascript
   // Полный пример кода из spec.md
   const example = () => {
     // ...
   }
   ```
   
   3. **Проверить:**
   ```bash
   node файл.js
   ```
   ```

7. **Критерии приёмки:**
   ```markdown
   - [ ] Файл создан
   - [ ] Команда X работает
   ```

8. **Ограничения:**
   ```markdown
   - Не менять файл Y
   - Использовать только библиотеку Z
   ```

9. **Как закончить:**
   ```markdown
   1. Проверка: `команда`
   2. Коммит:
      ```bash
      git add файлы
      git commit -m "T[N]: описание
      
      Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>"
      ```
   3. Финальный ответ (максимум 6 строк):
      - Что сделано
      - Результат проверки
      - Что изменено
   ```

### Шаг 4: Проверить последовательность

- T1 → T2 → T3: блокировки правильные
- Нет циклических зависимостей
- Каждый тикет автономный (можно выполнить отдельно)

### Шаг 5: Сохранить тикеты

Создать файлы:
```
.scratch/[название-задачи]/issues/T1-[название].md
.scratch/[название-задачи]/issues/T2-[название].md
...
.scratch/[название-задачи]/issues/TN-[название].md
```

### Шаг 6: Создать SUMMARY.md

```markdown
# Summary — Тикеты T1-TN

## Порядок выполнения:
1. T1 (описание) ← начать здесь
2. T2 (описание) ← зависит от T1
...

## Команда коммита:
```bash
git add .scratch/[название]/issues/
git commit -m "feat: создать тикеты T1-TN для [задачи]"
git push origin master
```
```

## Критерии качества тикетов от Sonnet:

✅ Каждый тикет содержит:
- Перед началом работы (путь к проекту)
- ⚠️ Файлы НЕЛЬЗЯ трогать
- Файлы для чтения (контекст)
- Алгоритм с ПОЛНЫМ кодом
- Критерии приёмки
- Как закончить (6 строк)

✅ Код в тикетах:
- Полные примеры (не "добавь функцию X", а весь код функции)
- Рабочие команды (bash, curl, docker)
- Проверочные шаги

✅ Последовательность:
- Блокировки указаны правильно
- Можно выполнять параллельно где возможно
- Каждый тикет = 1 коммит

## Расход токенов (ожидаемый):

**Opus (создание spec.md):**
- Grill: 5-10k токенов
- Spec: 10-15k токенов
- **Итого Opus: 15-25k токенов**

**Sonnet (нарезка на тикеты):**
- Чтение spec: 5k токенов
- Создание 5 тикетов с кодом: 15-25k токенов
- **Итого Sonnet: 20-30k токенов**

**Всего: 35-55k токенов (вместо 140k)**

**Экономия: 60-75%**

- Количество тикетов: N

Создай тикеты в .scratch/[название]/issues/T1-TN.md"
```
