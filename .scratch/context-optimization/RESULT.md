## Рекомендации, требующие отдельного решения

Ничего из этого списка не применено.

1. Для System2 завести явный project-профиль MCP: Figma оставить выключенной/opt-in,
   пока она исключена из обязательного объёма; Firecrawl включать для отдельного
   research-маршрута; Playwright — для sites/browser QA. Не удалять их глобально.
   Последствие: соответствующая внешняя задача потребует явного включения и повторной
   проверки доступа; другие проекты сохранят подключения.
2. Не отключать `node_repl` без отдельной проверки инструментов Codex; `cua_repl` уже
   отключён. Последствие отключения инфраструктурного MCP неизвестно по доступным
   метаданным и может убрать browser/tool orchestration.
3. Развести model-triggers `to-tickets` и `writing-tickets-for-qwen`: оставить общий
   автоматический trigger у одного, второй сделать явным System2/Qwen-вариантом или
   user-invoked. Последствие: меньше конкурирующих маршрутов, но старые явные команды
   нужно сохранить.
4. Оставить model-trigger у `systemqwen`, а `subagent-pipeline` сделать внутренней
   ссылкой либо user-invoked, если он не должен выбираться независимо. Последствие:
   единая точка выбора последовательного исполнения; перед изменением проверить все
   ссылки на skill.
5. Сузить `skill-forge` до явного запроса/отдельного процесса или сделать user-invoked.
   Последствие: знания перестанут автоматически предлагаться в конце любой задачи;
   повторяемые gotchas придётся фиксировать через явный вызов. Это согласует текущий
   запуск, но может изменить привычки других проектов — поэтому глобально не применять
   без отдельного разрешения.
