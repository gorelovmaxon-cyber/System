# T2 — Создать скилл /profile-update с относительными путями

**What to build:** Скилл для ручного обновления user-profile после завершения задачи, использующий относительные пути к `.claude/memory/user-profile/`

**Blocked by:** T1

**Status:** ready-for-agent

**Перед началом работы:**
Открой VS Code в папке `D:\System2` (File > Open Folder).

## Контекст

Нужно создать скилл `/profile-update`, который анализирует последнюю завершённую задачу и предлагает обновить файлы в `.claude/memory/user-profile/`. Скилл вызывается вручную или автоматически из `/auto-learn`.

**Важно:** Все пути должны быть относительными (`.claude/memory/`), чтобы при переносе System2 на другой ПК всё работало.

## Файлы для изменения

Нет — только создание нового скилла.

## Файлы для чтения (контекст)

- [.claude/memory/user-profile/coding-style.md](.claude/memory/user-profile/coding-style.md) — пример структуры user-profile (создан в T1)
- [.claude/memory/user-profile/architecture-prefs.md](.claude/memory/user-profile/architecture-prefs.md) — пример содержимого
- [.claude/skills/auto-learn/SKILL.md](.claude/skills/auto-learn/SKILL.md) — похожий скилл для понимания структуры и формата

## ⚠️ Файлы НЕЛЬЗЯ трогать

- `.claude/skills/auto-learn/SKILL.md` — не изменять в этом тикете (обновим в T3)
- `.claude/skills/autopilot/SKILL.md` — не изменять в этом тикете (обновим в T4)
- `.claude/memory/user-profile/*.md` — не изменять содержимое, только читать для понимания структуры

## Алгоритм (шаг за шагом)

1. **Создай папку для скилла:**
   ```bash
   mkdir -p .claude/skills/profile-update
   ```

2. **Создай файл `.claude/skills/profile-update/SKILL.md` с frontmatter:**
   ```markdown
   ---
   name: profile-update
   description: Анализирует последнюю задачу и предлагает обновить user-profile (.claude/memory/user-profile/). Вызывается вручную после завершения задачи или автоматически через auto-learn.
   ---
   
   # profile-update
   
   Ручное обновление профиля пользователя: анализирует последнюю завершённую задачу и предлагает дополнить файлы в `.claude/memory/user-profile/` — стиль кода, архитектурные предпочтения, типичные ошибки, рабочие паттерны.
   
   ## Когда запускается
   
   - Вручную: `/profile-update` после задачи
   - Автоматически: из `/auto-learn` если найден новый паттерн в стиле пользователя
   ```

3. **Добавь секцию "## Шаги" с детальным алгоритмом:**
   ```markdown
   ## Шаги
   
   1. **Проанализировать последнюю задачу**
      - Что делали (из git log или истории диалога)
      - Какие решения принимали
      - Какой стиль кода использовали
      - Какие технологии применили
      
      **Готово, когда:** есть список из 3-5 наблюдений
   
   2. **Определить категорию для обновления**
      - `coding-style.md` — если нашли паттерны кода, стиль именования, форматирование
      - `architecture-prefs.md` — если нашли архитектурные решения, выбор технологий
      - `common-mistakes.md` — если нашли ошибку и как её исправили
      - `work-patterns.md` — если нашли паттерн работы, workflow, организацию
      
      **Готово, когда:** категория определена
   
   3. **Предложить конкретное обновление**
      - Показать, в какой файл добавить
      - Показать, в какую секцию
      - Показать конкретный текст для добавления
      - Спросить подтверждение: "Добавить?"
      
      **Готово, когда:** пользователь ответил "да" или "нет"
   
   4. **Если "да" — обновить файл**
      - Прочитать существующий файл из `.claude/memory/user-profile/`
      - Найти подходящую секцию (или создать новую)
      - Добавить новую информацию
      - Сохранить файл
      
      **Готово, когда:** файл обновлён
   
   5. **Обновить MEMORY.md если нужно**
      - Если добавлена новая секция — обновить индекс в `.claude/memory/MEMORY.md`
      
      **Готово, когда:** индекс актуален
   
   6. **Резюме**
      - "Обновлён `user-profile/<файл>`, секция `<название>`"
      - "Будет доступно в следующих сессиях"
      
      **Готово, когда:** пользователь уведомлён
   ```

4. **Добавь секцию "## Что НЕ записывать":**
   ```markdown
   ## Что НЕ записывать
   
   - Разовые решения специфичные для одного проекта
   - Временные workarounds
   - То, что уже есть в профиле
   - Факты о проектах (это в `.claude/memory/facts/`, не в `user-profile/`)
   ```

5. **Добавь секцию "## Gotchas":**
   ```markdown
   ## Gotchas
   
   - **Относительные пути:** всегда используй `.claude/memory/user-profile/`, не абсолютные пути типа `D:\System2\...` — проект должен быть переносимым между машинами
   - Не дублировать существующую информацию — сначала проверить файл
   - Не записывать детали проекта — только стиль/подход пользователя
   - Спрашивать подтверждение перед записью
   ```

6. **Добавь секцию "## Пример вызова":**
   ```markdown
   ## Пример вызова
   
   ```
   Пользователь: /profile-update
   
   Claude: Анализирую последнюю задачу...
   
   Нашёл паттерн: используешь explicit stop gates между фазами работы.
   
   Предлагаю добавить в work-patterns.md, секция "Workflow":
   
   ### Explicit Stop Gates
   Всегда останавливаюсь после каждой фазы (grill → spec → tickets → implement).
   Никогда не продолжаю автоматически без подтверждения пользователя.
   
   Добавить? (да/нет)
   
   Пользователь: да
   
   Claude: ✅ Обновлён user-profile/work-patterns.md, секция "Workflow"
   Будет доступно в следующих сессиях.
   ```
   ```

7. **Проверь, что все пути относительные:**
   - Все упоминания путей должны начинаться с `.claude/memory/`
   - Никаких `D:\System2\` или `D:\System\` в файле

- [ ] Все 6 шагов описаны с критериями "Готово, когда"
- [ ] Секции "Что НЕ записывать", "Gotchas", "Пример вызова" присутствуют
- [ ] Все пути в файле относительные (`.claude/memory/`)

## Ограничения

- Использовать ТОЛЬКО относительные пути (`.claude/memory/...`)
- НЕ использовать абсолютные пути (`D:\System2\...`)
- Следовать формату других скиллов (frontmatter + секции)
