## План и неизвестное

**Основной путь:** сверить состояние → ограниченный проверенный резерв → fetch и закрепление SHA → безопасное слияние → восстановление местных незакоммиченных изменений → актуальные инструкции и bootstrap → достаточная проверка → отчёт.

**Первая проверка:** актуальные ветка/remote, незавершённая Git-операция, staged/unstaged/untracked, расхождение истории и совпадения путей с remote. Указанные выше значения — снимок, их перепроверить.

**Рубеж пересмотра:** несовместимые пользовательские решения в одном файле, конфликт payload одного event_id, неизвестные staged-изменения, переписанная удалённая история или необходимость менять проекты сайтов/глобальные настройки. Сохранить обе версии и назвать конкретное препятствие; продолжить независимые проверки. Не выбирать сторону целиком ради зелёного merge. Если remote ушёл дальше снимка, сначала проверить новый diff: обычные изменения в прежних границах включить в закреплённый SHA, расширение объёма вынести пользователю.

## Алгоритм

1. Проверить исходное состояние и remote `https://github.com/gorelovmaxon-cyber/System.git`. Зафиксировать HEAD, remote SHA, ветку, staged/unstaged/untracked, эффективные hooks и только несекретные параметры конфигурации.
2. До изменений создать ограниченный резерв вне репозитория, например в `D:\SystemTheBest\System-update-backups\<timestamp>`. Сохранить затрагиваемые конфиги, writer-журналы, полное содержимое незакоммиченной памяти и HANDOFF, staged/unstaged patches, перечисленные untracked/задания и исходные refs. Проверить SHA-256 резервов; секреты не печатать. Полный архив репозитория не нужен.
3. Выполнить fetch, закрепить полученный SHA, сравнить историю и пути. При возможности использовать fast-forward. При подтверждённом обычном расхождении разрешено нормальное merge без переписывания истории; повторное разрешение только из-за ahead 3 / behind 6 не нужно. Не обещать совпадение HEAD с remote после merge.
4. Пересекающиеся незакоммиченные изменения сначала отделить безопасно. Разрешено временно вернуть только конкретные пересекающиеся отслеживаемые файлы к исходному HEAD после проверки полных резервов и отсутствия неучтённых staged-правок; после merge обязательно перенести местные изменения поверх обновлённой версии. Не использовать автоматический stash, массовый restore или reset. Не коммитить чужую память/HANDOFF как способ освободить дерево. Если безопасный перенос неочевиден — остановить зависимую операцию с обеими версиями и точным описанием.
5. При конфликте памяти сопоставлять event_id и полные payload, не только заголовки. Дубликат удалять лишь при доказанном совпадении; уникальные записи обеих сторон сохранять. При конфликте смыслов не придумывать объединённое решение. Перед merge-коммитом проверить, что staged содержит только результат слияния; местные незакоммиченные правки восстановить отдельно и проверить отсутствие потерь/дублей.
6. Прочитать актуальные инструкции. Применить штатный bootstrap для `D:\SystemTheBest\System`, предварительно проверив его действия и профиль core. Сохранить реальные local_paths и посторонние hooks; старый capture → queue → AP не должен активироваться. Недоступные Khoj/bridge диагностировать без переустановки/запуска.
7. Проверить обновлённые файлы site-build, стандарт, маршрутизацию и шаблон. Выполнить ограниченный существующий тест адаптера в его временных fixtures. Не запускать init-project на действующей системе сайтов. Доступность slash-команды в конкретном клиенте заявлять только при фактической проверке обнаружения; наличие файла само по себе этого не доказывает. Не запускать генерацию сайта ради smoke-test.
8. Выполнить проверки ниже, восстановить и сверить местное состояние. Подготовить единый отчёт и краткую передачу. Не начинать новую разработку по старым записям памяти.

Local fallback не доказывает обновление индекса Khoj. Обязательная непроведённая проверка означает awaiting-validation, не ложный успех.

## Ограничения

- Не применять reset --hard, clean, force push, rebase опубликованной/местной истории или автоматический stash.
- Docker, Activepieces, WSL, Figma не устанавливать и не запускать; старую очередь и платные AI-вызовы не запускать. Khoj/bridge не переустанавливать. Trading-dev/autopilot-framework не подключать.
- Не создавать новые навыки, тикеты, систему автоматизации или дополнительные циклы приёмки. Опубликованные навыки приходят как часть обновления.
- Не исправлять самостоятельно найденный код: сначала назвать воспроизведённый дефект и минимальную границу исправления. Не превращать обновление в аудит.
- Секреты не включать в отчёт/Git. Не писать тестовые факты и дополнительные записи writer ради доказательства обновления; существующая память приходит с merge и сохраняется.
- Push в этой задаче не разрешён: применение опубликованного снимка на ноутбуке не требует публикации местной истории. Не запускать фоновые механизмы синхронизации.
