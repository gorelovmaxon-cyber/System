# L03-03 — Реальный flow: событие → AI → writer, коррелированный ack и переносимый export

**What to build:** Настоящий Activepieces получает событие SC-07, реальный AI-вызов даёт валидированные proposals, writer сохраняет запись; отправитель получает коррелированный sync-ack с тем же `event_id`; flow экспортируется без секретов и проверяется на импорт в закреплённой версии.
**Requirement IDs:** R06, R07; SC-09, FIX-09
**Blocked by:** L03-02 (рабочий стек и достижимый bridge); разрешённое AI-подключение
**Status:** blocked
**Перед началом работы:** Открой `D:\SystemTheBest\System`, проверь корень Git и текущие изменения.

## Контекст

`services/activepieces/flows/memory-event-to-writer.json` — **blueprint, а не
готовый импортируемый экспорт**: в нём намеренно стоят заглушки webhook ID,
AI-connection/модели и bridge URL/token. Реальный flow ещё не создавался и не
импортировался. Delivery endpoint настраивается локально; секретные webhook URL
и значения connection не коммитятся.

Контракт подтверждения: endpoint — синхронный webhook URL, оканчивающийся на
`/sync`, flow завершается Return Response. Generic 2xx считается только приёмом
запроса; очередь подтверждает элемент лишь при коррелированном ответе
`{event_id,status:"persisted"}` либо `{event_id,status:"no-pattern"}`.

## План и неизвестное

- **Подтверждено:** bridge идемпотентен по `event_id` **и содержимому**; повтор
  того же события даёт `idempotent:true`. Другой AI-ответ по тому же `event_id`
  может дать `409 CONFLICT` — температура `0` не гарантирует совпадения proposals,
  поэтому сверяются фактические proposals, а не настройка модели.
- **Предполагается:** для реального AI-вызова нужен провайдер и connection.
  AI-ключ в `.env` не найден — недостающий выбор/доступ запрашивается у пользователя,
  ключ вводится локально. Платные серии прогонов не выполняются.
- **Основной путь:** собрать flow в UI по blueprint, заменить заглушки локальными
  значениями, выполнить один ограниченный явный AI-сценарий, затем экспортировать flow.
- **Первая проверка:** после L03-02 — короткий прогон ветки `no-pattern` без
  writer, чтобы убедиться в работоспособности flow до подключения AI.
- **Рубеж пересмотра → альтернатива:** настоящий API закреплённой версии требует
  правки production-кода (например, `scripts/memory/deliver.js`) — тогда изменение
  минимально, с тестами и отдельным объяснением; архитектура без согласования не
  меняется. Если AI-подключение не разрешено, тикет остаётся `blocked` с названным
  недостающим решением.

## Входные/выходные данные

Вход — событие SC-07: `event_id`, зарегистрированный `project_id`, `kind` и контекст.
AI возвращает `has_pattern:boolean` и `proposals:array`; proposals валидируются до
writer. Sync endpoint отвечает `{event_id,status:"persisted"}` либо
`{event_id,status:"no-pattern"}`. Ошибка, таймаут или некоррелированный 2xx
сохранение **не** подтверждают.

## Алгоритм (шаг за шагом)

1. Собрать flow по blueprint в UI; заглушки заменить локальными значениями.
2. Проверить ветку `no-pattern`: успешный прогон **без** вызова writer.
3. Настроить разрешённый AI connection; выполнить один ограниченный AI-сценарий.
4. Подтвердить, что proposals валидированы и запись persisted; сверить фактические proposals.
5. Проверить sync-ack: тот же `event_id` в ответе; подтвердить реальный HTTP-ответ
   и run flow, а не только лог шага.
6. Проверить негативный сценарий: bridge недоступен или отказ авторизации → нет
   ложного `persisted`, событие пригодно для повтора. После восстановления тот же
   контролируемый сценарий завершается успешно.
7. Проверить повтор доставки: дубля нет, подтверждение объяснимо.
8. Экспортировать flow, очистить от секретов, проверить импорт в закреплённой версии.

## Критерии приёмки

- [ ] Ограниченный явный AI-сценарий в настоящем Activepieces даёт валидированные
      proposals и persisted через writer.
- [ ] Ветка `no-pattern` проверена без вызова writer.
- [ ] Отправитель получает sync-ack с тем же `event_id`; подтверждены реальный
      HTTP-ответ и run flow, а не только лог шага или generic 2xx.
- [ ] Повтор события не создаёт дубля и имеет объяснимое подтверждение.
- [ ] Негативный сценарий (bridge недоступен/отказ авторизации) не даёт ложного
      `persisted`; событие пригодно для повтора.
- [ ] Настоящий export получен, очищен от секретов и проверен на импорт в выбранной версии.
- [ ] Delivery endpoint настроен локально; секретные webhook URL и значения connection не закоммичены.
- [ ] Основная память после проверки не изменилась; затронутые тесты пройдены.

## Проверки

**Среда и предпосылки:** рабочий стек L03-02, достижимый bridge, разрешённое AI-подключение; ключ вводится локально.
**Команды:** создаются в этом тикете (сборка flow и экспорт выполняются в UI Activepieces); точные шаги и фактический вывод записать в отчёт. Команды неподтверждённого API не выдумывать.
**Ожидаемый результат:** доказаны положительный сценарий, `no-pattern` и негативный сценарий, а также коррелированный ack.
**Данные и наблюдение:** изолированная память/журналы/тестовая конфигурация bridge, связанная с настоящим Activepieces; fixture явно называется fixture. Удалить только созданные проверкой данные и подтвердить неизменность основной памяти.
