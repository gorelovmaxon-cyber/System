# L06-01 — Безопасный перенос: доступ ко второму ПК и готовый пакет

**What to build:** Определить фактический доступ к реальному второму ПК и его состояние (путь, git status, незакоммиченные файлы, memory/runtime, локальные конфиги). При отсутствии доступа — выдать конкретный пакет команд/проверок для пользователя и не объявлять drill выполненным.
**Requirement IDs:** SC-13; R09, R13.
**Blocked by:** SC-12, SC-13.
**Status:** **blocked** — доступа ко второму ПК из этой среды нет (проверка 2026-09-14, см. ниже); пакет команд готов и лежит в этом тикете. Пакет — не замена drill.
**Перед началом работы:** Открой `D:\SystemTheBest\System`, проверь корень Git и текущие изменения; ничего на этом ПК и на втором ПК не менять до сохранения данных.

## Контекст

## Пакет команд для второго ПК

Выполнять **на втором ПК**, по шагам. Шаги 0–1 — только чтение и сохранение: до них
ничего не менять. Значения секретов никуда не печатать и не коммитить.

### Шаг 0 — найти фактический путь и снять состояние

```powershell
# где вообще есть рабочие копии репозитория
Get-ChildItem C:\,D:\,E:\ -Directory -Depth 2 -ErrorAction SilentlyContinue |
  Where-Object { Test-Path (Join-Path $_.FullName '.git') } |
  Select-Object -ExpandProperty FullName

Set-Location <НАЙДЕННЫЙ_КОРЕНЬ>
git remote -v
git branch --show-current
git log -1 --format='%H %ad %s' --date=iso
git status --short
git config --get core.hooksPath
git fetch origin
git log --oneline --left-right HEAD...origin/master
```

Ожидаемое: `origin` = `https://github.com/gorelovmaxon-cyber/System.git`, ветка `master`.
Строки `HEAD...origin/master` показывают расхождение в обе стороны — их надо сохранить
как есть. `git status --short` — это список незакоммиченных файлов второго ПК.

### Шаг 1 — сохранить данные до любых изменений

```powershell
$ts  = Get-Date -Format 'yyyyMMdd-HHmmss'
$dst = "D:\transfer-backups\second-pc-$ts"
New-Item -ItemType Directory -Force -Path $dst | Out-Null

# рабочее дерево как есть: патч + список + полный bundle истории
git diff HEAD --binary           > "$dst\uncommitted.patch"
git status --porcelain=v1        > "$dst\status.txt"
git bundle create "$dst\repo-$ts.bundle" --all

# локальные данные, которых нет в Git
Copy-Item -Recurse -Force .claude\memory      "$dst\memory"
Copy-Item -Recurse -Force .local              "$dst\local"
if (Test-Path config\system.local.json) { Copy-Item config\system.local.json "$dst\" }

# контрольные суммы всего сохранённого
Get-ChildItem -Recurse -File $dst |
  Get-FileHash -Algorithm SHA256 |
  ForEach-Object { "$($_.Hash)  $($_.Path)" } | Set-Content "$dst\MANIFEST.sha256"
```

Границы: `git diff` и `git bundle` рабочий файл не меняют. `.env` и ключи в пакет не
копировать — только в защищённый менеджер секретов (см. `docs/system-operations.md`,
раздел Backup). Если незакоммиченного кода много, предпочтительнее сначала сделать
явный commit на втором ПК, а патч оставить как страховку.

### Шаг 2 — принять изменения из Git, сохранив обе версии

```powershell
# только при чистом дереве и отсутствии собственных расходящихся коммитов:
git pull --ff-only origin master

# при расхождении (в выводе шага 0 видны обе стороны):
git pull --no-rebase origin master      # merge, не rebase
# разрешить конфликт явно, обе версии должны быть видны в файле
git add <разрешённые файлы>; git commit
```

Запрещено: `reset --hard`, `clean -f`, force push, удаление `.local/`. Если конфликт
непонятен — остановиться, сохранить оба варианта и передать вопрос пользователю.

### Шаг 3 — проверить, что сохранение действительно полное

```powershell
$dst = <каталог из шага 1>
Get-ChildItem -Recurse -File $dst | Measure-Object | Select-Object -ExpandProperty Count
(Get-Content "$dst\status.txt").Count
```

Ожидаемое: число строк в `status.txt` совпадает со числом незакоммиченных файлов,
увиденных на шаге 0, а `MANIFEST.sha256` покрывает весь пакет. Это и есть доказательство,
что данные сохранены до изменений.

## Критерии приёмки

- [x] Определено, есть ли доступ ко второму ПК; результат назван прямо (доступа нет).
- [x] Пакет команд готов, конкретен и не требует чтения всей переписки.
