## Требования Docker Desktop — сверено официальным источником 2026-09-13

Источник: [Docker Desktop Windows install](https://docs.docker.com/desktop/install/windows-install/)
и [Microsoft WSL basic commands](https://learn.microsoft.com/en-us/windows/wsl/basic-commands).

| Требование Docker Desktop | Факт на машине | Итог |
|---|---|---|
| WSL версии ≥ 2.1.5 (для WSL 2 backend) | `2.7.14.0` | выполняется |
| Windows 10 64-bit 22H2 (build 19045) — перечислены редакции Enterprise/Pro/Education | Windows 10 **Home** Single Language, build `19045` | **Home в списке требований не названа** |
| 8 ГБ RAM минимум | ~16 ГБ | выполняется |
| SLAT, аппаратная виртуализация | `Firmware virtualization=True`, `SLAT=True` | выполняется |
| Служба `LanmanServer` — Running и Automatic | Running, Automatic | выполняется |
| Свободное место на диске | до установки C: ~13 ГБ, D: ~27 ГБ; после установки C: 10.2 ГБ, D: 27.3 ГБ | **впритык**, подлежит наблюдению |

Оговорка того же источника: «Windows Home or Education editions only allow you to run
Linux containers» — наш сценарий использует **Linux-контейнеры**, поэтому ограничение
редакции Home по типу контейнеров нам не мешает. Отсутствие Home в формальном списке
поддерживаемых редакций — фактическое расхождение, а не отказ: оно проверяется
реальным запуском движка, а не решается по документации.

## План и неизвестное

- **Подтверждено:** WSL работает; требования Docker Desktop сверены по официальному
  источнику с датой. Раннее evidence — [activepieces-phase3-preflight-host-smoke-2026-09-13.json](../evidence/activepieces-phase3-preflight-host-smoke-2026-09-13.json),
  поля `environment.wsl` и `environment.docker`.
- **Основной путь:** Docker Desktop официальным установщиком → Compose v2 → существующий
  pinned compose в `services/activepieces`. Не собирать Activepieces из исходников и не
  заменять стек имитацией ради обхода блокера.
- **Первая проверка:** `docker info` и `docker compose version` отвечают о работающем
  движке. PID установщика или наличие файла `Docker Desktop.exe` этого не доказывают.
- **Рубеж пересмотра → альтернатива:** движок не поднимается из-за редакции Home или
  нехватки места. Тогда зафиксировать конкретную ошибку и один поддерживаемый вариант.
  Смена машины, платный доступ или смена архитектуры согласуются с пользователем;
  установка без новой гипотезы не повторяется.

## Алгоритм (шаг за шагом)

1. Проверить текущее состояние: `wsl --status`, `wsl -l -v`, `docker --version`,
   `docker compose version`, `Get-Service` по `WSLService`/`docker`/`vmcompute`.
2. Сверить требования Docker Desktop для этой версии Windows по официальной
   документации; записать вывод и дату.
3. Если WSL-компонент не установлен — передать пользователю **одну** точную команду
   PowerShell от администратора и объяснить причину требования прав. Не перезагружать
   автоматически.
4. После подтверждения выполнения — проверить результат, затем установить Docker
   Desktop официальным установщиком.
5. Проверить `docker info` и `docker compose version`; только после этого переходить к L03-02.
6. При недостижимости поддерживаемого пути — зафиксировать конкретную ошибку и
   предложить один поддерживаемый вариант; не повторять установку без новой гипотезы.

## Итог проверки 2026-09-13

Docker Desktop `4.90.0` установлен официальным установщиком через `winget` (exit 0),
запущен, движок отвечает. Дистрибутив `docker-desktop` создан и является дистрибутивом
по умолчанию; `wsl -l -v` в покое показывает `Stopped`, при этом `docker info` и
`docker ps` отвечают — состояние дистрибутива само по себе доступность движка не
доказывает, доказательство здесь — ответ `docker info`.

**Два наблюдения, требующие внимания на следующих шагах:**

1. **Редакция Home.** Windows 10 Home Single Language отсутствует в формальном списке
   поддерживаемых редакций Docker Desktop, но движок на ней поднялся, а источник
   допускает Linux-контейнеры для Home. Расхождение снято фактом, не толкованием.
2. **Место на диске.** Свободно C: 10.2 ГБ, D: 27.3 ГБ (до установки было 13.3 ГБ на C:).
   Слои образа `ghcr.io/activepieces/activepieces:0.86.3` по умолчанию лягут на C: —
   при нехватке места потребуется перенос data-root, а не удаление чужих файлов.

Docker Desktop запускается вручную и в автозапуск не входит: после перезагрузки ПК его
нужно поднимать заново. Соглашение Docker Subscription Service этим чатом не принималось
и не пересказывается.

подтверждаются официальным источником и датой.
