# L03-01 — Рабочая среда WSL/Docker и запуск стека Activepieces

**What to build:** Docker Desktop с Compose v2 работает на этой машине, `docker info` отвечает, и стек `services/activepieces` поднимается из закреплённого compose; либо зафиксирован конкретный внешний блокер и согласован поддерживаемый обходной путь.
**Requirement IDs:** R06; SC-06
**Blocked by:** none (внешняя предпосылка: права администратора и перезагрузка — действие пользователя)
**Status:** blocked
**Перед началом работы:** Открой `D:\SystemTheBest\System`, проверь корень Git и текущие изменения.

## Контекст

Текущая проверка 2026-09-13 подтвердила блокер фактами, а не предположением:
`wsl.exe --status` завершается с `Wsl/WSL_E_WSL_OPTIONAL_COMPONENT_REQUIRED`
(«требуется дополнительный компонент подсистемы Windows для Linux»), команда
`docker` не найдена (ENOENT), Docker Desktop не установлен. Служба `WSLService`
остановлена. Аппаратная виртуализация ранее подтверждена (`Firmware virtualization=True`,
`SLAT=True`), поэтому BIOS вслепую не перепроверяется.

Пользователю уже передавалась команда `wsl --install --no-distribution`; ответа о
выполнении нет. Повторно вслепую не просить: сначала проверить результат.

## План и неизвестное

- **Подтверждено:** Windows 10 Home Single Language `10.0.19045`, сессия без прав
  администратора. `wsl --status` → `WSL_E_WSL_OPTIONAL_COMPONENT_REQUIRED`;
  `docker` → ENOENT. Evidence — [activepieces-phase3-preflight-host-smoke-2026-09-13.json](../evidence/activepieces-phase3-preflight-host-smoke-2026-09-13.json),
  поля `environment.wsl` и `environment.docker`.
- **Предполагается:** включение компонентов Windows требует прав администратора и,
  возможно, перезагрузки. Только это действие остаётся за пользователем.
- **Основной путь:** WSL → Docker Desktop → Compose v2 → существующий pinned compose
  в `services/activepieces`. Не собирать Activepieces из исходников и не заменять
  стек имитацией ради обхода блокера.
- **Первая проверка:** выполнить `wsl --status` и `docker --version`; если компонент
  уже установлен, перейти к установке Docker Desktop. Перед установкой сверить
  актуальные официальные требования Docker Desktop к этой версии Windows
  ([Microsoft WSL basic commands](https://learn.microsoft.com/en-us/windows/wsl/basic-commands),
  [Docker Desktop Windows install](https://docs.docker.com/desktop/install/windows-install/)) —
  без опоры на память модели.
- **Рубеж пересмотра → альтернатива:** поддерживаемый Docker-путь не работает и после
  установки необходимых компонентов (например, Home-редакция без поддержки нужного
  гипервизора), либо требуется другая машина или платная среда. Тогда зафиксировать
  конкретную ошибку и один поддерживаемый вариант. Смена машины, платный доступ или
  смена архитектуры согласуются с пользователем; установка без новой гипотезы не повторяется.

## Входные/выходные данные

Вход: машина без WSL-компонента и без Docker. Выход: работающие `docker info` и
`docker compose version`, либо зафиксированный внешний блокер с точной командой
пользователю и названной причиной.

## Алгоритм (шаг за шагом)

1. Проверить текущее состояние: `wsl --status`, `wsl -l -v`, `docker --version`,
   `docker compose version`, `Get-Service` по `WSLService`/`docker`/`vmcompute`.
2. Сверить требования Docker Desktop для этой версии Windows по официальной
   документации; записать вывод и дату.
3. Если WSL-компонент не установлен — передать пользователю **одну** точную команду
   PowerShell от администратора и объяснить причину требования прав. Не перезагружать
   автоматически.
4. После подтверждения выполнения — проверить результат, затем установить Docker
   Desktop официальным установщиком.
5. Проверить `docker info` и `docker compose version`; только после этого переходить к L03-02.
6. При недостижимости поддерживаемого пути — зафиксировать конкретную ошибку и
   предложить один поддерживаемый вариант; не повторять установку без новой гипотезы.

## Критерии приёмки

- [ ] `docker --version` и `docker compose version` отвечают; `docker info` возвращает
      данные о работающем движке (не ошибку соединения).
- [ ] Фактическая версия Docker Desktop/WSL записана в отчёте с датой и источником.
- [ ] Если блокер сохраняется — записана точная команда ошибки, назван один следующий
      поддерживаемый шаг и согласованная альтернатива; статус остаётся `blocked`, не `done`.
- [ ] `docs/activepieces-setup.md` не содержит устаревшего рабочего пути `E:\System2`.
- [ ] SC-06 в части среды покрыт; сервисный функционал проверяет L03-02.

## Проверки

**Среда и предпосылки:** Windows 10 Home SL; действия с правами администратора выполняет пользователь.
**Команды:** `wsl --status`, `wsl -l -v`, `docker --version`, `docker compose version`, `docker info`.
**Ожидаемый результат:** каждое фактическое значение версии/ошибки доказывает состояние среды, а не намерение.
**Данные и наблюдение:** сырые выводы команд сохранять в evidence рядом с отчётом; секреты туда не попадают.
**Если проверка недоступна:** указать причину, оставить `blocked`; не объявлять `done`.

## Ограничения

Требуется реальный запуск Docker-движка на этой машине. Автоматическая перезагрузка,
обход прав и установка «по памяти модели» запрещены. Актуальные требования к ОС
подтверждаются официальным источником и датой.
