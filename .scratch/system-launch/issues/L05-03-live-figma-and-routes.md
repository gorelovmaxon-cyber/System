## Контекст

R11 требует, чтобы у разработки, сайтов и маркетинга были разные маршруты с общей
памятью. Маршруты — это `docs/routes/dev-workflow.md`, `sites-workflow.md`,
`marketing-workflow.md` плюс детерминированный селектор `scripts/memory/route.js`.
Критерий SC-14 (живая Figma) упирается во внешний доступ, которого у исполнителя нет.

## Покрытие критериев маршрутов (SC-15) — 2026-09-14

Сопоставление уже имеющихся доказательств с действующими критериями SC-15 — это и есть
критерии маршрутов dev/sites/marketing. Уже доказанное повторно не прогонялось.

| Критерий SC-15 | Чем закрыт | Состояние |
|---|---|---|
| Три примерных запроса выбирают верный маршрут | `route.js` на формулировках самого критерия: «добавь валидацию формы в проект X» → `dev`, «сделай лендинг для клиента N» → `sites`, «привлеки подписчиков на тему Y» → `marketing` | закрыт |
| Неоднозначный запрос → уточняющий вопрос | запрос без домена → `route: null`, «ambiguous; ask the user to clarify the domain» | закрыт |
| Каждый маршрут начинается с обязательных файлов и retrieval | `route.js` для всех трёх возвращает `core: [CLAUDE.md, HANDOFF.md if present, node scripts/memory/search.js]`; тот же шаг записан первым в трёх `docs/routes/*.md` | закрыт |
| dev-маршрут не тянет бриф сайтов и маркетинга | `docs/routes/dev-workflow.md:12-13` — дизайн сайта, маркетинг, публикация и расходы не добавляются без запроса | закрыт |
| Сложность соразмерна; публикация и бюджет не запускаются из одного анализа | во всех трёх `docs/routes/*.md` это записано отдельной строкой; в marketing реклама, публикация, бюджет и SEO требуют явного решения | закрыт |
| Клиентские данные не смешиваются, scope проекта соблюдается | живой прогон: тот же запрос с `--project systemqwen` → 3 записи, все `scope=systemqwen`; с `--project trading-dev` → **0 записей**; `--project` вне реестра → `unknown-project` до HTTP | закрыт |
| Gemini — внешний документ с источником и датой, API-интеграции нет | `docs/routes/marketing-workflow.md`, последний абзац | закрыт |
| route-доки связаны из start и system-workflow.md | `docs/system-workflow.md:176-178` — таблица с относительными ссылками; `start/SKILL.md:22-25` — домен и указание на `docs/routes/` | закрыт |

**Недостающее покрытие найдено одно и закрыто здесь.** Вторая половина первого критерия
— «находят релевантную память (поиск SC-05)» — до сих пор не проверялась: L05-03 проверял
выбор маршрута, L05-02 — живой поиск на своих трёх запросах, но не на маршрутных. Прогон
на живом Khoj (`ok:true`, без локального fallback) на формулировках-заглушках критерия:

| Запрос критерия | `--project` | Найдено |
|---|---|---|
| «добавь валидацию формы в проект X» | `trading-dev` | 2 записи, обе `scope=user`: `facts/projects-overview.md`, `nick-vels-autopilot-analysis.md` |
| «сделай лендинг для клиента N» | `site-portfolio` | 2 записи, обе `scope=user`: `nick-vels-autopilot-analysis.md` — одна и та же запись дважды |
| «привлеки подписчиков на тему Y» | `systemqwen` | 3 записи: `user-profile/work-patterns.md` и `nick-vels-autopilot-analysis.md` дважды |

Что это показывает и чего не показывает:

- **Поиск на маршруте работает живьём**: ответ `ok:true` без fallback, каждая запись со
  `source`, `scope` и `status_hint`, время — секунды. Общее ядро маршрута действительно
  получает контекст, а не только описано в документе.
- **Доменной памяти под эти запросы в общей памяти нет.** «проект X», «клиент N» и
  «тема Y» — заглушки без проекта, поэтому совпадения быть не может: в `.claude/memory`
  всего два scope — `systemqwen` (37 записей) и `user` (12); записей со scope
  `site-portfolio` или `trading-dev` не существует. Найденное имеет низкую релевантность
  (0.14–0.17) и к формулировке не относится.
- Значит, вторая половина критерия подтверждена **как механизм** — поиск на маршруте
  запускается и возвращает источник, scope и статус, — но **не как содержимое**: доменной
  памяти под маршрутные примеры пока нет. Это свойство наполнения памяти, а не дефект
  маршрутизации; на реальном клиентском проекте с собственной памятью оно проявится иначе
  и здесь не проверялось. Отдельным тикетом не оформляется, критерий закрытым не
  объявляется сверх сказанного.
- Разделение scope проверено отдельно и жёстко: тот же запрос с `--project systemqwen`
  даёт 3 записи `scope=systemqwen`, а с `--project trading-dev` — 0 записей. Записей
  клиентских проектов в памяти ещё нет, поэтому отсечение **чужих клиентских** данных на
  реальных данных не проверялось — названо прямо, а не выдается за проверенное.
