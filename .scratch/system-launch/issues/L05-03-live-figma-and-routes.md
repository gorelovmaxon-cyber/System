**What to build:** Проверить Figma MCP на реальном файле и nodeId и проверить, что маршруты разработки, сайтов и маркетинга действительно выбираются по SPEC R11. При отсутствии доступа зафиксировать точный незакрытый критерий, не покупать доступ и не выдавать fixture за живую проверку.
**Requirement IDs:** SC-14, SC-15; R11.
**Blocked by:** L05-01.
**Status:** awaiting-validation (маршруты проверены живьём 2026-09-14; живая Figma недоступна — нет ключа и макета)
**Перед началом работы:** Открой `D:\SystemTheBest\System`, проверь корень Git и текущие изменения.

## Контекст

R11 требует, чтобы у разработки, сайтов и маркетинга были разные маршруты с общей
памятью. Маршруты — это `docs/routes/dev-workflow.md`, `sites-workflow.md`,
`marketing-workflow.md` плюс детерминированный селектор `scripts/memory/route.js`.
Критерий SC-14 (живая Figma) упирается во внешний доступ, которого у исполнителя нет.

## Figma — что проверено и чего не хватает

Подтверждено отсутствие доступа, а не сделано предположение:

- `.claude/mcp-servers/figma/.env` и `.mcp.json` **отсутствуют** — есть только
  `.env.example` и `.mcp.example.json`; `FIGMA_*` в окружении не задан;
  `.gitignore:16` закрывает путь `.env`, поэтому ключа в репозитории нет и быть не должно.
- Локальный стенд MCP прогнан ранее в этой сессии: `npm test` в
  `.claude/mcp-servers/figma` → **7/7 pass, 0 fail, 1696 мс**, включая «real MCP client
  initializes, lists and calls the tool». Это проверка кода на fixture, **не** живая
  проверка Figma.

**Незакрытый критерий SC-14 формулируется точно:** не подтверждён вызов настоящего
Figma API по реальному файлу и `nodeId` с реальным ключом — получение узлов, ссылок и
изображений из живого документа, а также поведение при истёкшем ключе и при отсутствии
доступа к файлу. Fixture 7/7 этого не доказывает и за live не выдаётся.

**Что требуется от пользователя, чтобы закрыть:** ключ Figma и ссылка на реальный файл
плюс `nodeId`. Ключ вводится локально в `.claude/mcp-servers/figma/.env` по
`.env.example`, в Git не попадает. Доступ не покупается.

Селектор запускался на реальных формулировках задач, не на заглушках:

маршрут, а возвращает явный отказ — это соответствует правилу `start/SKILL.md`
«если сигналы равны или отсутствуют, задай уточняющий вопрос».

Минимальные реальные задачи, а не три продукта: dev-маршрут фактически пройден на

маршрута, а не отчёт о нём. Содержание трёх документов сверено с R11: у каждого есть

публикация, домен, реклама, бюджет и платная аналитика не запускаются автоматически.
