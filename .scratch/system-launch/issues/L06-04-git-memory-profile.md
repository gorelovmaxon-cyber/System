## Факты и первая проверка

save.js уже вызывает writer напрямую; sync.js уже умеет --status и --push и проверяет SHA назначения. --status не делает fetch. bootstrap.js сейчас безусловно устанавливает hooks, doctor.js требует AP и hooks. Простое выключение Docker оставит несовместимые запуск и диагностику. Проверить эти точки и фактический hooksPath до изменения. Не считать названные ниже новые настройки существующими CLI-флагами.

## Что изменить

1. Ввести один явно документированный основной профиль локальной памяти/Git в существующую конфигурацию. Прочитать resolve-paths.js и init-local-config.js: обновление существующего local config должно сохранять ключи и привязки, не требовать пересоздания файла. Отсутствующий старый параметр мигрировать предсказуемо, не включать AP неявно. Сохранить явный необязательный профиль AP.
2. bootstrap в основном профиле не запускает Docker и не устанавливает захват очереди. Миграция отключает только принадлежащий System2 захват на этой машине и в реально подключённых проектах, сохраняя посторонние hooks. Учесть эффективную global/local настройку и .git/hooks, а не только удалить одну строку config. Повторный bootstrap не возвращает захват. Если есть workers — штатно остановить только установленные процессы System2. Старые события сохранить как неактивную историю, не удалять и не помечать delivered. Текущие состояния читать через API очереди, не считать строки JSONL.
3. doctor проверяет выбранный профиль: конфигурацию, доступность путей/записи, нужные зависимости и отсутствие активного старого захвата. Неактивные интеграции показывать как disabled, а не проверенные healthy. Для включённых интеграций ошибки оставлять видимыми; локальное ядро и интеграции различать. Локальный save/search должны работать при выключенных bridge/Khoj/AP; проверить существующий fallback, не писать второй поисковик.
4. В действующие правила завершения работы встроить: полезное знание → save.js → чтение результата → соразмерная проверка → scoped commit → sync.js --push → verified:true. При повторе одного сохранения использовать прежний event_id и содержимое; конфликт не трактовать как успех. Отсутствие нового знания нормально. Память не требует отдельного платного анализатора. При включённом Khoj использовать существующее обновление индекса; при выключенном не запускать постоянные попытки индексации, не заявлять indexed. Локальный поиск должен видеть сохранённый файл независимо от индекса.
5. Перед публикацией refresh remote, проверить ветку/upstream и исходящий диапазон; грязные чужие файлы сохранить. При расхождении — остановить публикацию, сохранить обе версии, дать конкретный следующий шаг; обычный отказ push безопасен. Использовать существующий sync.js, минимально исправить только воспроизведённый пробел. Не создавать daemon, GitHub Actions, watcher или автопереписку чатов. Прямо назвать исполнителя владельцем публикации на границе блока и перед сменой ПК.
6. Согласовать текущие SPEC/затронутые SC-критерии, инструкции запуска/переноса, правила памяти и навыки, которые реально управляют завершением задачи. Ссылаться на один основной порядок в docs/system-workflow.md вместо копирования его во все навыки. Прежнее каноническое решение об остановках/публикации исправлять адресно через supersedes, если оно реально противоречит новому решению. Историю приёмки не переписывать.

## Критерии и достаточные проверки

- Регрессии на новый/существующий config, повторный bootstrap без возвращения hooks, сохранность чужого hook и profile-aware doctor. Точные команды выбрать по существующему test runner; новые тесты создать только для изменённого поведения.
- Один изолированный сценарий: кириллица с известным источником → save → повтор того же event_id/данных без дубля → локальный поиск с правильным scope/источником. Исходный текст и прочитанный должны совпасть, без U+FFFD. Тестовые знания не засоряют каноническую память.
- Один реальный scoped-коммит этого блока при неактивном AP: не добавляет событие в старую очередь и не создаёт новую память из факта коммита. Сравнить состояния до/после. Не запускать дополнительные коммиты ради повторной проверки.
- Обычный push согласованной ветки: подтверждён destination SHA. Отказ сети/расхождение проверить локально через временный Git remote или существующие тесты, не ломая рабочее подключение. Проверить, что нет ложного сообщения «опубликовано».
- Обновлённые runbooks содержат реальные проверенные команды без обязательного Docker. git diff --check и проверка изменённых ссылок. Если общие primitives не менялись, полный аудит и полный исторический набор не нужны.
