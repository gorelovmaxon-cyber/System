# PROC-02 — Границы задания и повторных возвратов для планировщика

**What to build:** Свод правил, по которому планировщик (Astra или выбранная модель)
составляет задания для Sonnet/Sol и ведёт повторные возвраты блока: доказываемая граница
приёмки до работы, разбор причины повторения, доказательства по риску, объём списка
чтения и один адрес отчёта.
**Requirement IDs:** R01, R12 (SC-01); дополняет PROC-01
**Blocked by:** PROC-01 (принят)
**Status:** awaiting-review
**Перед началом работы:** корень `D:\SystemTheBest\System`, HEAD после `8c822b1`.

## Контекст

По обзору фазы ремедиации блока writer (`.scratch/system-remediation/issues/SUMMARY.md`)
блок прошёл шесть раундов приёмки (R, S, T, U, V/G15, W1) — пять отклонений на одном
блоке, каждый раунд с воспроизведённым дефектом. Числа затрат взяты из отчётов той фазы
и отдельно не перепроверялись. Форма задания при этом умножала работу: несколько
прогонов полного набора, повторяющиеся harness, обновление шести документов на один
фикс, разросшиеся тикеты.

## Критерии приёмки

- [x] Правила не противоречат `docs/system-workflow.md` и дополняют, а не заменяют его.
- [x] Точка входа планировщика (CLAUDE.md, шаблон тикета) ссылается на свод.
- [x] Обязательное требование нигде не ослабляется ради закрытия блока; повторная
  проверка исправленного дефекта прямо разрешена.
- [x] Относительные ссылки разрешаются; `git diff --check` проходит.
- [x] Код, сервисы, hooks, конфиги и память не затронуты.

## Проверки

`git diff --check`; обход относительных ссылок изменённых файлов; чтение изменённых
разделов. Полный набор тестов ядра не запускается: исполняемый код не меняется.

## Ограничения

Это проверка согласованности инструкций, не live-тест. Действие правил на практике
подтверждается следующими заданиями, а не этим коммитом.

## Доработка после независимой проверки — 2026-09-13

Проверяющий вернул документ на доработку: правила были сформулированы категоричнее, чем
следует, и в одном месте могли работать против обязательного требования.

| Было | Стало |
|---|---|
| «Второй возврат означает, что дело не в исполнителе» | Сигнал установить причину повторения, без выводов о виновности |
| Обязательно другой механизм либо остаточный риск | Сначала разбор причины; обязательное требование не ослабляется ради завершения |
| «Почини инструмент» безусловно | Исправление, если польза оправдывает затраты и изменение входит в задачу; иначе короткий документированный обход |
| Порог чтения «примерно 50 КБ» | Порог убран как необоснованный; сокращается повторное и нерелевантное чтение, нужный контекст сохраняется |
| «Среду готовит тот, кому она нужна» | Один назначенный ответственный, циклических зависимостей нет; подготовка другим исполнителем допустима |
| «Живое наблюдение и негативный сценарий» для интеграций | Проверки по риску; интеграция тоже может затрагивать гонки, потерю данных и изоляцию |
| Соседняя находка всегда отдельная задача | Отдельная, если не нарушает критерии блока и не вызвана его изменениями |
| Третий раунд запрещён | Запрещены повторы тех же проверок без изменения кода, требования или инварианта; проверка исправления — новое основание |

Дублирование с разделом «Короткий план для исполнителя» сокращено: состав задания,
экономия чтения и общая сверка перед передачей остаются в `docs/system-workflow.md`,
в своде — только граница приёмки, цена доказательств и порядок возвратов. Проверки
доработки: `git diff --check`, чтение изменённых разделов, обход относительных ссылок.
