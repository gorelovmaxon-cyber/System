# Оставшаяся работа: память и Git без обязательного Docker

Статус: план, реализация не выполнена. Основание — решение пользователя 2026-09-23 перейти к обмену через GitHub из-за проблемы Docker на втором ПК. Этот документ задаёт новый порядок оставшейся части фаз 6–7; принятые фазы не переоткрываются.

## Целевой результат

Пользователь → Astra уточняет задачу → один Sonnet выполняет → проверяет по риску → сохраняет полезное знание через существующий writer → обновляет короткую передачу → делает scoped commit и обычный push. На другом ПК исполнитель получает изменения и продолжает по актуальным файлам. GitHub хранит переносимую память и код, но не заменяет writer, локальное окружение или резерв секретов.

«Автоматически» здесь означает обязанность работающего исполнителя публиковать проверенный блок и передачу без нового вопроса о каждом push. Это не служба 24/7, не выгрузка каждого изменения файла и не автоматическая доставка сообщения в другой чат. При закрытом исполнителе публикации нет. Astra получает конкретный опубликованный SHA и короткий отчёт через пользователя либо доступное чтение репозитория; возможность чтения приватного GitHub в каждом клиенте нельзя предполагать.

Docker/AP, контейнерные volumes и post-commit-анализ сырых событий исключаются из обязательного профиля. Код остаётся как неактивная интеграция. Khoj сохраняется полезным необязательным поиском: без него обязателен локальный поиск с источниками. Bridge не требуется для локального save.js; нужен только использующему его клиенту. Не удалять работающие установки ради упрощения.

## Договор экономии и сохранности

- Чтение: своё задание, актуальная шапка HANDOFF, docs/system-workflow.md и непосредственно затронутые файлы. Исторические аудиты — только по конкретной ссылке при необходимости.
- Перед началом — состояние дерева и свежий remote; чужие изменения не включать. Проверять процессы только если они нужны текущему действию.
- Исполнитель формулирует знания из контекста задачи; не пересказывает каждый коммит в память. Источник, scope и степень подтверждения обязательны. Исправления прежних решений — через предусмотренное supersedes, а не новая противоречащая «истина».
- Обычный scoped commit/push согласованы. Публикуется весь фактический исходящий диапазон: перед push проверить и ранее неопубликованные коммиты. Секреты, локальные пути/конфиги, журналы и backup вне Git. Не применять git add ., force, reset --hard, автоматический stash или молчаливое разрешение конфликта.
- Нет сети — сохраняется локальный коммит, явно сообщаются SHA и «не опубликовано»; повтор при следующей рабочей границе. Нет бесконечного polling и повторных платных анализов.
- Документы: diff/check и ссылки. Изменённое поведение: целевые регрессии и один ограниченный smoke. Общие writer/queue/locks менять только по воспроизведённой необходимости, тогда один соответствующий полный прогон. Старые evidence остаются действительными для неизменившихся частей.
- При повторении ошибки без новой проверяемой гипотезы — краткая передача Astra через пользователя: ожидание, факт, команды/ошибка, попытки и вопрос. Не ослаблять обязательное требование и не запускать новую оркестрацию.
- U+FFFD остаётся известным дефектом до отдельного доказанного исправления. Новый режим должен сохранять новую кириллицу точно. Если это не так — конкретный блокер; не выдавать отключение AP за исправление кодировки.

## Приёмка без подмены результата

Обязательны: рабочая локальная запись и поиск без AP, отсутствие самозапуска старого конвейера, безопасный Git-обмен на настоящих двух машинах, restore актуальной памяти в отдельный каталог, понятная передача следующему исполнителю. persisted, indexed и опубликовано — разные состояния. Старые AP-проверки исторически действительны, но не являются обязательными для нового профиля. Figma остаётся исключённой по прежнему решению.
