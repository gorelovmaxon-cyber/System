## Свои тикеты

L04-01 (SC-07/11): подключить один контролируемый проект: registry/local_paths, действующий hook без потери пользовательского hook, обычный commit → ровно одно durable-событие. Сначала выяснить effective hooksPath; не менять его принудительно ради зелёного doctor. Подключение настоящей памяти выполняется по принятому рубежу и с действующим backup; не мигрировать все старые каталоги.

L04-02 (SC-08/09/10): провести один настоящий event → AP AI → bridge → writer → indexer → Khoj search → Git. Использовать осмысленное решение проекта, track event_id и состояния. Новая запись видна при отдельном следующем запросе/сессии. Существующая writer-запись годится для smoke, но не доказывает весь новый цикл.

L04-03 (SC-10/17): точечно проверить повтор, один обрыв до acknowledgement, перезапуск получателя и отказ Khoj с восстановлением. Определить реальные ограничения watch: bounded window, hook --no-revive. Если заявляется доставка после длительного простоя без нового commit, нужен проверенный явный повторный запуск, например локальный планировщик. Не добавлять бессрочный оркестратор без необходимости.

## Готово, когда

Есть один коррелированный live-трейс и конкретные результаты восстановления, без ложного indexed/synced и без дубля. При падении производного индекса память сохраняется, после восстановления запись находится. Реальный live-сбой — небольшой отдельный тикет и нужная регрессия, а не повтор общего аудита.

Сохранить один компактный evidence с event_id, шагом, результатом, временем и SHA; содержимое ключей и чувствительных AI-запросов не публиковать. Отчёт reports/CHAT-04-RESULT.md: какие R06/R07/R08/R05 закрыты live, какие нет. В конце scoped-коммиты/push; исходящий push проверить по remote SHA.
