## Общий договор каждого чата

1. Работа в D:\SystemTheBest\System. Прочитать своё задание, этот договор, актуальную верхнюю секцию HANDOFF.md и отчёт непосредственного предшественника. HANDOFF-GPT-NEXT-2026-09-12.md читать выборочно: разделы 1, 5, 8 и раздел 6 своей фазы. Не перечитывать всю историю аудитов и все тестовые логи.
2. В начале проверить git status, HEAD, remote и реальные процессы. Предыдущий PID, лог или статус документа не доказывает, что сервис сейчас работает. Не менять чужой грязный код; сначала установить его происхождение и сохранить.
3. Самостоятельно уточнить и выполнить 1–3 небольших тикета своей фазы. Существующие SC/FIX/PUB не дублировать: связать дочерние задачи с ними. Закрытые F01–W1 не переоткрывать без воспроизведённой регрессии. Файлы новых задач — .scratch/system-launch/issues/; имена начинаются L01-, L02- и т.д. по номеру чата. Новый дефект — конкретное воспроизведение, затем необходимый фикс и регрессия.
4. Разрешение пользователя на запуск сервисов, необходимые исправления, коммиты и обычный push уже есть. Не спрашивать «коммитить ли?». Прежде чем установить уже имеющийся компонент или создать аккаунт, проверить состояние. Admin/UAC, перезагрузка, реальный внешний доступ, выбор платного подключения могут потребовать действия пользователя; спросить только то, без чего нельзя продолжить. Не выполнять автоматическую перезагрузку, покупку или неограниченный расход API.
5. Не применять force push/reset --hard и очистку чужих worktree. Секреты/config.local/.env/.local остаются вне Git; не печатать их. Сервисный процесс запускать скрыто, с логом и способом штатной остановки. Не запускать второй pip/service поверх первого.
6. Код и подтверждающий тест — scoped-коммит; отчёт можно включить вместе, если он относится к тому же изменению. Не создавать отдельные коммиты на каждую косметическую правку отчёта. Публиковать завершённую фазу обычным push с проверкой remote SHA, после сохранения runtime отдельно. Push не означает READY.
7. Проверки соразмерны. Документация не требует полного набора 152 тестов. Изменённый адаптер — его проверки плюс живой smoke. Изменённый общий primitive/queue/writer — затронутые регрессии и полный набор. Повторять полный набор без новой причины не нужно. Старые пробы могут перезаписывать evidence и имеют разные значения exit code.
8. Один краткий итог .scratch/system-launch/reports/CHAT-NN-RESULT.md: base/final SHA; тикеты; что реально работает; команды и результат; где evidence/локальные логи/backup; нерешённые вопросы; ровно следующий шаг. Без секретов. HANDOFF.md дополнить только краткой актуальной записью и ссылкой. Не копировать один отчёт в пять матриц: текущая фаза обновляет только затронутые строки.
9. Рабочие статусы: implemented, verified-local, verified-live, blocked; финальную независимую READY исполнитель сам себе не ставит. Уже принятую локальную Фазу 1 пересматривать не надо. Финальная независимая оценка — ограниченная проверка новых live-доказательств, не новый общий аудит.
10. После отчёта и сохранения фазы остановиться на её границе; следующую фазу выполняет новый чат. Если блокировка, сохранить достигнутое, не выдавать частичное за завершённое.

## Текущие решения пользователя

Khoj помогает искать историю, но не заменяет прямое чтение задачи, HANDOFF, обязательных правил и актуального кода. Поиск при новой задаче/существенном новом вопросе, не один и тот же запрос каждый ход. Пустая выдача не доказывает отсутствие информации; даты, источники и scope обязательны для оценки актуальности. Экономию измерять, не обещать проценты заранее.

Старые Opus → Sonnet-нарезчик → Luna и ручные остановки после каждого тикета не отражают последнее направление пользователя. Уточнение ролей — чат 5. Swarm, плагины из видео, skill-forge, бесконечная самооценка и необязательная архитектурная реформа в эти фазы не входят.
