# Задание локальному исполнителю на первом ПК (ноутбук): закрыть обмен с вторым ПК

Одна страница, без чтения переписки. Задание выполняет исполнитель **на ноутбуке**
(`DESKTOP-BUGF4FI`, рабочая копия `D:\SystemTheBest\System`). Всё, что нужно, есть в этом
файле; второй ПК свою половину уже сделал и опубликовал.

**Зачем.** Обмен через Git проверен 2026-09-15 только со стороны второго ПК: встречную
сторону исполнял временный клон на той же машине. Это доказывает механику, но не участие
настоящего первого ПК. Пока ноутбук сам не сделает `pull` и `push`, фраза «обмен работает
в обе стороны между машинами» доказана наполовину. Этот файл закрывает вторую половину.

**Что запрещено на любом шаге:** `git push --force`, `git reset --hard`, `git clean -f`,
`git pull --rebase`, удаление `.local/`. Если конфликт непонятен — остановиться, сохранить
оба варианта и передать вопрос пользователю. Секреты (токены, ключи, `.env`) в этот файл
не вписывать.

## Короткая передача ноутбуку (актуально 2026-09-21)

Слот ноутбука ниже всё ещё пуст, отметки `SYSTEM2-EXCHANGE-BUGF4FI-…` в `origin/master`
нет. На `DESKTOP-BUGF4FI` нужно: убедиться, что дерево чистое; выполнить шаги 1–5 ниже;
изменить только «Слот первого ПК»; сделать обычные commit и push без rebase/force; прислать
SHA из `git log -1`, совпадающий с `git ls-remote`, и текущий `queue-status.js`. После этого
второй ПК сделает обычный pull и сверит отметку. Docker для этого задания не нужен.

## Шаги

Перед началом: ноутбук должен уметь ходить в `origin`
(`https://github.com/gorelovmaxon-cyber/System.git`). Пароль/токен в чат не пересылать.

### Шаг 1 — снять состояние до изменений (только чтение)

```powershell
Set-Location D:\SystemTheBest\System
git remote -v
git branch --show-current
git log -1 --format='%H %ad %s' --date=iso
git config --get core.hooksPath
git status --short
git fetch origin
git log --oneline --left-right HEAD...origin/master
```

Ожидаемое: `origin` — тот же репозиторий, ветка `master`. Строки `HEAD...origin/master`
показывают расхождение в обе стороны; сохранить их как есть, **в том числе если они
непустые**. Если рабочее дерево не чистое — не коммитить поверх: сохранить вывод
`git status --short` и остановиться, это отдельное решение.

### Шаг 2 — принять опубликованное вторым ПК (направление второй ПК → ноутбук)

```powershell
git pull --no-rebase origin master
```

`--no-rebase` — не украшение: rebase переписывает локальные коммиты ноутбука, а обмен
обязан сохранить обе стороны. При расхождении получится merge-коммит с двумя родителями —
это правильный результат, а не ошибка.

Ожидаемое: в дереве появился файл `.scratch/system-launch/CHAT-06-LAPTOP-TASK.md` и в нём
заполнен слот второго ПК с отметкой `SYSTEM2-EXCHANGE-NCLRFDV`. Проверить:

```powershell
Test-Path .scratch\system-launch\CHAT-06-LAPTOP-TASK.md
Select-String -Path .scratch\system-launch\CHAT-06-LAPTOP-TASK.md -Pattern 'SYSTEM2-EXCHANGE-NCLRFDV'
```

Если файла нет — pull не дошёл, дальше не идти.

### Шаг 3 — заполнить свой слот в этом же файле

Редактировать **только** раздел «Слот первого ПК» в конце файла. Значения — фактический
вывод команд, а не пересказ. Если что-то из перечисленного недоступно (например сервисы
не подняты) — так и написать, а не оставлять пустым.

Отметка первого ПК — строка вида `SYSTEM2-EXCHANGE-BUGF4FI-<первые 12 символов HEAD>`;
она должна быть уникальной и её не должно быть у второго ПК.

### Шаг 4 — опубликовать (направление ноутбук → второй ПК)

```powershell
git add .scratch/system-launch/CHAT-06-LAPTOP-TASK.md
git status --short                 # в индексе только этот файл
git commit -m "L06-02: первый ПК подтверждает обмен (слот в задании обмена)"
git push origin master
```

Ожидаемое: push принят без `--force`; в выводе видно `... -> master` (fast-forward или
merge, но не `forced update`). Если push отклонён как non-fast-forward — сделать
`git pull --no-rebase origin master`, разрешить, повторить push. Force не применять.

### Шаг 5 — записать доказательства

Вписать в свой слот фактические выводы шагов 1–4. После push дополнительно:

```powershell
git log -1 --format='%H %s'
git log --oneline --left-right HEAD...origin/master
git ls-remote origin refs/heads/master
```

`git ls-remote` должен показать **тот же** SHA, что `git log -1` — это и есть доказательство,
что коммит ноутбука действительно лежит в `origin`, а не только локально.

## Ожидаемый результат задания

1. На ноутбуке есть файл, добавленный вторым ПК, — направление второй ПК → ноутбук
   подтверждено фактическим `pull`.
2. В `origin` есть коммит ноутбука, и это подтверждено `git ls-remote` — направление
   ноутбук → второй ПК подтверждено.
3. Слот первого ПК заполнен фактическими значениями (HEAD, hooksPath, состояние очереди,
   вывод push).

Прислать (текстом, без секретов):

| `git log -1 --format='%H %ad %s' --date=iso` до шага 2 | шаг 1 |

Про очередь: на ноутбуке hooks включены, поэтому коммит шага 4 породит событие. Если стек
Activepieces там сейчас не запущен (Docker Desktop не в автозапуске), событие останется в
очереди как `failed` — это ожидаемо и допустимо, это и есть смысл durable-очереди.
**Массовый `--redeliver` не запускать**: повторная доставка — отдельное решение пользователя.
Достаточно привести вывод `queue-status.js` как есть.

## Границы

- Задание закрывает **участие ноутбука в обмене**. Оно не закрывает установку Docker на
  втором ПК, не поднимает Activepieces и не проверяет его flow — это отдельная работа.
- Второй ПК после ответа ноутбука сделает свой `pull` и сверит отметку; до этого обмен
  считается подтверждённым на одну сторону.
- Файл остаётся в репозитории как журнал обмена: обе отметки — доказательство, а не мусор.
