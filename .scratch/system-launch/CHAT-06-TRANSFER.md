Работай на реальном втором ПК E:\SystemTheBest\System после опубликованного [чата 6A](CHAT-06A-GIT-MEMORY.md). Прочитай [новый план](PLAN-GIT-MEMORY-2026-09-23.md), актуальную шапку HANDOFF, reports/CHAT-06A-RESULT.md и незакрытые критерии существующих L06-01…03. Ниже сохранено первоначальное задание для истории; обязательства Docker/AP/hooks заменены новым профилем, не исполнять их по старому тексту.

1. **L06-01 — сохранить локальное и получить новую версию.** Установить фактический путь, HEAD, дерево и remote. Не клонировать поверх существующей копии. Сохранить незакоммиченное, локальные конфиги/секреты и необходимые журналы отдельно от Git; использовать имеющийся проверенный backup, дополнив только изменившееся. Если дерево позволяет — fetch и безопасный fast-forward. При расхождении сохранить обе версии и разбирать только конфликт. Не переустанавливать уже работающие зависимости, не заниматься Windows recovery/Docker.
2. **L06-02 — применить основной профиль.** Использовать уже реализованные команды чата 6A, не угадывать флаги. Подтвердить, что bootstrap не устанавливает старый захват, а существующий System2 hook выключен также в реально привязанных проектах. Не трогать чужие hooks. Уточнить только неоднозначные local_paths: E:\dev не считать автоматически trading-dev. Если проект фактически не нужен на ПК, согласовать и явно пометить непривязанным, не придумывать путь и не объявлять его рабочим. Проверить doctor и локальные save/search без AP. Включённый Khoj проверять только по необходимости обновления, сохранённые доказательства неизменившегося поиска не повторять.
3. **Довести реальный обмен вместо повторения готового.** В [задании ноутбуку](CHAT-06-LAPTOP-TASK.md) уже есть свидетельства ответа ноутбука, включая маркер SYSTEM2-EXCHANGE-BUGF4FI-ee706bc3fc60. После fetch проверить наличие соответствующего коммита/маркера на ПК и зафиксировать это. Для нового режима один полезный реальный результат ПК сохранить через writer и опубликовать, без выдуманных тестовых правил в общей памяти. На ноутбуке пользователь передаёт короткое действие: сохранить локальные изменения, получить опубликованный коммит, найти именно эту запись локальным поиском и вернуть SHA/источник. До ответа не объявлять проверенным получение новой памяти на ноутбуке. Если эквивалентный сценарий уже доказан после чата 6A, сослаться на него без нового прогона. Конфликт обеих версий проверить в изолированных клонах/локальном remote или использовать подходящее прежнее evidence; не создавать искусственный конфликт в master.
4. **L06-03 — restore обязательного локального состояния.** Использовать имеющийся пакет и manifests, определить дельту с момента его создания. Резерв должен покрывать каноническую память, переносимые настройки и необходимые для идемпотентности журналы writer; локальные секреты хранить отдельно с ограниченным доступом. Различать восстанавливаемые данные и производный индекс. Восстановить в отдельный каталог на ПК, без перезаписи рабочей копии. Сверить hashes и проверить чтение/поиск восстановленной памяти; повтор сохранения с тем же event_id не должен создавать дубль (проба только в изолированной восстановленной копии). Если инструмент обращается к рабочему data_dir, сначала исправить изоляцию, затем запускать. Старую очередь хранить как неактивную историю без redeliver; AP flow/volume restore исключён, не отмечать его выполненным. Индекс Khoj восстанавливать/перестраивать только если включён в проверяемом профиле.

Один отчёт reports/CHAT-06-RESULT.md с новым датированным итогом и ссылками вместо переписывания истории. Согласовать изменённые критерии L06-01…03 с SPEC, сохранив выполненные evidence; не переименовывать старые успешные прогоны. Приложить команды, машины, SHA обмена, manifest/результат restore, открытые local_paths и ограничения. Коммит/push без нового согласования; проверить remote SHA. Документный коммит не порождает следующую запись памяти. Независимая приёмка — в чате 7 одним пакетом; готовность исполнителя awaiting-review. Нет доступа — точный пакет следующему оператору, не имитация второй машины.

## Свои тикеты

L06-01 (SC-13): подготовить безопасный перенос. Получить фактический путь и git status второго ПК; сохранить его незакоммиченные файлы, memory/runtime и локальные конфиги до pull/clone. Git переносит код и каноническую Markdown-память, не локальные ключи. Не копировать конфиги первого ПК поверх второго вслепую, не использовать reset --hard. Если доступа ко второму ПК нет — сделать конкретный пакет команд/проверок для пользователя; нельзя объявить drill выполненным по локальному fresh clone.

L06-02 (SC-12/13): на втором ПК выполнить bootstrap, local binding, запуск нужных сервисов/клиента, hooks и поиск известной записи. Проверить согласованный сценарий возвращения изменения через Git и конфликта без force/потери обеих версий. Сохранять одну каноническую копию памяти на каждой машине, не превращать локальный lock в сетевую блокировку общей папки.

L06-03 (SC-17/R13): restore backup в отдельный каталог/среду, сверка целостности памяти, состояния очереди и восстановления производного индекса. Восстановление AP flow/данных — по проверенному экспорту/резерву. Не удалять единственную рабочую БД/volume для проверки. Если пользователь хочет перенести старую настоящую память: сначала конкретная инвентаризация источников и проверка коллизий, backup, план объединения; не предполагать разрешение на уничтожение старой копии.
