## Что НЕ подтверждено — и почему

| Пункт | Состояние | Чего не хватает |
|---|---|---|
| Стек Activepieces, `/api/v1/health` | не поднимался | WSL 2.7.14 и Docker Desktop 4.91.0 уже установлены; нужна ручная перезагрузка и запуск Docker Desktop |
| Импорт flow и локальный `WEBHOOK_ID` | не выполнялись | то же; `.env` Activepieces уже создан и заполнен локально |
| Hooks включены, доставка события и сохранение результата | не выполнялись | того же: получатель событий должен быть готов до `install-hooks.sh` |
| Восстановление AP flow/volume из резерва | не выполнялось | того же; единственный рабочий volume не удалялся |
| Обмен **с настоящим ноутбуком** | подтверждён с одной стороны | ноутбук должен выполнить [CHAT-06-LAPTOP-TASK.md](../CHAT-06-LAPTOP-TASK.md) и запушить свой слот |
| `local_paths` трёх проектов | остаются заглушками | пользователь должен назвать соответствие каталог → проект |

Это не «зелёная приёмка с оговорками», а прямое перечисление: пять пунктов ждут **внешнего
действия**, а не доработки кода. Ни один из них не отмечен выполненным.

## Что приёмщик может перепроверить сам

Ничего разрушительного; все команды читающие.

```powershell
Set-Location E:\SystemTheBest\System

# Khoj и bridge в Windows-версии в автозапуск не входят: перед doctor их нужно поднять,
# иначе он даст PROBLEM ещё и по ним. Запуск — два отдельных окна:
#   node scripts/memory/bridge-server.js
#   & E:\SystemTheBest\runtime\khoj-1.42.10\Scripts\python.exe services\khoj\run-local.py

git log -1 --format='%H %ad %s' --date=iso      # ожидается коммит этого пакета
git status --short                              # ожидается пусто
node scripts/memory/sync.js --status            # ahead/behind, clean
node scripts/memory/queue-status.js             # ожидается 0 событий — hooks выключены
node scripts/memory/doctor.js --json            # PROBLEM ровно по hooksPath и Activepieces
                                                # (при неподнятых сервисах — ещё Khoj и bridge)
node scripts/memory/project-id.js               # systemqwen
node scripts/memory/project-id.js E:\dev        # project_id cannot be determined — это верно

# пакет сохранения и drill (каталоги вне репозитория, только чтение)
Get-ChildItem E:\SystemTheBest\transfer-backups\second-pc-20260915-191058
Get-ChildItem E:\SystemTheBest\transfer-backups\restore-drill-second-pc-20260915-164123
```

Сверка SHA-манифеста пакета воспроизводится скриптом
[l06-03-restore-drill-second-pc-2026-09-15.cjs](../evidence/l06-03-restore-drill-second-pc-2026-09-15.cjs)
идемпотентно: он копирует пакет в новый каталог и не трогает живую память.

## Границы приёмки

- **Figma исключена** из объёма решением пользователя 2026-09-14 — это «исключено», а не
  «проверено».
- **Дефект `U+FFFD` в записях цикла остаётся открытым** и не должен исчезнуть из отчёта:
  перенос на другой ПК его не исправляет, причина не установлена.
- Сервисы на втором ПК **не запущены** на момент публикации: bridge и Khoj в Windows-версии
  в автозапуск не входят, их поднимают вручную (`bridge-server.js`, `run-local.py`).
- Приёмка фазы 6 не означает приёмку фазы 7: фаза 7 не начиналась.
