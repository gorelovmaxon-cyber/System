## Исправить первым: ошибка самой пробы

В `evidence/activepieces-phase3-preflight-2026-09-13.json` — `checks:{}` и ошибка hash. Это **не успешный smoke**. Проба остановилась **до любого POST**: авторизация `/write` и replay не проверены.

Причина сверена: проба хэширует `JSON.stringify({event_id, proposals})`, а `scripts/memory/writer.js`, функция `proposalHash`, хэширует `JSON.stringify({eventId, proposals})`. Поле HTTP-запроса остаётся `event_id`; контракт writer менять нельзя. `proposalHash` сейчас не экспортируется — не вызывать несуществующий export.

1. Исправить формулу **в пробе**, сверить нормализованные proposals по writer.
2. Сохранить проверку совпадения с persisted-событием **до POST**. Не отключать assert, не менять основную память/журнал ради зелёного теста. При новом несовпадении установить расхождение; если безопасный replay доказать нельзя, использовать отдельную fixture с памятью/журналами/портом.
3. Проба перезаписывает фиксированный JSON. До повторного запуска добавить `--output` с отказом перезаписи существующего файла (**создать в этой доработке**). Сохранить неуспешное evidence; не плодить копии пробы и ручные обходы её вывода.
4. Проверить таймауты внешних HTTP/команд и честный exit code. Ошибка harness не является дефектом production-кода.

## Вход, выход и достаточная приёмка

Вход — SC-07 event: `event_id`, зарегистрированный `project_id`, `kind` и контекст события. AI возвращает `has_pattern:boolean`, `proposals:array`; валидация до writer. Реальный sync endpoint возвращает `{event_id,status:"persisted"}` либо `{event_id,status:"no-pattern"}`. Ошибка/таймаут/некоррелированный 2xx не подтверждает сохранение.

- [ ] Манифест двух сохранённых конфигов проверен; перед публикацией отдельно сохранён фактически изменённый ignored runtime. Наличие backup-каталога не равно проверке восстановления.
- [ ] `docker info` и Compose работают, pinned образ реально загружен. App **и worker**, Postgres/Redis готовы; owner/flow и данные сохраняются после restart.
- [ ] Контейнер, **исполняющий flow**, достигает bridge; отсутствие/неверный token даёт отказ без записи. Host health эту границу не доказывает. При изменении bind выбрать минимально необходимый адрес/маршрут, сохранить аутентификацию, не открывать сервис произвольно всей сети.
- [ ] Ограниченный явный AI-сценарий в настоящем AP даёт валидированные proposals и persisted через writer. Ветка no-pattern проверена без writer. Для детерминированной проверки веток можно использовать отдельный input, но он не заменяет реальный AI-вызов. Провайдер/модель/connection — разрешённые; при отсутствии запросить только недостающий выбор/доступ, ключ вводится локально.
- [ ] Отправитель получает sync ack с тем же `event_id`; подтверждены реальный HTTP-ответ и AP run, а не только лог шага/generic webhook 2xx.
- [ ] Повтор события не создаёт дубля и имеет объяснимое подтверждение. Writer идемпотентен по event_id **и содержимому**; новый AI-ответ может дать 409. Температура 0 не гарантирует совпадения — сверить реальные proposals.
- [ ] Один негативный сценарий (bridge недоступен/отказ авторизации) не даёт ложного persisted; событие пригодно для повтора. После восстановления тот же контролируемый сценарий завершается.
- [ ] Настоящий export получен и проверен на импорт в выбранной версии AP, очищен от секретов; blueprint отдельно сохраняет свою роль. Delivery endpoint настроен локально; секретные webhook URL/connection values не коммитятся.

**Данные и наблюдение:** основной контент вручную не менять. Host replay — только после предварительного совпадения hash. Для flow — изолированная память/журналы/тестовая конфигурация bridge, связанная с настоящим AP; удалить лишь созданные проверкой данные и подтвердить неизменность основной памяти. Fixture явно назвать fixture; для production-настроек отдельно проверить маршрутизацию/защиту, не выдавая fixture за production-запись.

**Проверки по изменению:** проба/адаптер — его регрессии и живой smoke; документация не требует полного core. Реальные команды, исходное состояние и вывод записать в отчёт; команды неподтверждённого AP API не выдумывать. Все обязательные live-критерии должны быть доступны; иначе `awaiting-validation`/`blocked`, не done.

**Граница:** перечисленные инварианты и один связанный положительный/отрицательный проход достаточны. После успеха закончить фазу. Второй возврат того же инварианта требует нового механизма или явного ограничения; третий одинаковый круг без основания запрещён.
