# L06-02 — возврат изменения через Git на втором ПК

Машина: **DESKTOP-NCLRFDV** (второй ПК), корень `E:\SystemTheBest\System`.
Стартовая точка — `6d08ca4`, она же `origin/master` на момент начала: локальная копия
пришла клоном, а не переносом файлов.

Роль встречной копии исполняет отдельный клон **вне репозитория**
(`E:\SystemTheBest\transfer-backups\roundtrip-peer-<ts>`), снятый с `origin`. Он нужен,
чтобы обмен шёл через настоящий remote, а не между двумя каталогами на диске.
**Граница доказательства:** этот пир — не ноутбук. Направление
«второй ПК → `origin` → встречная копия» проверено живьём в обе стороны, но участие
настоящего первого ПК и его доступ к `origin` этим не подтверждаются.

## А. Блок правок для проверки конфликта

Ниже — единственная точка, которую правят обе стороны: строка состояния в этом блоке.
Она намеренно тривиальна, потому что проверяется не содержание, а то, **как Git
разрешает одновременную правку без force и без потери чьей-либо версии**.

Строка состояния: `версия: обе правки сохранены (второй ПК и встречная копия, 2026-09-15)`
  - версия второго ПК: `правка второго ПК (DESKTOP-NCLRFDV)`
  - версия встречной копии: `правка встречной копии (пир)`

## Б. Журнал направлений

Записи добавляются той стороной, которая получила изменение; порядок строк — порядок
проверки, а не порядок коммитов.

- 2026-09-15, второй ПК: отправил `d125695` в origin; встречная копия его приняла.
- 2026-09-15, встречная копия: получила `d125695` от второго ПК через origin (`pull --ff-only`), затем правила строку состояния.

## В. Что фактически произошло

Все переходы — обычные `push`/`pull`; ни на одном шаге не применялись `--force`,
`reset --hard` и `clean -f`. Проверка SHA — по `git ls-remote`, а не по выводу push.

| Шаг | Где | Коммит | Результат |
|---|---|---|---|
| старт | обе копии | `6d08ca4` | локальный HEAD и `origin/master` совпадали |
| А: второй ПК → origin | `E:\SystemTheBest\System` | `d125695` | push `6d08ca4..d125695` |
| А: приём | встречная копия | `d125695` | `git log --left-right` показал один `>`; `pull --ff-only` прошёл |
| Б: встречная копия → origin | пир | `bad97cb` | push `d125695..bad97cb` |
| Б: правка второго ПК | `E:\SystemTheBest\System` | `37df900` | обе стороны ушли от `d125695` в одну строку |
| слияние | `E:\SystemTheBest\System` | `a1692e9` | `CONFLICT (content)` в двух местах, разрешён вручную |
| публикация слияния | origin | `a1692e9` | push fast-forward `bad97cb..a1692e9` |
| приём слияния | встречная копия | `a1692e9` | `pull --ff-only` прошёл |

Merge-commit `a1692e9` имеет двух родителей: `37df900` (второй ПК) и `bad97cb`
(встречная копия). В разрешённом файле присутствуют **обе** правки — и версия второго
ПК, и версия встречной копии; ни одна не выбрана за счёт другой.

## Г. Границы

- Проверено: обмен изменениями через настоящий `origin` в обе стороны, конфликт одной
  строки, явное разрешение с сохранением обеих версий, обычный merge-commit, отсутствие
  force и `reset --hard`.
- **Не проверено:** участие настоящего первого ПК (ноутбук `DESKTOP-BUGF4FI`) — его
  доступ к `origin`, его `git status` и его локальная привязка. Встречная копия снята
  с `origin` на этой же машине и ноутбуком не является.
- Встречная копия — временная: она нужна была как вторая сторона обмена и после
  проверки удаляется, чтобы на машине осталась одна каноническая копия памяти.
